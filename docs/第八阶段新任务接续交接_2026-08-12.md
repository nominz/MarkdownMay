## 2. 用户已经明确的第八阶段范围

### 2.1 在光标插入点切分

- 三种编辑模式都必须把当前光标映射到 `DocumentSession` 唯一 UTF-8 源偏移。
- 把当前文档在该位置切分为两个新文件；当前原文件保持不变，不删除、不覆盖。
- 两个目标必须不同，全部写入并校验成功后才报告成功；部分成功不得冒充完整成功。
- 用户明确决定：切分生成了外部文件，因此切分操作不进入正文撤销栈，也不提供“撤销切分”。失败时仍须清理临时文件并保持原文不受损。

### 2.2 在光标插入点插入文件

- 选择另一个文件，把其内容插入当前光标位置；来源文件保持原样，不移动、不改写、不删除。
- 插入改变当前 `DocumentSession` 正文，应作为一次可撤销编辑事务。
- 编码、换行、UTF-8/CRLF 边界、结构粘连、相对链接和本地图片事务继续遵守 V04 COMBINE-005～010；具体交互与失败提示须在 V05 冻结。

### 2.3 `.md` / `.txt` Windows 集成

- 马冬梅同时注册为 `.md` 和 `.txt` 的候选打开程序，并提供应用内界面管理注册、撤销和跳转 Windows 默认应用设置。
- 不篡改 `UserChoice`，不逆向或伪造 Hash，不静默抢占默认程序。Windows 10/11 的最终默认选择由用户在系统界面确认。
- 用户目标是可以主动把马冬梅设为 `.txt` 默认程序，从而替代记事本；产品界面必须清楚说明“注册候选”和“在 Windows 中设为默认”的区别。
- `.txt` 打开后的精确编辑语义、Markdown 渲染边界、编码/换行保存策略尚需在新任务 V05 评审时确认，不得由实现自行猜测。
