# 大纲功能变更影响分析与设计变更方案

> 变更：CR-2026-002
> 需求草案：`需求规格说明书_V03.md` 0.1
> 状态：待用户评审；不得进入实现

## 1. 影响分析结论

大纲是只读的派生导航视图。它读取 `DocumentSession` 最新有效语义树中的 Heading 节点和 `NodeId/SourceRange`，不拥有正文、不修改 Markdown 文件，也不改变 PDF/DOCX/打印内容。主要影响集中在 UI 布局、三模式位置映射、会话事件、设置、DPI/主题/无障碍和性能测试。

| 维度 | 影响与处理 |
| --- | --- |
| 需求 | 新增 OUTLINE-001～025；V02 其他编号保持语义不变 |
| UI | 主文档容器增加左侧侧栏、分隔拖柄、视图命令、工具栏状态和空/错状态 |
| 文档模型 | 不新增节点；复用 Heading、NodeId、SourceRange；不改变模型不变量 |
| Markdown | 不改解析和写回格式；只消费最新成功解析结果 |
| 三模式同步 | 监听会话修订和当前选区；点击后调用既有源位置映射；解析失败清空旧大纲 |
| 文件/图片 | 无文件格式和图片生命周期影响 |
| 导出/打印 | 无内容影响；大纲不进入导出或打印 |
| 平台 | 新增 Win32 子窗口及 UIA；遵循 Per-Monitor V2 DPI、主题和高对比度 |
| 设置 | INI V3 增加 `outline_visible`、`outline_width`，保留未知键并从 V2 迁移 |
| 性能 | 标题索引 O(n) 构建；按修订替换不可变快照；10,000 标题压力测试 |
| 安全/隐私 | 不联网、不记录标题文字到日志、不执行标题中的 HTML |
| 兼容性 | Windows 10/11、100%～300% DPI、键盘/UIA、高对比度新增矩阵 |
| 文档 | V03、功能矩阵、总体/详细设计、接口/数据图、实现验收矩阵、README/用户说明 |

## 2. 冲突审查

- 与“单活动文档”不冲突：大纲仅属于当前 `DocumentSession`。
- 与“三模式唯一状态”不冲突：大纲是可丢弃派生投影，不是正文模型。
- 与“轻量单 EXE”不冲突：使用 Win32 原生控件和现有语义树，不引入依赖。
- 与“默认渲染模式”不冲突：大纲在三模式中保持同一结构，定位适配当前表面。
- 与“解析失败不得显示旧渲染”一致：旧大纲同样必须清除。
- 与“快速启动”存在可控风险：窗口首帧不等待大纲；首次有效语义快照到达后构建。
- 与窄窗口正文可用性存在布局竞争：采用自动临时隐藏，不改变用户持久显示意图。

未发现硬性矛盾。

## 3. 总体设计变更

新增只读组件关系：

```text
DocumentSession（唯一状态）
  ├─ SemanticDocument / NodeIndex
  ├─ ViewModeController（三模式）
  └─ OutlineController
       ├─ OutlineSnapshot（revision + heading items）
       └─ OutlineView（Win32 树形导航视图）
```

依赖规则：

- `OutlineController` 订阅 `DocumentEvent`，只接受与当前 `ParsedRevision` 一致的快照；
- `OutlineView` 不直接读取或修改磁盘、解析器或 RichEdit/Scintilla 文本；
- 点击项目产生 `NavigateToNode(NodeId)` 意图，由 `ViewModeController` 映射到当前表面；
- 解析失败或 `ParsedRevision != SourceRevision` 时发布 Invalid 快照，视图清除旧项；
- 大纲构建可在 UI 线程对普通文档执行；超过阈值时后台只读扫描不可变语义快照，按 revision 丢弃过期结果。

## 4. 详细设计变更

建议新增组件：

| 组件 | 文件 | 职责 |
| --- | --- | --- |
| CMP-UI-06 | `ui/outline_view.*` | 树项绘制、键盘、折叠、UIA、DPI/主题 |
| CMP-EDIT-11 | `editor/outline_controller.*` | 标题快照、修订校验、当前章节、高亮和导航 |
| CMP-SVC-03 扩展 | `services/local_services.*` | INI V3 大纲显示意图和宽度迁移 |
| CMP-UI-02 扩展 | `ui/document_window.*` | 侧栏、拖柄、窄窗口自动隐藏、正文布局 |
| CMP-EDIT-01 扩展 | `editor/view_mode_controller.*` | `NavigateToNode` 三模式位置映射 |

核心数据：

```text
OutlineItem {
  NodeId node_id;
  uint8 level;
  string visible_text;
  SourceRange source_range;
}

OutlineSnapshot {
  DocumentId document_id;
  Revision parsed_revision;
  valid | empty | invalid state;
  vector<OutlineItem> items;
}
```

不变量：

1. `OutlineSnapshot.parsed_revision == DocumentSession.ParsedRevision` 才可显示；
2. `ParsedRevision != SourceRevision` 时不得显示旧 items；
3. 每个 item 的 `NodeId` 在对应语义快照中存在且类型为 Heading；
4. 大纲操作不得创建文档编辑事务或改变 dirty 状态；
5. 自动隐藏只改变瞬时布局，不覆盖用户 `outline_visible` 设置。

## 5. 依赖有序实现路线（评审通过后）

1. 文档与接口基线：冻结 V03，更新总体/详细设计、功能矩阵、接口和数据结构图。
2. 标题快照核心：无 UI 地从语义树生成大纲，覆盖缺级、同名、空文档和修订失效测试。
3. 原生大纲视图：显示、缩进、键盘、折叠、主题、DPI、高对比度和 UIA。
4. 文档窗口布局：侧栏、拖柄、宽度限制、窄窗口自动隐藏。
5. 三模式导航与当前章节高亮：NodeId 到 RichEdit/Scintilla 映射，不改变文档。
6. 实时刷新与错误态：渲染即时、源码防抖、失效清空、恢复自动显示。
7. 设置 V3：显示意图、宽度、迁移和损坏值回退。
8. 性能与总验收：10,000 标题、既有 36 项回归、新增矩阵、Debug/Release、人工 UI 验收。

每个增量完成后形成验收证据和本地 Git 提交；大纲全部验收后才恢复第七阶段。
