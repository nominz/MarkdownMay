## 1. 文档目的

本文定义马冬梅 1.0 的完整产品需求、约束和验收标准，是总体设计、详细设计、编码和最终验收的上位依据。

本文评审通过后升级为 1.0 并冻结。冻结后：

- 开发不得自行增加、删除或重新解释需求；

## 2. 产品定义

### 2.1 一句话定义

马冬梅是一个面向普通 Windows 办公用户的、原生轻量、所见即所得、支持图片和文档导出的 Markdown 记事本。

### 2.2 目标用户

- 财务、行政、人事、运营等非开发岗位；
- 需要直接阅读和修改 `.md` 文件的 Windows 用户；
- 不愿安装 VS Code、语言包、插件或大型运行时的用户；
- 需要免费、开源、离线工具的个人和组织。

### 2.3 核心目标

| 编号 | 目标 |
| --- | --- |
| OBJ-001 | 用户双击 Markdown 文件后几乎感觉不到等待 |
| OBJ-002 | 用户不学习 Markdown 标记也能完成日常排版 |
| OBJ-003 | 默认在可编辑渲染模式阅读和所见即所得编辑，同时提供源码和对照模式 |
| OBJ-004 | 程序以单个 EXE 发布，不要求安装运行时或插件 |
| OBJ-005 | 文档仍是通用 Markdown 文件，不建立私有数据库 |
| OBJ-006 | 支持图片以及 PDF、DOCX 导出 |
| OBJ-007 | 默认中文，操作习惯接近 Windows 记事本和 Office |

### 2.4 永久产品边界

以下能力永久不属于本产品：

- 账号、登录、会员和付费功能；
- 云同步、在线文档、团队协作和远程存储；
- 广告、遥测和用户行为上报；
- 应用内检查更新和自动更新；
- 插件系统和插件市场；
- 笔记库、双向链接、知识图谱和项目管理；
- 内嵌浏览器、网页调试和脚本执行；
- Mermaid、LaTeX 及其他需要外部运行时的动态内容；
- Office 文档导入；
- macOS、Linux、Android、iOS 和 Web 版本；
- 将知识库或开发工具能力塞入源码、对照或渲染模式。

## 3. 运行环境与发布约束

| 编号 | 需求 |
| --- | --- |
| ENV-001 | 支持 64 位 Windows 10 和 Windows 11 |
| ENV-002 | 产品发布物为单个 `MarkdownMay.exe` |
| ENV-003 | EXE 不依赖随程序分发的 DLL、资源目录或配置文件 |
| ENV-004 | EXE 可从任意具有读取和执行权限的目录启动 |
| ENV-005 | 程序正常工作不得要求管理员权限 |
| ENV-006 | 程序不得要求安装 Visual C++、.NET、WebView2、Java 或 Node.js 运行时 |
| ENV-007 | 用户设置、恢复数据和日志保存到当前用户本地应用数据目录 |
| ENV-008 | 程序不得在正常功能中发起网络请求 |
| ENV-009 | 软件许可证为 MIT，源代码和构建说明公开 |

验收：

- 在干净的 Windows 10/11 虚拟机中只复制 EXE，能够启动、编辑、保存和导出；
- 使用网络监测确认正常操作没有外连；
- 普通用户账户能够使用除系统最终默认应用确认外的全部功能。

## 5. 文件生命周期需求

### 5.1 新建、打开和保存

| 编号 | 需求 |
| --- | --- |
| FILE-001 | 支持新建空白 Markdown 文档 |
| FILE-002 | 支持打开 `.md` 和 `.markdown` 文件 |
| FILE-003 | 支持菜单、拖放、命令行和文件关联四种打开方式 |
| FILE-004 | 支持保存和另存为 |
| FILE-004A | 源码存在解析错误时允许按当前源码原样保存；保存前明确提示渲染和导出暂不可用，但不得强迫用户丢弃源码 |
| FILE-005 | 未命名文档首次保存时默认扩展名为 `.md` |
| FILE-006 | 首次创建的文档默认使用无 BOM 的 UTF-8 和 CRLF；无 BOM 便于跨 Windows、macOS、Linux 和常见 Markdown 工具交换，CRLF 符合 Windows 记事本式软件的默认习惯 |
| FILE-007 | 打开已有文件时识别 UTF-8、UTF-8 BOM、UTF-16 LE 和 UTF-16 BE |
| FILE-008 | 保存已有文件时保留原编码和 CRLF/LF 换行方式 |
| FILE-009 | 不支持或无法确定的编码必须提示用户，禁止静默乱码保存 |
| FILE-010 | 保存使用同目录临时文件写入和原子替换 |
| FILE-011 | 保存失败不得破坏原文件，且必须显示可理解的原因 |
| FILE-012 | 退出、关闭或覆盖前检测未保存修改并要求确认 |
| FILE-013 | 检测其他程序对当前文件的修改，并提供重新载入、保留当前内容或另存为 |
| FILE-014 | 只读文件可以打开；编辑保存时提示另存为 |
| FILE-015 | 最近文件列表最多保存 20 项，可单独清空 |

### 5.2 恢复

| 编号 | 需求 |
| --- | --- |
| FILE-016 | 未保存文档发生异常退出时提供本地恢复副本 |
| FILE-017 | 恢复副本不得覆盖原文件 |
| FILE-018 | 正常保存或用户明确放弃后删除相应恢复副本 |
| FILE-019 | 恢复数据和日志不得被打包进 Markdown 文件 |

## 6. 所见即所得编辑需求

### 6.1 基本行为

| 编号 | 需求 |
| --- | --- |
| EDIT-001 | 默认隐藏 Markdown 语法标记，显示实际排版结果 |
| EDIT-002 | 用户可在排版后的内容中直接定位、选择、输入和删除 |
| EDIT-003 | 普通输入支持中文 IME 组合文字和候选窗口正确定位 |
| EDIT-004 | 支持撤销和重做，模型内容与屏幕内容必须同步 |
| EDIT-005 | 支持剪切、复制、粘贴和全选 |
| EDIT-006 | 支持纯文本粘贴；HTML/富文本粘贴转换为受支持的 Markdown 语义 |
| EDIT-007 | 支持查找、向前/向后查找、全部替换和区分大小写 |
| EDIT-008 | 支持鼠标和键盘跨段落、列表、表格、图片进行选择 |
| EDIT-009 | 提供可编辑的 Markdown 源码模式；该模式不渲染格式，直接显示并编辑完整 Markdown 源文 |
| EDIT-010 | 提供对照模式：左栏为可编辑源码，右栏为只读渲染结果 |
| EDIT-010A | 提供渲染模式：显示排版结果并允许所见即所得编辑；该模式为默认模式 |
| EDIT-010B | 三种模式共享同一份文档会话、保存状态、撤销语义和磁盘文件，不得产生三个相互独立的副本 |
| EDIT-010C | 模式切换不得丢失内容、选区附近位置或未保存状态 |
| EDIT-010D | 源码模式或对照模式左栏修改后，渲染结果应在短暂防抖后更新；解析失败时保留源码并显示错误，不得用旧渲染结果冒充当前内容 |
| EDIT-010E | 渲染模式修改后，切换到源码或对照模式时必须显示由当前语义文档生成的最新 Markdown |

### 6.3 结构化编辑规则

| 编号 | 需求 |
| --- | --- |
| EDIT-011 | 空列表项按 Enter 退出当前列表层级 |
| EDIT-012 | 非空列表项按 Enter 新建同级项目 |
| EDIT-013 | Tab/Shift+Tab 在允许时调整列表层级；表格中用于移动单元格 |
| EDIT-014 | 表格最后一个单元格按 Tab 新建一行 |
| EDIT-015 | 代码块内 Enter 保持代码块，明确命令退出代码块 |
| EDIT-016 | 删除两个相邻块的边界时按内容类型执行可预测的合并 |
| EDIT-017 | 对跨多种格式的选区应用格式时不得删除未选内容 |
| EDIT-018 | 每个用户操作形成一个可理解的撤销单位 |
| EDIT-019 | 渲染模式保存前必须验证文档结构；验证失败时保留原文件并提示。源码模式按 FILE-004A 处理 |

### 6.4 Markdown 往返

| 编号 | 需求 |
| --- | --- |
| ROUND-001 | 未编辑的受支持文档打开再保存后语义保持一致 |
| ROUND-002 | 编辑后的文档可以规范化等价 Markdown 写法 |
| ROUND-003 | 规范化不得改变可见文字、链接目标、图片目标、列表层级或表格数据 |
| ROUND-004 | 未识别原始块在未被用户删除时必须逐字节保留其正文 |
| ROUND-005 | 保存结果必须能被 GitHub Markdown 正常解释其受支持语义 |
| ROUND-006 | 保存后立即重新解析；语法有效文档必须通过结构校验，源码模式保存的无效文档必须保持原样并记录明确解析错误 |

## 7. 图片需求

### 7.1 支持格式与显示

| 编号 | 需求 |
| --- | --- |
| IMG-001 | 支持 PNG、JPEG、GIF 静态首帧、BMP 和系统 WIC 可解码格式 |
| IMG-002 | 支持 Markdown 相对路径、绝对路径和 `file:` 本地图片 |
| IMG-003 | 不下载、不缓存、不显示远程 HTTP/HTTPS 图片；仅显示本地图片 |
| IMG-003A | 源文中已有的远程图片语法应保留原文或地址，并显示“远程图片未加载”占位符；程序不得提供一键下载功能 |
| IMG-004 | 图片缺失或解码失败时显示占位符、替代文字和原路径 |
| IMG-005 | 图片显示宽度不得自动超过正文可用宽度 |
| IMG-006 | 用户可保持纵横比调整显示尺寸 |
| IMG-007 | Markdown 保存图片地址和可选尺寸信息，不把图片二进制写进 Markdown |

### 7.2 插入规则

| 编号 | 需求 |
| --- | --- |
| IMG-008 | 支持文件选择、拖放和剪贴板粘贴插入图片 |
| IMG-009 | 引用已有图片时，用户可选择“仅引用原文件”或“复制到文档资源目录” |
| IMG-010 | 默认资源目录为 Markdown 文件同目录下的 `<文档名>.assets` |
| IMG-011 | 从剪贴板粘贴的位图默认保存为 PNG 到资源目录 |
| IMG-012 | 未命名文档插入需要落盘的图片前，先要求保存 Markdown 文件 |
| IMG-013 | 复制图片使用不冲突的可读文件名，禁止覆盖已有不同文件 |
| IMG-014 | 删除文档中的图片引用不得删除磁盘图片 |
| IMG-014A | 删除的图片如果位于当前文档的 `<文档名>.assets` 受管资源目录，且当前文档已无其他引用，则将文件名增加 `del_` 前缀 |
| IMG-014B | 已有 `del_` 前缀或发生重名时使用 `del_2_`、`del_3_` 等不冲突名称，不得覆盖任何现有文件 |
| IMG-014C | 删除外部目录图片、绝对路径图片或不由马冬梅管理的图片时，不重命名磁盘文件 |
| IMG-014D | 撤销图片删除时，应把受管图片恢复为原文件名和原引用；若原文件名已被占用，必须提示并选择安全的新名称 |
| IMG-014E | 如果同一受管图片在当前文档仍有其他引用，删除一个引用时不重命名文件 |
| IMG-015 | 另存为时保留仍然有效的图片引用；必要时提示是否复制资源目录 |
| IMG-016 | `del_` 文件属于可识别的未使用资源；程序不得自动永久删除，用户可在资源目录中自行处理 |

## 12. 安全与隐私需求

| 编号 | 需求 |
| --- | --- |
| SEC-001 | Markdown、HTML 和链接均按不可信输入处理 |
| SEC-002 | 不执行脚本、宏、命令和原始 HTML 活动内容 |
| SEC-003 | 原始 HTML 默认作为原始内容块保留或安全显示 |
| SEC-004 | 远程图片永不下载、缓存或显示，只保留地址并显示安全占位符 |
| SEC-005 | HTTP/HTTPS 链接交给系统默认浏览器，不在应用内打开 |
| SEC-006 | `file:` 链接打开前要求用户确认 |

### 17.1 需求变更流程

用户有权随时提出新增、修改或删除功能。为防止 AI 上下文有限导致局部修改和全局矛盾，每次变更按以下顺序执行：

1. 为变更建立唯一编号 `CR-YYYY-NNN`，记录原始要求和原因；
2. 检索需求规格、技术方案、功能矩阵、源代码、资源、测试和用户文档；
3. 输出影响清单，至少覆盖 UI、文档模型、文件格式、保存、导出、系统集成、性能、安全和兼容性；
4. 检查新要求与已有要求是否矛盾，并提出唯一处理结论；
5. 先修订需求规格并提升版本，再修订设计和功能矩阵；
6. 设计评审通过后才修改代码和测试；
7. 执行受影响模块测试以及完整回归测试；
8. 更新变更记录，确认所有影响点均已关闭；
9. 形成新的需求基线，不在旧版文件上覆盖历史。

每个需求版本使用独立文件保存，例如 `需求规格说明书_V01.md`、`需求规格说明书_V02.md`。旧版本只读保留，禁止回写。

## 18. 本次评审重点

第二轮评审已确认：

1. 新文档默认 UTF-8 无 BOM、CRLF。
2. 粘贴图片前先保存文档，图片默认进入 `<文档名>.assets`。

## 19. V02 全文一致性审查结论

本轮已逐项检查第 2～18 章，处理了以下冲突：

- 删除了“永远不提供源码和对照编辑”的原要求，改为三个模式；
- 保留“渲染模式所见即所得”作为默认体验，不再把“单一表面”误解为“只有一种模式”；
- 将远程图片从“默认不加载”强化为“产品不负责下载”，同时保留原始 Markdown 地址避免数据丢失；
- 将“删除图片不删除文件”与 `del_` 标记规则合并，并限制在受管资源目录，避免破坏外部共享图片；
- 将“需求冻结”修订为“基线受控”，不限制用户增加功能；
- 三种模式必须共享同一文档状态，避免源码、渲染内容和磁盘文件分叉。
- 源码语法错误时仍允许原样保存，但禁止进入渲染模式和导出，避免旧语义模型冒充当前内容。

当前未发现无法同时满足的硬性矛盾。新增的主要技术风险是三种模式之间的同步、撤销和解析失败处理，已在 EDIT-010B～EDIT-010E 中规定结果要求，详细算法留到设计阶段定义。
