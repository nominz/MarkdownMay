## 与此前各轮的区别

此前各轮从画面推断 column tracker、caret、cursor、capture 或 `EN_CHANGE`，然后直接修改行为。本轮不新增另一种拦截猜测，而是记录真实程序的消息与状态序列，以决定下一轮应修改正文同步、原生结构还是布局层。

## 本轮新增证据能力

Release 运行时写入：

```text
%TEMP%\MarkdownMay_table_trace.log
```

日志包含：

- ViewMode host 的 `WM_SIZE`；
- RichEdit 的 `WM_SIZE`、`WM_LBUTTONDOWN`、`WM_LBUTTONUP`、`WM_CAPTURECHANGED`；
- 鼠标消息发生时 RichEdit 是否持有 capture；
- `EN_CHANGE` 在父窗口到达的时刻；
- posted sync 实际分发的时刻；
- `note_change_notification()` 看到的临时只读、capture、resize cursor 状态；
- `synchronize_change()` 进入的分支；
- 同步前的 `DocumentSession.source_revision`、table projection 数量；
- `project()` 开始/结束、原生表格插入失败；
- resize 时 `SetNativeTableParameters(..., insert=false)` 的调用和结果；
- RichEdit 控件尺寸及最终文本长度。

## 复现要求

1. 退出所有马冬梅进程；
2. 启动上述诊断版；
3. 文件 → 最近文件 → 打开 `需求规格说明书_V04.md`；
4. 保持非最大化，拖动一次表格线；
5. 最大化；
6. 再拖动一次表格线，直到表格消失；
7. 不要再次启动马冬梅，以免新进程清空日志；
8. 通知 Codex 读取 `%TEMP%\MarkdownMay_table_trace.log`。
