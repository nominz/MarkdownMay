# 002 最大化宽度与原生表格重建

日期：2026-08-28  
类型：基于真实 trace 的功能修复  
状态：自动验证通过，等待用户真实复测

## 新证据

第 001 轮真实日志证明：

1. 最大化后 RichEdit 宽度达到 2044/2539px；
2. `refresh_layout_after_resize()` 对 9 张表执行的 `EM_SETTABLEPARMS` 返回失败；
3. 拖动后的延迟恢复进入 `project()`，但 `EM_INSERTTABLE` 同样失败；
4. `DocumentSession` 修订没有变化，projection 仍有 9 张表。

因此所有表格消失的直接原因是原生表格参数/结构重建失败，不是 Markdown table 节点被删除。

## 与此前各轮的区别

此前修复集中在列线命中、caret、capture、cursor 和 `EN_CHANGE` 分类。本轮首次依据真实运行返回值修改 `WM_SIZE → EM_SETTABLEPARMS/EM_INSERTTABLE` 链路，不再增加鼠标通知识别条件。

## 修改

### 1. 退出 WM_SIZE 后重建

删除 `refresh_layout_after_resize()` 在 RichEdit `WM_SIZE` 布局栈内对所有 rows 原位调用 `EM_SETTABLEPARMS` 的正式路径。

改为：

```text
WM_SIZE
→ 更新 formatting rect
→ 合并投递 deferred reproject
→ WM_SIZE 返回
→ 空 RTF 清除旧 table tree
→ 从 DocumentSession 重建 native tables
```

### 2. 限制原生表格最大逻辑宽度

新增 `kMaxNativeTableWidthTwips = 14400`。

原生表格宽度规则变为：

- 窄窗口：随 formatting rect 收缩；
- 宽窗口：最大为 14,400 twips，约等于 96 DPI 下 960px；
- 不再把 2K/4K 最大化宽度直接转换为累积 `cellx`。

Markdown 没有 viewport-filling 列宽语义，因此该上限只是稳定的视图布局约束，不修改 Markdown `---` 数量，也不引入第二套正文。

### 3. 合并延迟重投影

增加 `deferred_reproject_pending_`，连续的 RichEdit `WM_SIZE` 只排队一次完整重建，避免重复进入原生 table 创建。
