> 文档编号：MM-TRACE-001
> 版本：0.1
> 状态：随需求和设计持续维护

## 1. 目的

本文件解决“一个功能分散在需求、设计、代码和测试多个位置，AI 修改时容易漏改或改乱”的问题。

它不是需求规格的替代品，而是变更导航图。任何功能新增、修改或删除之前，必须先从本表找到影响范围；修改完成后必须更新本表。

## 5. 三模式的单一数据归属

三个模式不是三份文档：

```text
磁盘 Markdown
      │ 打开/保存
      ▼
Markdown 源文本  ⇄  语义文档模型
      │                  │
      │                  └── 渲染模式：RichEdit，可编辑
      ├── 源码模式：源码控件，可编辑
      └── 对照模式左栏：同一源码控件可编辑
                         右栏：语义模型的只读渲染
```

变更三模式时必须同时检查：

- 当前权威数据到底是源码文本还是已验证语义模型；
- 源码存在语法错误时是否允许保存，以及渲染区显示什么；
- 模式切换前是否提交组合输入和编辑事务；
- 撤销历史跨模式如何表示；
- 光标、选区和滚动位置如何近似映射；
- 外部文件变化时三个视图是否一起失效；
- 保存、恢复、导出读取的是不是同一版本。

这些问题必须在总体设计和详细设计中形成状态机，不能分散在窗口事件中临时判断。
