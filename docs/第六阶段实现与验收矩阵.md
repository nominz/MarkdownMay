> 文档编号：MM-DEV-006
> 状态：执行中

## 阶段边界

本阶段把第五阶段已经封闭的编辑器组件装配为完整 Windows 桌面应用，完成日常文件操作和系统集成。PDF、DOCX 导出属于第七阶段；完整系统测试和发布验收分别属于第八、九阶段。

## 阶段出口

从任意目录运行单 EXE，能够合法注册为 Markdown 候选程序，并完成新建、打开、编辑、保存、另存为、关闭和重新打开等日常文件操作。第六阶段结束前不发布中间版本。

增量 1 已建立正式 `MarkdownMay.exe` 目标和独立于风险样机的应用外壳。入口按顺序设置系统 DLL 搜索、Per-Monitor V2 DPI 和 STA COM，顶层捕获未处理 C++ 异常；`Application` 负责主消息循环，`MainWindow` 的窗口过程包含异常边界、DPI 建议矩形和焦点转交，`DocumentWindow` 只装配第五阶段既有的 `ViewModeController`，默认进入可编辑渲染模式，不建立第二份文档状态。应用使用普通用户 `asInvoker` 清单。真实进程启动验证确认正式中文窗口可见并响应，Release 初始实测可执行文件 1.25 MB、工作集 32.32 MB；装配集成测试覆盖窗口标题、默认模式、编辑器句柄和客户区缩放。公共控件将在创建菜单工具栏的对应增量按实际类别初始化。

增量 2 已冻结 `100/200/300/400/500` 五段稳定命令编号，建立 `CommandDispatcher::query/execute` 单一入口及独立命令编号表。中文菜单提供文件、编辑、格式、视图和帮助五组助记键；加速键表接入应用消息循环，菜单和快捷键都只投递同一 `CommandId`。撤销、重做、剪切、复制、粘贴、全选、八项格式命令、三模式切换、退出和关于已接通；源码及对照模式的剪贴板操作由 Scintilla 表面执行。命令状态随撤销栈和当前模式查询，当前视图显示选中标记，格式命令离开渲染模式后禁用。文件及查找命令虽已登记但在所属后续增量完成前保持禁用。装配测试固定关键编号并覆盖禁用菜单、模式选中、格式可用性、`WM_COMMAND` 路由和退出回调。

增量 3 已建立轻量原生格式工具栏和状态栏。工具栏提供粗体、斜体、删除线、行内代码、引用、无序/有序/任务列表及渲染、源码、对照三模式按钮；所有按钮复用增量 2 的 `CommandId`、`WM_COMMAND` 路由和可用性查询，模式按钮互斥选中，源码及对照模式自动禁用结构化格式按钮，并提供中文悬停提示。状态栏观察同一个 `DocumentSession`，显示“已保存/未保存”、编码、换行方式、非空白字符数和当前模式；文件格式接口可在后续打开文件时更新 UTF-8 BOM、UTF-16 LE/BE、LF、CRLF 或混合换行。主窗口布局固定为菜单、工具栏、文档区、状态栏，缩放时文档区不会覆盖上下控件。装配测试覆盖控件创建、布局边界、模式按钮同步、格式禁用、中文提示、脏状态和文件格式显示。

增量 4 已完成单活动文档的新建、打开、保存、另存为和文件拖放。`DocumentSession::reload` 以 `file_reload` 事件替换当前源码、语义树和保存修订号；三模式控制器收到该事件后清空跨文件撤销/重做历史，并按解析状态默认进入渲染或源码模式。`DocumentWindow` 持有规范文件路径、原编码和原换行方式，保存继续使用第五阶段封闭的临时文件校验与原子替换；未命名文档保存自动进入另存为并默认 `.md`。打开及保存对话框只使用中文本地界面且不改变进程当前目录。混合换行保存前要求用户选择统一为 CRLF 或 LF，并把占比更高者设为默认按钮。主窗口接收资源管理器文件拖放，应用层在安全检查后打开首个文件。标题、状态栏和格式元数据随新建、打开、编辑和保存刷新。测试覆盖会话重载、非法 UTF-8 回滚、UTF-16 LE/LF 打开编辑保存重开、另存为、新建、拖放路径传递及脏文档命令状态。脏文档替换保护已由增量 5 的统一确认流程接管。

增量 5 已完成日常文件状态安全链路。最近文件保存于当前用户的本地应用数据目录，最多保留 20 项，按最近使用顺序展示在“文件—最近文件”菜单中，支持再次打开和清空；打开、保存及另存为成功后统一刷新列表。新建、打开、拖放、最近文件和退出都经过同一未保存确认流程，“是”仅在实际保存成功后继续，“否”明确放弃，“取消”保留现场。只读文件允许打开和编辑，标题显示“[只读]”，保存自动引导另存为，不覆盖原文件。`DocumentWindow` 保存磁盘内容快照，在窗口重新激活和覆盖保存前检测外部修改；用户可重新加载最新内容或保留当前版本，脏文档重新加载前明确提示内容丢失风险。错误码新增 `4014 file_read_only`。集成测试覆盖外部修改发现与确认、只读拒绝原位保存、关闭回调取消/放行；服务测试覆盖最近文件排序、上限及清空。Debug 全部 32 项测试通过，Release 主程序和本增量封闭测试通过。

增量 6 已完成命令行、单实例 IPC 和待打开队列。命令行使用 `CommandLineToArgvW` 的系统拆分结果，支持一个或多个文件路径及 `--register`、`--unregister`、`--safe-mode` 选项识别，路径统一规范为绝对路径；注册和安全模式的实际动作分别由后续对应增量接管。单实例名称按当前用户 SID 的稳定哈希派生，使用用户会话内互斥体和命名管道；协议采用版本化固定头与 UTF-16 路径数组，限制 128 条路径和 1 MB 载荷，拒绝魔数、版本、长度或边界不合法的消息。次实例在管道尚未建立或正忙时于 3 秒预算内重试，投递成功后退出；无路径的次实例请求激活并恢复已有窗口；IPC 失败则明确提示并独立打开，绝不丢弃原始请求。接收线程只验证并转交路径，文档打开通过 `WM_APP` 回到 UI 线程。多个路径按序进入队列，窗口标题显示待打开数量，当前文档保存后继续下一项；带队列退出时明确确认且默认不退出。协议集成测试覆盖中文、空格、Emoji、相对路径、冲突参数、损坏消息和真实命名管道传输；真实双进程试跑确认次实例退出、仅保留一个进程且首窗口打开目标文件。Debug 全部 33 项测试通过，Release 主程序和本增量协议测试通过。
