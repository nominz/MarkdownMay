# 马冬梅第六阶段实现与验收矩阵

> 文档编号：MM-DEV-006
> 状态：执行中
> 路线：瀑布开发、依赖有序增量、阶段内不发布

## 阶段边界

本阶段把第五阶段已经封闭的编辑器组件装配为完整 Windows 桌面应用，完成日常文件操作和系统集成。PDF、DOCX 导出属于第七阶段；完整系统测试和发布验收分别属于第八、九阶段。

## 阶段出口

从任意目录运行单 EXE，能够合法注册为 Markdown 候选程序，并完成新建、打开、编辑、保存、另存为、关闭和重新打开等日常文件操作。第六阶段结束前不发布中间版本。

增量 1 已建立正式 `MarkdownMay.exe` 目标和独立于风险样机的应用外壳。入口按顺序设置系统 DLL 搜索、Per-Monitor V2 DPI 和 STA COM，顶层捕获未处理 C++ 异常；`Application` 负责主消息循环，`MainWindow` 的窗口过程包含异常边界、DPI 建议矩形和焦点转交，`DocumentWindow` 只装配第五阶段既有的 `ViewModeController`，默认进入可编辑渲染模式，不建立第二份文档状态。应用使用普通用户 `asInvoker` 清单。真实进程启动验证确认正式中文窗口可见并响应，Release 初始实测可执行文件 1.25 MB、工作集 32.32 MB；装配集成测试覆盖窗口标题、默认模式、编辑器句柄和客户区缩放。公共控件将在创建菜单工具栏的对应增量按实际类别初始化。

增量 2 已冻结 `100/200/300/400/500` 五段稳定命令编号，建立 `CommandDispatcher::query/execute` 单一入口及独立命令编号表。中文菜单提供文件、编辑、格式、视图和帮助五组助记键；加速键表接入应用消息循环，菜单和快捷键都只投递同一 `CommandId`。撤销、重做、剪切、复制、粘贴、全选、八项格式命令、三模式切换、退出和关于已接通；源码及对照模式的剪贴板操作由 Scintilla 表面执行。命令状态随撤销栈和当前模式查询，当前视图显示选中标记，格式命令离开渲染模式后禁用。文件及查找命令虽已登记但在所属后续增量完成前保持禁用。装配测试固定关键编号并覆盖禁用菜单、模式选中、格式可用性、`WM_COMMAND` 路由和退出回调。

增量 3 已建立轻量原生格式工具栏和状态栏。工具栏提供粗体、斜体、删除线、行内代码、引用、无序/有序/任务列表及渲染、源码、对照三模式按钮；所有按钮复用增量 2 的 `CommandId`、`WM_COMMAND` 路由和可用性查询，模式按钮互斥选中，源码及对照模式自动禁用结构化格式按钮，并提供中文悬停提示。状态栏观察同一个 `DocumentSession`，显示“已保存/未保存”、编码、换行方式、非空白字符数和当前模式；文件格式接口可在后续打开文件时更新 UTF-8 BOM、UTF-16 LE/BE、LF、CRLF 或混合换行。主窗口布局固定为菜单、工具栏、文档区、状态栏，缩放时文档区不会覆盖上下控件。装配测试覆盖控件创建、布局边界、模式按钮同步、格式禁用、中文提示、脏状态和文件格式显示。

增量 4 已完成单活动文档的新建、打开、保存、另存为和文件拖放。`DocumentSession::reload` 以 `file_reload` 事件替换当前源码、语义树和保存修订号；三模式控制器收到该事件后清空跨文件撤销/重做历史，并按解析状态默认进入渲染或源码模式。`DocumentWindow` 持有规范文件路径、原编码和原换行方式，保存继续使用第五阶段封闭的临时文件校验与原子替换；未命名文档保存自动进入另存为并默认 `.md`。打开及保存对话框只使用中文本地界面且不改变进程当前目录。混合换行保存前要求用户选择统一为 CRLF 或 LF，并把占比更高者设为默认按钮。主窗口接收资源管理器文件拖放，应用层在安全检查后打开首个文件。标题、状态栏和格式元数据随新建、打开、编辑和保存刷新。由于增量 5 的未保存确认尚未实现，新建、打开和拖放在脏文档时明确禁用或阻止，绝不静默丢弃内容。测试覆盖会话重载、非法 UTF-8 回滚、UTF-16 LE/LF 打开编辑保存重开、另存为、新建、拖放路径传递及脏文档命令状态。
