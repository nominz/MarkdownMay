# CR-2026-036 原生表格 Cell 化实现与验收记录

## 1. 变更目标

将 Markdown 表格从“一行 paragraph + tabs + GDI 网格”迁移为 Windows 11 系统 RichEdit 原生 table/row/cell。每个 cell 必须拥有独立 wrapping rectangle；Markdown 与 `DocumentSession` 保持唯一正文。

## 2. 实现边界

- 系统 API：`msftedit.dll`、`EM_INSERTTABLE`、`EM_SETTABLEPARMS`、TOM2 `ITextRange2/tomCell`。
- 投影：`TableProjection/TableRowProjection/TableCellProjection`。
- 编辑：单 Cell 内输入、删除、普通粘贴、选择替换；跨 Cell 结构化选择留后续。
- 绘制：原生 cell 负责 border/background/margin/wrap；GDI 基础网格退出。
- 平台：仅 Windows 11，不实现旧系统与 tabs fallback。

## 3. 验收证据

- Debug 全量构建：通过。
- Release 全量构建：通过。
- `wysiwyg_table_integration`（Debug/Release）：通过。覆盖三列分别为长中文、三列同时为长文本、独立 Cell 内换行、行高随最高 Cell 扩展、resize、DPI、多行、多表、表格前后正文、粗体与行内代码。
- `table_editor_unit`、`wysiwyg_complete_integration`、`save_reopen_integration`、`large_document_projection_integration`（Debug/Release）：通过。
- 全量 CTest（Debug/Release）：44/47 通过。三个失败均为不经过表格投影的既有环境/交互断言：`heading_fold_integration` 的折叠后滚动像素精确相等、`block_interaction_integration` 的模拟鼠标悬停窗口可见性、`file_association_integration` 的系统文件关联环境；原生表格相关测试全部通过。

## 4. 已知边界

- 本增量只支持单 Cell 内编辑；跨 Cell 结构化选择与编辑仍按需求留到后续增量。
- Tab/Shift+Tab 使用 Win11 RichEdit 原生表格导航行为，本轮没有另建第二套键盘导航状态。
- 中文、ASCII、中英文混排、选择替换和普通粘贴由自动化用例覆盖；真实输入法候选窗交互需随应用人工验收，底层仍走同一 `EN_CHANGE -> cell-local diff -> DocumentSession` 路径。
- RichEdit `EM_INSERTTABLE` 的 `cRow` 为 `BYTE`，单次原生表格投影当前上限为 255 行；超大表格分段原生插入留作后续增强，不回退到 tabs 假表格。
