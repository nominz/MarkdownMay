### 3.2 当前可用产品能力

- 原生 C++20/Win32 单 EXE，无 Electron、WebEngine、云服务或运行时下载。
- `DocumentSession` 是渲染、源码、对照三种编辑模式唯一的正文状态。
- 支持 UTF-8/UTF-16、换行保留、原子保存、只读和外部修改检测。
- 支持标题、段落、行内格式、链接、引用、代码块、分隔线、列表、任务项、表格、图片和安全原始 HTML 显示。
- 支持受管本地图片目录及安全删除标记；远程图片不下载、不缓存、不显示。
- 支持中文菜单、快捷键、工具栏、状态栏、主题、高对比度、DPI、多显示器、打印和页面设置。
- 支持新建、打开、保存、另存为、拖放、最近文件、命令行和当前既有启动模型。
- 已实现当前用户范围的 `.md/.markdown` 候选程序注册、撤销、EXE 移动后的路径修复提示，以及打开 Windows 默认应用设置；程序不写受保护的 `UserChoice`，最终默认应用必须由用户在 Windows 中确认。当前尚缺最新环境下的完整收口证据，不能简称为“已经设置默认应用”。
- 支持大纲及三模式标题导航；支持查找替换及规定的通配符、`^p`、`^t` 语义。

## 5. 第七阶段冻结范围

### 5.1 PDF

以 V02 PDF-001～012 为准：导出完整当前文档；A4 纵向及横向；页边距；覆盖全部正式 Markdown 语法；中文可复制和搜索；图片等比缩小；表格跨页并重复表头；长代码行换行；链接可点击；失败不留下损坏目标；不包含任何编辑器界面；解析修订无效时禁止导出旧语义内容。

### 5.2 DOCX

以 V02 DOCX-001～011 为准：导出完整当前文档；Microsoft Word 和常用 WPS 可打开；标题映射标题 1～6；正文和行内语义保留；列表保持层级；表格可编辑；图片嵌入包内；链接可点击；代码块使用独立样式和等宽字体；失败不留下损坏目标；解析修订无效时禁止导出旧语义内容。

### 5.3 共同非功能要求

- SEC-010：不得写入未要求的用户名、计算机名、本地路径等元数据。
- PERF-010、REL-003：导出期间界面保持响应，显示可取消进度，UI 线程不得无限等待。
- REL-004：成功、失败和取消必须有明确结果。
- 导出使用语义文档而不是屏幕截图，不追求与 RichEdit 屏幕逐像素一致。
- 大纲、查找栏、工具栏、状态栏、光标和选区均不进入输出。
- 不引入 Office 自动化、Word/WPS 安装依赖、云转换服务或运行时下载。

### 5.4 HTML

全文 HTML 导出是第七阶段正式范围，不是候选项：

- 导出完整当前文档，包括标题、正文、列表、任务项、引用、代码、链接、表格、图片、Mermaid 源码和公式源码；
- 普通 Markdown 语义转换为安全 HTML；应用内仅显示占位的 Mermaid/公式在浏览器中由内嵌固定版本脚本尝试渲染；
- 产物优先为单个离线 `.html`，CSS、脚本和允许内嵌的图片资源包含在文件内，不依赖伴随目录或 CDN；
- 使用严格 CSP，禁止外部网络、任意原始 HTML 脚本、事件处理器、表单提交和渲染回调；
- 不附带或嵌入字体，只使用浏览器可访问的 Windows 已安装字体；公式路线必须通过 MathML/系统字体样机；
- 马冬梅只生成文件，不嵌入浏览器、不在进程内执行 JavaScript；用户使用系统浏览器打开导出结果；
- HTML 导出失败、取消或资源超限时不得留下伪成功文件。

HTML 当前只要求“全文”，不增加“仅大纲 HTML”；如果将来需要，作为低风险受控增量评审。

### 5.5 本阶段明确不做

- 导入 PDF、DOCX 或其他 Office 格式；
- RTF、EPUB 等未批准的新增导出格式；HTML 和 TXT 已由用户明确加入正式范围；
- 页眉页脚、目录域、批注、修订、宏、浮动图片和复杂排版模板；
- 追求 Word 与屏幕显示逐像素一致；
- 借导出阶段实现多窗口、多标签、SVG 工具栏图标或其他未冻结需求。

## 6. 设计基线与强制约束

1. `DocumentSession` 继续是唯一正文状态；导出不得创建第二套可编辑正文模型。
2. 创建请求时必须满足 `ParsedRevision == SourceRevision`、语义文档修订一致且快速校验通过，否则返回 `EXPORT-6001`。
3. `ExportDocument` 是不可变、与 UI 无关的中间模型，保留 `NodeId` 供诊断，但不持有窗口、RichEdit、Scintilla 或其他 UI 对象。
4. 后台任务只接收固定修订快照；用户后续编辑不得改变正在生成的文件。
5. PDF 使用自有轻量 writer 和系统 DirectWrite 字体能力，不把中文正文栅格化为整页图片。
6. DOCX 使用 Open XML 和静态链接 ZIP 实现；不得通过 COM 启动 Word/WPS 生成文件。
7. 所有目标文件先写同目录唯一临时文件，完整校验成功后再原子替换；失败或取消删除临时文件。
8. 新增依赖必须经过许可证、体积、静态链接、安全和离线边界审查，并同步第三方说明。
9. “静态链接”本身不代表路线通过：最终必须仍为单个 EXE，且不得通过首次运行解压 DLL、脚本、WASM、字体或辅助程序规避约束。

## 8. 测试与验收基线

### 8.1 固定样例

至少建立以下可版本化样例：

- 中文和英文混排、H1～H6、全部行内格式；
- 有序、无序、嵌套和任务列表；
- 引用、分隔线、代码块和超长代码行；
- 宽表格、长表格、跨页表格和重复表头；
- PNG/JPEG 等受支持本地图片、超宽图片、损坏或缺失图片；
- 内部文本与外部 URL 链接；
- 长文档、多页文档、10 MB 压力文档；
- 源码解析失败、目标无权限、磁盘空间不足模拟和用户取消。

### 8.2 自动检查

- PDF：文件头、对象引用、xref、页树、字体、图片、链接注释、文本提取和页数。
- DOCX：ZIP 完整性、必需部件、XML 可解析、关系目标、样式、编号、媒体、超链接和元数据。
- HTML：语义结构、字符转义、CSP、脚本资源完整性、单文件离线、零网络请求、内嵌图片、Mermaid/公式容器和浏览器打开。
- 一致性：三种视图模式从同一 `DocumentSession` 修订导出时内容一致；编辑器视觉状态不进入文件。
- 可靠性：导出失败或取消不覆盖既有目标，不残留伪装成功的文件。
- 回归：现有 36 项测试以及新增导出测试全部纳入 CTest。

### 8.3 人工兼容性

- PDF 至少使用 Windows 常见 PDF 阅读器检查打开、搜索、复制、链接、分页、中文和图片。
- DOCX 至少使用受支持 Microsoft Word 与当前常用 WPS 检查打开、编辑、样式、列表、表格、链接和图片。
- HTML 至少使用 Windows 当前受支持的主流系统浏览器检查离线打开、全文排版、链接、图片、Mermaid、公式失败回退和打印预览。
- 人工测试必须记录软件版本、Windows 版本、样例、结果、偏差和截图/文件证据；未实际执行不得写“通过”。
