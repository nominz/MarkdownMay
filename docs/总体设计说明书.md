# 马冬梅（Markdown May）总体设计说明书

> 文档编号：MM-HLD-001
> 版本：1.0
> 需求基线：`需求规格说明书_V02.md` 1.0
> 状态：瀑布第二阶段交付物

## 1. 目的与范围

本文把冻结需求转换为系统级设计，规定模块边界、依赖方向、运行时组件、数据所有权、三模式同步、线程、持久化、导出和平台集成。详细的类、函数、状态和算法见《详细设计说明书》；公共 C++ 接口见 `design/include/markdownmay/`。

设计目标按优先级排列：

1. 不丢失用户 Markdown 源文；
2. 三种模式不分叉、不用旧渲染冒充当前内容；
3. Windows 中文输入、文件操作和系统集成可靠；
4. 单 EXE、快速启动、低内存；
5. 结构可测试、可追踪、可由 AI 按文件实施。

## 2. 关键设计决策

| 编号 | 决策 | 原因 |
| --- | --- | --- |
| ADR-001 | C++20、MSVC、Win32 | 原生、小体积、快速启动、系统集成直接 |
| ADR-002 | RichEdit 承担渲染模式编辑 | 利用系统 IME、选区、无障碍、基础富文本 |
| ADR-003 | Scintilla 静态链接，承担源码编辑 | 源码文本、高亮、行列、错误标记成熟 |
| ADR-004 | MD4C 静态链接 | 小型、CommonMark/GFM 能力明确 |
| ADR-005 | Markdown 源文本始终可以保存 | 源码语法错误时优先保护用户输入 |
| ADR-006 | 语义文档只代表最近一次成功解析版本 | 禁止用无效源码构造半真半假的模型 |
| ADR-007 | 所有视图带版本号 | 判断模型、源码、渲染和导出是否一致 |
| ADR-008 | UI 线程拥有可变文档会话 | 避免跨线程同时修改编辑状态 |
| ADR-009 | 后台任务只接收不可变快照 | 解析、图片解码、导出不直接碰 UI 对象 |
| ADR-010 | 设置写 LocalAppData，资源编译进 EXE | 单 EXE 可从只读目录运行 |
| ADR-011 | PDF/DOCX 由语义文档导出 | 不截图，不依赖屏幕布局 |
| ADR-012 | 错误使用稳定错误码和 `Result<T>` | 禁止异常跨模块边界传播 |

禁止的依赖：

### CR-2026-022 原生界面完善

工具栏继续采用 Win32 Toolbar 自绘，不引入 SVG/Web 运行时；用户 SVG 作为受控视觉源，绘制时统一使用主题前景色。段落清除格式经当前渲染选区映射到唯一 `DocumentSession` 源范围，并作为一次正文事务提交。插入菜单只负责命令编排，表格仍复用 `TableEditor`，链接仍复用行内格式链路。状态栏和菜单保持 DPI 感知的 GDI 自绘；关于窗口的位图编入单 EXE 资源，项目链接交由 Shell 打开。

## 5. 运行时组件

### 5.1 单进程单 UI 线程

默认只有一个应用进程和一个 UI 线程。第二次启动通过命名管道把文件路径交给现有实例，然后退出。

进程内组件：

```text
Application
 ├─ MainWindow（当前 1.0 仅一个活动文档会话）
 │   ├─ ViewModeController
 │   │   ├─ RichEditHost
 │   │   ├─ SourceView
 │   │   └─ SplitView
 │   └─ CommandDispatcher
 ├─ DocumentSession
 ├─ BackgroundExecutor
 ├─ SettingsService
 ├─ RecoveryService
 └─ SingleInstanceServer
```

技术方案早期写过“多标签”，冻结需求没有要求多标签。1.0 采用单窗口单活动文档，打开另一个文件前按未保存流程处理。这样符合记事本定位并显著降低三模式状态复杂度。未来若用户提出多标签，必须走 CR 流程。

### 5.2 后台任务

后台线程池固定为最多 2 个工作线程，执行：

- 源码防抖后的 Markdown 解析；
- 图片解码和缩略；
- PDF/DOCX 导出；
- 大文件加载后的非关键计算。

任务携带 `DocumentId`、`SourceRevision` 和取消令牌。结果回到 UI 线程时，版本不匹配就丢弃，不得覆盖新状态。

## 6. 文档数据所有权

`DocumentSession` 是单个打开文档的聚合根，包含：

- 文档身份、路径、编码、换行符；
- 当前 Markdown 源文本 `SourceBuffer`；
- 当前源码修订号 `SourceRevision`；
- 最近成功解析的不可变 `SemanticDocument`；
- 该语义模型对应的 `ParsedRevision`；
- 磁盘已保存修订号 `SavedRevision`；
- 当前模式和三个视图的位置状态；
- 解析错误、外部修改和只读状态；
- 应用级撤销协调器。

核心不变量：

```text
ParsedRevision <= SourceRevision
SavedRevision <= SourceRevision
RenderRevision == ParsedRevision 或 RenderRevision 为空
ExportAllowed 当且仅当 ParsedRevision == SourceRevision 且文档校验通过
```

### 6.1 权威数据切换

| 用户动作 | 临时权威表示 | 提交结果 |
| --- | --- | --- |
| 渲染模式编辑 | 编辑事务中的语义模型 | 序列化为新源码，二者版本相同 |
| 源码模式编辑 | SourceBuffer | 解析成功后更新语义模型 |
| 对照左栏编辑 | SourceBuffer | 解析成功后更新右栏 |
| 打开文件 | 磁盘字节 | 解码为 SourceBuffer，再解析 |
| 保存 | 当前 SourceBuffer | 原子写入后更新 SavedRevision |
| 导出 | 最新 SemanticDocument | 仅在 ParsedRevision 等于 SourceRevision 时允许 |

## 7. 三模式状态机

```mermaid
stateDiagram-v2
    [*] --> Render: 打开且解析成功
    [*] --> SourceError: 打开但解析失败
    Render --> Source: 切换源码
    Render --> Split: 切换对照
    Source --> Render: 解析成功
    Source --> Split: 解析成功或保留错误占位
    Split --> Render: 解析成功
    Split --> Source: 任意状态
    Source --> SourceError: 编辑后解析失败
    Split --> SplitError: 编辑后解析失败
    SourceError --> Source: 解析恢复
    SplitError --> Split: 解析恢复
    SourceError --> SourceError: 原样保存
    SplitError --> SplitError: 原样保存
```

规则：

- 默认模式是 `Render`；
- 文件初次解析失败则进入源码错误态，而不是显示空白渲染；
- 错误态可保存源码、撤销、重做和继续编辑；
- 错误态不能进入可编辑渲染模式，不能导出；
- 对照错误态右栏显示错误摘要和位置，不显示旧文档；
- 模式切换前提交 IME 组合输入和活动编辑事务；
- 视图位置用稳定节点 ID 加节点内偏移映射，失败时退化到最近源码行。

## 8. Markdown 解析与序列化

### 8.1 解析

MD4C 回调经 `SyntaxBuilder` 构建不可变语义树。每个节点具有：

- `NodeId`：在一次会话中稳定；
- `NodeKind`；
- `SourceRange`：UTF-8 字节范围；
- 块/行内属性；
- 子节点；
- 未识别内容的原始字节。

局部编辑后优先按受影响块重新解析；若边界不安全则整篇解析。第一实现可以先整篇解析，但接口必须保留局部解析能力，性能测试决定何时启用。

### 8.2 序列化

- 渲染模式编辑后由 `MarkdownWriter` 生成规范化 Markdown；
- 源码模式不做无意义重写，直接保存 SourceBuffer；
- 未修改的未知块由 `SourcePreserver` 原样复制；
- 新文件输出 UTF-8 无 BOM、CRLF；
- 已有文件保留可识别编码和换行符。

## 9. 图片生命周期

图片分为：

1. **受管图片**：位于当前文档 `<文档名>.assets`；
2. **外部本地图片**：其他本地路径；
3. **远程图片引用**：HTTP/HTTPS，仅保留地址并显示占位符。

删除引用：

- 受管图片且当前文档无剩余引用：原子重命名为 `del_原名`；
- 重名依次使用 `del_2_`、`del_3_`；
- 外部图片和仍被引用的图片不改名；
- 撤销记录原路径和删除标记路径，安全时恢复；
- 永不自动永久删除图片。

重命名和文档编辑属于一个复合事务。若重命名失败，文档引用删除仍可继续，但必须提示“图片文件未标记”；不得因此损坏文档。

## 10. 文件读写

打开流程：

```text
规范化路径 → 读取字节 → 检测 BOM/编码 → 解码为 UTF-8 内部文本
→ 检测换行 → 建立 SourceBuffer → 解析 → 建立会话 → 投影视图
```

保存流程：

```text
取得 SourceBuffer 快照 → 转换原编码/换行 → 同目录唯一临时文件
→ 写入并 FlushFileBuffers → 保留必要文件属性 → ReplaceFile
→ 更新磁盘身份和 SavedRevision
```

外部修改通过目录变更通知和文件身份二次核验，避免仅比较时间戳。

## 11. PDF 与 DOCX 导出

`ExportDocument` 是与 UI 无关的不可变中间模型，由最新语义文档建立。

PDF：

- 自有轻量 PDF writer；
- DirectWrite 提供字形和度量；
- 中文字体子集嵌入；
- 两遍布局：先测量分页，再写对象和交叉引用；
- 临时文件成功完成后原子替换目标文件。

DOCX：

- 生成 Open XML 部件；
- miniz 静态打包 ZIP；
- 标题、列表、表格、链接、图片映射到 Word 原生结构；
- 先写临时包，完成关系校验后替换。

导出只读取固定修订快照。用户继续编辑不影响正在导出的内容；界面显示“正在导出文档修订 N”。取消时删除临时文件。

## 12. UI 与命令

所有操作映射到稳定 `CommandId`，菜单、工具栏和快捷键不直接修改文档。

```text
UI 事件 → CommandDispatcher → 查询 CanExecute
→ Editor/Document/Application 服务 → Result
→ UI 显示状态或错误
```

命令可用性由 `CommandContext` 决定，包括当前模式、选区、只读、解析状态、导出状态和未保存状态。

## 13. 错误处理

- 公共接口返回 `Result<T>` 或 `Status`；
- 错误包含稳定 `ErrorCode`、严重级别、系统错误、参数和来源；
- UI 使用错误码查找中文模板；
- 内部异常在模块边界转换为错误，禁止穿过 Win32 消息过程；
- 日志只记录错误码、模块、系统码、耗时和路径哈希，不记录正文；
- `Fatal` 只用于无法维持进程不变量的情况。

完整编号见《错误码表》。

## 20. 查找替换增量（DC-2026-003）

`ui/find_replace_bar.*` 是 `DocumentWindow` 顶部的原生 Win32 非模态栏；`edit_find/edit_replace` 由 `CommandDispatcher` 显示对应形态。查找栏只采集查询、替换、大小写和通配符选项，业务语义下沉到 `editor/find_replace_controller.*`。

`ViewModeController` 在操作前提交当前可见表面，把当前源选区交给查找控制器，并把匹配的 UTF-8 源范围映射回渲染、源码或对照左栏。替换经现有 `ParagraphEditor`/`DocumentSession` 事务提交，刷新当前表面并进入应用级历史；不直接改 RichEdit 或 Scintilla 私有缓冲，不建立第二正文模型。

### CR-2026-023 标题折叠

`ViewModeController` 独占一个 `HeadingFoldController`。控制器只从当前 `DocumentSession` 最新有效语义修订派生 H1～H6 的标题范围和章节正文范围，并以稳定 `NodeId` 保存当前窗口内的折叠集合；它不是正文状态，不参与保存、dirty 或撤销。渲染模式 RichEdit、源码模式 Scintilla 以及对照模式左右两侧订阅同一折叠快照。导航到隐藏源位置时先展开覆盖该位置的祖先章节，再执行既有源位置映射。新开、重载或切换为 TXT 时清空折叠状态。

## 18. V03 大纲设计变更（DC-2026-002）

主文档容器在编辑表面左侧装配固定 `OutlineView`。它只读取当前 `DocumentSession` 有效语义文档中的 H1～H6，按源顺序生成同字体、同字号、仅层级缩进不同的列表，不建立第二套正文状态。菜单和状态栏通过同一 `view_outline` 命令切换显示；点击项目由 `ViewModeController` 将标题源位置映射到当前渲染、源码或对照表面。显示偏好写入本地 INI V3，大纲不进入保存、打印和导出内容。

2026-08-10 优化增量：大纲仅在当前有效语义文档含标题且用户显示意图开启时装配可见；左侧大纲与正文、对照模式左右表面均使用原生可拖动分隔条。大纲列表启用水平滚动范围。状态栏“大纲”移至最左侧。对照返回渲染模式时在隐藏旧分栏后重建并同步重绘活动 RichEdit，消除失效区域残留。

## 21. V04 系统设计变更（DC-2026-004）

### 21.1 统一导出架构

ADR-011 扩展为“所有派生格式由固定语义修订导出”。`ExportRequest` 由内容范围、格式、目标路径和经验证配置快照组成；当前范围为 `outline/full × pdf/docx/txt` 及 `full × html`。`ExportDocument` 仍是与 UI 无关的不可变模型，包含块/行内语义、标题层级、NodeId、资源引用和 Mermaid/公式原始源码，不持有 RichEdit、Scintilla、OutlineView 或 HWND。

```text
DocumentSession 固定有效修订
        │
        ▼
ExportDocumentBuilder ── 修订/不变量/资源门禁
        │
        ├── ScopeFilter(outline/full)
        │
        └── ExportTaskPipeline
              ├── TxtWriter
              ├── PdfWriter
              ├── DocxWriter
              └── SafeHtmlWriter
                       └── 单文件内嵌固定数据资源
```

所有 writer 只写同目录临时文件；格式结构校验成功后统一由 `AtomicExportCommit` 替换目标。取消令牌、进度、诊断和资源预算属于公共任务管线，不由各 writer 分别实现。HTML writer 只生成文件，应用进程不执行其脚本；严格 CSP、转义/清理和零网络是生成器不变量。

### 21.2 扩展源码

Markdown 层识别 Mermaid 围栏及行内/块公式的源范围和类型，语义层完整保留原文。当前渲染投影只生成安全只读占位，不建立图形或数学排版引擎。大纲忽略扩展节点；TXT/PDF/DOCX 保留类型和源码，HTML 输出受控容器。未来应用内原生渲染不得通过本设计变相进入。

### 21.3 文档组合

`DocumentCombineService` 只接收固定会话快照、源插入点和路径上下文。插入/追加通过单次 `DocumentSession` 事务提交；相对链接重写、受管图片复制与正文提交使用可回滚资源事务。`DocumentSplitService` 生成两个候选并预解析，使用双目标临时写入和完整提交协议，默认不改变或删除当前文档。

应用外壳通过“编辑”菜单中的同组命令承接两个服务。命令执行前由活动模式同步正文并取得源码选区，再经 `SourcePositionMapper` 验证折叠插入点和修订；服务提交后只刷新活动视图，不建立第二正文模型。切分要求当前文档已命名，插入允许未命名文档但涉及本地资源重写时要求先保存。

### 21.4 多进程多窗口

运行时从“系统范围单实例”调整为“一进程一窗口一会话，可多进程并列”。普通启动不走单实例转发必经路径；多路径由启动协调器按顺序派生独立进程。共享 INI、最近文件和恢复索引增加命名互斥/文件锁、读改写合并和原子替换，正文状态始终不跨窗口共享。当前不引入进程内文档集合或标签页。

### 21.5 MDM 配置

新增 `ProfileService`，负责受限 YAML 解析、schema 校验、分层合并、旁车发现、文件监视和最后有效配置回退。有效配置在应用到 UI、打印或导出前转换为有界的不可变 `ResolvedProfile`；系统高对比度和安全上限最后覆盖。字体解析只接受已安装字体族名称，不打开配置指向的字体文件。

### 21.6 发布约束

新增依赖和静态资源必须经过许可证、安全、体积和单 EXE 审查。用于 HTML 的固定脚本只作为数据编入 EXE，并仅在用户请求导出时写入目标 HTML；不得释放成运行组件。任何需要 WebEngine、外部程序、网络、伴随目录或字体分发的路线均在设计入口处拒绝。

## 22. V05 第八阶段系统设计冻结（DC-2026-006）

> 状态：2026-08-15 随 `需求规格说明书_V05.md` 1.2 完成受控修订。

### 22.1 文档类型与唯一状态

`DocumentSession` 增加 `DocumentKind { markdown, plain_text }` 元数据，但仍只保存一份 UTF-8 源文本、修订、选择、脏状态和撤销历史。Markdown 维持解析树与三模式；纯文本不构造伪 Markdown 语义树，只投影源码式编辑表面。文件打开、另存为和命令状态由文档类型路由。

### 22.2 统一位置映射与组合服务

新增 `SourcePositionMapper`，输入活动表面、表面修订和会话修订，输出合法 UTF-8 源偏移或稳定错误。切分读取固定 `SessionSnapshot`，先验证边界并预解析候选，再由 `DualNewTargetCommit` 写入两个不存在的新目标；它不调用会话事务或撤销服务。插入由 `DocumentCombineService` 生成不可变正文/资源计划，经资源补偿日志准备后，用一次 `DocumentSession` 事务提交。

切分输出文档类型和扩展名继承当前文档。`.md/.txt` 来源先按自身编码解码到内部 UTF-8；保存时统一按当前会话编码和换行输出，因此来源与目标编码不需要相同。8.3B 风险样机后用户撤销 DOCX/PDF 输入，不建立 reader、不引入 miniz/PDFium 等依赖；正式插入范围固定为 `.md/.markdown/.txt`。

### 22.3 TXT 文档链路

文件层根据扩展名确定初始 `DocumentKind`，编码检测和换行保留继续复用 `FileService`。纯文本支持查找、撤销、恢复和外部变更；大纲、Markdown 格式化、渲染/对照和语义导出在命令查询阶段禁用。扩展名变化只改变文档类型，不改写正文。

### 22.4 Windows 集成与图标

平台层以声明式 `AssociationPlan` 管理 Markdown/TXT 两个 ProgID、OpenWith、Capabilities、命令和 DefaultIcon。注册表写入局限于 HKCU，撤销时比较所有权和值；`UserChoice` 永远不在计划中。UI 只注册候选并可打开 Windows 默认应用设置，最终默认选择完全由用户完成。

应用、Markdown 文档和 TXT 文档 ICO 使用稳定资源 ID 编入 EXE。ProgID 引用 EXE 内资源索引；注册变化后发送文档化 Shell 通知，不重启资源管理器。

### 22.5 线程与失败边界

10 MB 组合操作的读取、预解析和文件准备可在后台执行，但 HWND、会话提交和最终用户确认只在 UI 线程。后台结果携带 DocumentId/Revision，过期结果丢弃。双目标补偿失败、资源回滚失败和注册表部分失败均为明确的非成功终态。

### 22.6 便携程序安置

`ApplicationPlacementService` 位于 platform 层，只接收当前 EXE 与目标文件夹，输出规范目标、是否同路径、是否需覆盖及提交结果。复制事务使用目标目录内独占临时文件，刷新并逐字节校验后原子替换 `MarkdownMay.exe`；它不删除源 EXE、不遍历或整理目标目录。

UI 通过“安置马冬梅…”模态对话框收集可编辑文件夹路径，并复用应用现有未保存文档门禁。提交后由新 EXE 使用受控内部参数在普通单实例仲裁前等待旧 PID 退出，随后修复候选文件关联并打开当前已保存文档。安置不改变 `UserChoice`，也不建立更新器、安装器或后台常驻组件。
