# DEF-048 打开文件后首次模式切换失效跟踪记录

> 日期：2026-08-28  
> 状态：代码修复及相关回归完成，等待用户实窗复核  
> 样本：`docs/需求规格说明书_V04.md`

## 1. 用户可见现象

启动应用时三模式切换正常。打开既有 Markdown 文档后，第一次选择源码模式时工具栏按钮已进入选中态，但文档区仍显示渲染视图；随后选择对照模式也可能不改变文档区，再次选择源码模式才恢复。

## 2. 影响分析

- 需求：EDIT-009、EDIT-010B～EDIT-010E、EXT-004；模式命令必须立即显示与选中态一致的视图。
- 设计：`ViewModeController` 仍是三模式状态机的唯一所有者，不增加第二套正文或模式状态。
- 代码：`editor/view_mode_controller.*` 的模式显隐落实逻辑。
- 测试：`tests/integration/view_modes_test.cpp`，增加逻辑模式与实际子窗口显隐短暂错位后的自愈回归。
- 数据安全：不改变 `DocumentSession`、磁盘文件、源码同步或保存语义。

## 3. 根因与修复过程

模式按钮的选中态查询 `ViewModeController::mode()`，文档区则由两个 Win32 子窗口的实际显隐决定。旧实现遇到 `target == mode_` 时直接返回，并且显隐调用分散在创建、重载和切换路径中；因此在打开文件投影期间若逻辑模式和窗口显隐短暂错位，按钮会按逻辑模式亮起，同模式命令却不能修复文档区。

本次将显隐、源码/对照布局和强制重绘收口为 `ApplyModeVisibility`。创建后的重载和每次模式切换都通过这一入口落实实际视图；即使目标等于逻辑模式，也会重新校正窗口显隐并恢复焦点。
