# 第六阶段封闭后缺陷修复记录

> 记录编号：MM-DEFECT-2026-001
> 日期：2026-08-02
> 基线：`155d9c4 feat: close phase 6 application integration`
> 范围：封闭阶段实现偏差修复，不改变 V02 产品范围

## 1. 缺陷与既有需求

| 缺陷 | 用户可见问题 | 既有需求 | 结论 |
| --- | --- | --- | --- |
| BUG1 | 渲染文档区没有动态垂直滚动条，鼠标滚轮无效 | EDIT-002、EDIT-008、UI-013～014 | 已有交互能力的实现缺陷 |
| BUG2 | 菜单栏、弹出菜单和菜单项过矮，不符合 Win11 记事本式体验 | OBJ-007、UI-009、UI-013～014 | 已有 UI/DPI 要求的视觉实现缺陷 |
| BUG3 | 打开 Markdown 时滚动到文末且加载期间不可操作 | OBJ-001、PERF-002、EDIT-010C | 打开位置和投影行为缺陷 |
| BUG4 | 渲染模式输入 `---` 不即时显示分隔线 | EDIT-002、EDIT-004、EDIT-010A、MD-011 | 所见即所得同步缺陷 |

上述四项均不新增产品能力，不修改 V02 冻结需求；修复继续以唯一 `DocumentSession` 为状态源。

## 2. 修复设计与实现

- BUG1：渲染 RichEdit 增加 `WS_VSCROLL`，由系统按内容范围动态显示/隐藏；增加明确的 `WM_MOUSEWHEEL` 子类处理，按每个滚轮刻度三行滚动。
- BUG2：菜单改为 Win32 owner-draw；96 DPI 基准菜单项约 33 px、菜单字体 14 px，并随 DPI 缩放；选中、禁用及高对比度颜色继续取系统颜色。
- BUG3：投影前保存选区和滚动位置，投影后恢复；文件重载前后显式把选区和视口置于文首，删除原先每次投影强制选中文末的行为。
- BUG4：RichEdit 订阅 `ENM_CHANGE`；收到 `EN_CHANGE` 后向 UI 消息队列投递同步，待当前按键完成后提交到 `DocumentSession` 并重新投影，避免在光标尚未更新时重入。

## 3. 影响检查

| 维度 | 结论 |
| --- | --- |
| 需求/文件格式/图片/导出/系统集成 | 无需求语义变化；不改变 Markdown 字节格式和导出输入 |

| UI/DPI/主题/无障碍 | 菜单尺寸按 DPI 缩放；高对比度使用系统颜色；保留键盘菜单和助记键 |

| 测试 | 应用外壳测试增加滚动条、滚轮、文首打开、owner-draw 菜单和 `---` 即时语义验证 |
