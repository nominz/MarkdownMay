# 第六阶段封闭后缺陷修复记录

> 记录编号：MM-DEFECT-2026-001
> 日期：2026-08-02
> 基线：`155d9c4 feat: close phase 6 application integration`
> 范围：封闭阶段实现偏差修复，不改变 V02 产品范围

## 1. 缺陷与既有需求

| 缺陷 | 用户可见问题 | 既有需求 | 结论 |
| --- | --- | --- | --- |
| BUG1 | 渲染文档区没有动态垂直滚动条，鼠标滚轮无效 | EDIT-002、EDIT-008、UI-013～014 | 已有交互能力的实现缺陷 |
| BUG2 | 菜单栏、弹出菜单和菜单项过矮，不符合 Win11 记事本式体验 | OBJ-007、UI-009、UI-013～014 | 已有 UI/DPI 要求的视觉实现缺陷 |
| BUG3 | 打开 Markdown 时滚动到文末且加载期间不可操作 | OBJ-001、PERF-002、EDIT-010C | 打开位置和投影行为缺陷 |
| BUG4 | 渲染模式输入 `---` 不即时显示分隔线 | EDIT-002、EDIT-004、EDIT-010A、MD-011 | 所见即所得同步缺陷 |

上述四项均不新增产品能力，不修改 V02 冻结需求；修复继续以唯一 `DocumentSession` 为状态源。

## 2. 修复设计与实现

- BUG1：渲染 RichEdit 增加 `WS_VSCROLL`，由系统按内容范围动态显示/隐藏；增加明确的 `WM_MOUSEWHEEL` 子类处理，按每个滚轮刻度三行滚动。
- BUG2：菜单改为 Win32 owner-draw；96 DPI 基准菜单项约 33 px、菜单字体 14 px，并随 DPI 缩放；选中、禁用及高对比度颜色继续取系统颜色。
- BUG3：投影前保存选区和滚动位置，投影后恢复；文件重载前后显式把选区和视口置于文首，删除原先每次投影强制选中文末的行为。
- BUG4：RichEdit 订阅 `ENM_CHANGE`；收到 `EN_CHANGE` 后向 UI 消息队列投递同步，待当前按键完成后提交到 `DocumentSession` 并重新投影，避免在光标尚未更新时重入。

## 3. 影响检查

| 维度 | 结论 |
| --- | --- |
| 需求/文件格式/图片/导出/系统集成 | 无需求语义变化；不改变 Markdown 字节格式和导出输入 |
| 文档模型与三模式 | 仍只有 `DocumentSession`；只提前提交渲染模式已有编辑事务 |
| UI/DPI/主题/无障碍 | 菜单尺寸按 DPI 缩放；高对比度使用系统颜色；保留键盘菜单和助记键 |
| 性能 | 每个已完成输入消息后触发一次当前同步；重复投递在内容无变化时立即返回 |
| 测试 | 应用外壳测试增加滚动条、滚轮、文首打开、owner-draw 菜单和 `---` 即时语义验证 |

## 6. 第二轮用户复测修正

用户复测第一轮提交后继续报告五项问题：顶层菜单仍矮且宽、选中态为蓝色；打开仍有可见滚动过程；三模式切换改变视口；逐键输入时 `---` 仍未即时成为分隔线；正文贴近边框。

第二轮修正：

- 顶层菜单与弹出项分开度量：弹出项继续保持原 33 px 基准；顶层菜单改为 36 px 基准，宽度按文字实测加 20 px 边距；普通主题选中态改为浅灰，高对比度继续使用系统高亮色。
- RichEdit 全量投影在 `WM_SETREDRAW(FALSE)` 期间完成，恢复选区和视口后才一次重绘，消除打开时“先滚再回顶部”的可见过程。
- 模式切换同时捕获源视图的首个可见行/总行数比例，并在目标视图恢复，避免 `EM_SCROLLCARET` 或 Scintilla 选区恢复改变文档区位置。
- 使用真实 `WM_CHAR` 逐键路径回归；检测完整 `---` 行并保证它与前一正文之间具有独立块边界，立即投影为 thematic break。
- RichEdit 使用随 DPI 缩放的 8 px 格式矩形内边距，正文不再贴住窗口边框。

第二轮验证：

- 菜单/布局/三模式/所见即所得四项直接回归 4/4 通过。
- Debug 完整回归最终 36/36 通过；前一轮 `wysiwyg_input_integration` 曾受系统剪贴板时序影响失败，单测复跑及第二次完整回归均通过。
- Debug、Release `MarkdownMay.exe` 均构建成功。

## 7. 第三轮用户复测修正（2026-08-03）

用户复测发现：在渲染模式输入两个空行后键入单独的 `*`，源码正确但项目符号被投影到上一段末尾，并产生可放置插入点的异常空白；同时原生非客户区菜单栏仍受 Windows 系统高度限制，未达到记事本的菜单行高度，顶层悬停区和下拉菜单也缺少 Win11 圆角观感。

本轮修正：

- Markdown 解析后的范围修复增加空列表项处理：从当前解析游标定位真实的 `-`、`*`、`+` 列表标记行，修正零长度 `list_item` 及父 `list` 的 `SourceRange`。渲染投影继续只读取 `DocumentSession` 的语义文档与源码，不建立第二套正文状态。
- 顶层菜单从受非客户区系统度量限制的 `HMENU` 菜单栏改为客户区原生子控件菜单栏，96 DPI 基准高度 36 px，宽度按各标签实测文字宽度加边距计算；悬停/按下背景使用浅灰圆角矩形。
- 下拉菜单项不再 owner-draw，恢复由 Windows 11 系统菜单绘制，以采用系统弹出窗口圆角、高亮、阴影和辅助功能行为；既有命令 ID、状态查询和快捷键表保持不变。
- 主窗口布局把菜单栏高度显式计入工具栏与文档区的纵向起点，避免新增菜单栏覆盖工具栏或正文。

自动验证：

- `MarkdownMayFullProjectionUnit` 增加“段落 + 空行 + 单独 `*` + 后续标题”回归，验证项目符号位于段落和标题之间、源码映射落在真实星号位置且不产生异常连续空行。
- `MarkdownMayAppShell` 验证主窗口不再安装受系统限制的非客户区菜单、客户区菜单栏不低于 36 DPI 缩放像素，以及文档区布局包含菜单栏高度。
- Debug、Release 的 `MarkdownMayFullProjectionUnit` 与 `MarkdownMayAppShell` 均返回 0；Debug/Release 主程序构建成功。
- Debug 完整回归为 34/36：本轮直接相关测试全部通过；既有 `wysiwyg_block_integration` 在撤销断言处稳定返回 6，既有 `wysiwyg_input_integration` 本轮出现一次输入时序失败。两项均如实保留为未通过，不记为 36/36，后续需单独诊断其与本轮变更的关联。

## 8. 客户区菜单不可见紧急修正（2026-08-03）

第三轮提交把 owner-draw 顶层菜单按钮错误地创建为背景 `STATIC` 栏的子控件，导致 `WM_DRAWITEM` 和 `WM_COMMAND` 发往背景栏而非主窗口；Release 实际运行只显示空白菜单区域。修正为背景栏与六个菜单按钮均直接隶属主窗口，按钮保持在背景栏上方，绘制和点击消息由主窗口统一处理。

应用外壳回归新增真实控件路径断言：必须能通过主窗口 ID 9000 取得“文件”按钮，按钮父窗口必须是主窗口且标题必须包含“文件”。重新构建并直接运行 Release `MarkdownMayAppShell` 返回 0；目标 Release 主程序已在用户指定路径重新生成。

## 9. 列表触发、菜单覆盖与弹出项高度修正（2026-08-03）

- 单独一行输入 `*` 时按普通文本投影；只有继续输入空格形成 `* ` 后才转为无序列表黑点。
- 列表合成标记的源码映射终点由列表项起点改为正文起点，黑点后的插入位置对应 `* ` 之后；继续输入中文不再写到星号之前。
- 顶层菜单背景 `STATIC` 改为隐藏布局控件，消除其重绘覆盖菜单按钮的问题；按钮继续由主窗口 owner-draw，实际 Release 截图已确认六个菜单文字可见且无静态方框。
- 弹出菜单恢复 owner-draw 项，96 DPI 基准高度 33 px；选中背景使用圆角矩形。弹出期间通过 DWM 请求圆角窗口，兼顾菜单框圆角与项目高度。
- 新增逐键 `*`、空格、`在` 集成回归，以及裸星号/列表标记源码映射、菜单项高度回归。Debug/Release 六个直接测试目标均返回 0。

## 10. 菜单交互与列表续项复测修正（2026-08-05，待验证）

本轮建立独立的 `缺陷台账.md`，统一登记历次用户反馈、自动证据、人工验收和关联提交。本轮四项缺陷编号为 DEF-010～DEF-013。

- 弹出菜单除 DWM 圆角偏好外，增加真实圆角窗口区域，裁掉右下角仍呈方形的窗口/阴影边缘。
- 弹出菜单的模态消息循环监听鼠标位置；鼠标横移到其他顶层菜单按钮时结束当前菜单并立即打开目标菜单，不要求再次单击。
- 渲染模式回车同步不再依赖投影前后的折叠源码偏移必须相等；列表编辑器优先执行续项，无法映射时才按普通换行处理。
- 每次重新投影后按 `DocumentSession` 的最新源码选区恢复插入点，避免使用投影前已失效的控件坐标把后续空格写到上一行。
- 空的 `1. ` 前缀补充有序列表投影语义，最多接受 3 个前导空格；集成用例覆盖无序列表续项和 `1.`、空格、正文、回车生成 `2. `。

- `markdown_parser.cpp` 的空列表范围修复现同时识别无序标记和“数字 + 点”的有序标记；投影层把裸 `1.` 按原始文本显示，只有形成 `1. ` 后才显示有序列表语义。
- Debug 完整增量构建成功；解析器、完整投影、列表和应用外壳直接回归通过。完整 Debug 回归 35/36，唯一失败为既有 `wysiwyg_block_integration` 撤销断言（退出码 6），不得记录为 36/36。

## 11. 块边界回车、列表续项与对照切换复测修正（2026-08-08）

用户报告四项问题，登记为 DEF-014～DEF-017。其中 DEF-014“单实例改多窗口”与 V02 SHELL-009 直接冲突，属于需求变更，已形成 V03 草案条款和《多窗口需求变更影响分析》，评审前不修改启动代码。本节实现范围仅为 DEF-015～DEF-017。

- RichEdit 文本差分在文档中间遇到连续换行时，可能把用户新输入的换行与后续既有换行混淆。同步逻辑改用控件报告的真实插入点反推旧投影源码位置。
- 普通段落回车重新投影后保留控件插入点，使光标停在新空行；列表续项则按 `DocumentSession` 的新源码选区恢复到新项目符号之后。
- 从源码/对照模式切回渲染模式时，同步源码但抑制即将隐藏的对照右栏刷新，避免同一大文档连续执行两次完整 RichEdit 投影。
- `wysiwyg_paragraph_integration` 新增文档中间段落回车及插入点断言；`wysiwyg_list_integration` 新增前后均有正文的列表续项断言；`view_modes_integration` 新增小文档和约 15,000 字文档中对照编辑后立即切回渲染的 2 秒响应断言。

- 本轮直接 Debug 回归 `wysiwyg_paragraph_integration`、`wysiwyg_list_integration`、`view_modes_integration` 全部通过。
