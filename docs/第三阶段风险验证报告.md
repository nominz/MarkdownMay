> 文档编号：MM-RISK-001  
> 版本：1.0

## 1. 阶段结论

第三阶段已建立可编译、可测试的 C++20 工程基线，并完成下列高风险技术点验证：

1. MSVC、CMake、Windows SDK 工具链可用；
2. Release 可生成为不依赖 VC Runtime DLL 的单 EXE；
3. Win32 + 系统 RichEdit 可创建中文可编辑窗口；
4. Scintilla 5.6.4 可静态编入单 EXE，适合源码模式；
5. MD4C 0.5.3 可静态解析 GFM 标题、表格、任务项与中文；
6. WIC 可离线读取本地图片，并在解码前执行像素上限检查；
7. 不依赖 Office 或浏览器内核即可写出最小 PDF、DOCX 容器；
8. 接口草案可被 C++20 编译器整体包含；
9. Debug、Release 和 CTest 流程可重复执行。

技术路线可以继续采用：

`C++20 + Win32 + RichEdit + Scintilla（静态）+ MD4C（静态）+ WIC`

本阶段样机只证明技术可行性，不是第四阶段正式产品代码。

## 5. 启动与内存测量

RichEdit Release 样机采用两段启动：

1. 先创建并显示主窗口；
2. 再通过窗口消息创建 RichEdit 编辑区；
3. OLE 不在启动关键路径初始化，首次插图时再按需初始化。

同机连续五次测得首窗口创建时间：

`291.791 ms、321.461 ms、173.249 ms、218.885 ms、559.262 ms`

- 中位数：291.791 ms；
- 最快：173.249 ms；
- 最慢：559.262 ms；
- 编辑区创建完成后工作集约 33.5 MB；
- 空闲稳定样本曾测得约 17.3 MB，Windows 缓存会造成波动。

结论：典型首屏达到约 300 ms，但冷启动仍有明显波动。正式实现必须保留两段启动、延迟 OLE/图片/解析器初始化，并在真实文件打开阶段继续做冷启动测试。

## 6. 各风险项结论

| 风险 | 结论 | 后续约束 |
| --- | --- | --- |
| CMake + MSVC 工程 | 通过 | 固定 preset，CI 使用相同配置 |
| 单 EXE | 通过 | 所有自有目标统一 `/MT`；新增依赖必须检查 DLL |
| RichEdit 中文编辑 | 技术通过 | 中文输入法、撤销、Emoji 需人工回归 |
| RichEdit 首屏速度 | 条件通过 | 必须两段启动，禁止启动时初始化 OLE 和导出模块 |
| Scintilla 静态链接 | 通过 | 只用于源码模式和对照模式左栏 |
| MD4C GFM | 通过 | MD4C 只解析，语义模型和规范化由自有代码承担 |
| 本地图片 | 通过 | 不提供远程下载入口；解码前检查像素数 |
| PDF 容器 | 最小验证通过 | 当前仅 ASCII 样例；正式版必须完成中文字体子集、可搜索文字、分页 |
| DOCX 容器 | 最小验证通过 | 当前为 Store ZIP；正式版必须完成样式、编号、关系、图片、表格 |
| 接口草案可编译 | 通过 | 后续接口变更必须同步详细设计和影响矩阵 |

## 7. 尚需人工验收的项目

以下项目需要在用户电脑的实际软件环境中完成，不能用自动测试代替：

1. 微软拼音及常用第三方输入法：候选框位置、组合输入、撤销重做；
2. 100%、125%、150%、200% DPI 及跨显示器移动；
3. 用常用 PDF 阅读器打开最小 PDF；
4. 用 Microsoft Word 和 WPS 分别打开最小 DOCX；
5. 检查 Scintilla 中中文、Emoji、复制粘贴、撤销重做。

这些人工项不会改变本阶段工程选型，但失败时必须在进入相应正式模块前修正。

## 8. 已识别但不在本阶段解决的问题

- 渲染模式的 Markdown 语义模型与 RichEdit 双向位置映射；
- RichEdit 原位图片对象和表格编辑；
- 三模式共享文档会话与增量同步；
- PDF 中文字体子集、分页、链接、表格、图片；
- DOCX 压缩、样式、编号、图片、表格和关系；
- 文件关联注册、卸载和便携模式；
- 真实大文件的打开、解析、投影和保存性能。

这些工作应严格按瀑布增量路线进入后续阶段，不把风险样机直接扩写为正式产品。
