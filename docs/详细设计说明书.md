## 1. 使用方式

本文件按组件编号规定到文件级的职责、接口、状态、算法和测试。编码任务必须引用组件编号，例如：“实现 CMP-FILE-03，目标文件 `fileio/file_saver.*`，满足 FILE-010/011”。

约定：

- `UI` 表示唯一 UI 线程；
- `BG` 表示后台工作线程；
- `R` 表示 `Revision`；
- 所有内部 Markdown 文本均为 UTF-8；
- 字节范围采用半开区间 `[begin, end)`；
- `MUST` 规则编码时不得改变。

### 2.1 CMP-UI-06：关于窗口

`ShowAboutDialog(owner)` 创建固定客户区约 720 × 420 逻辑像素的原生模态窗。组件持有当前 DPI、字体和内存图片资源；`LayoutAboutControls` 是唯一布局入口，以 96 DPI 逻辑尺寸计算人物照、身份、联系入口、分隔线与页脚，在初始化和 `WM_DPICHANGED` 后调用。人物照采用 contain 等比绘制且保留 PNG Alpha；应用图标使用已嵌入的 `IDI_MARKDOWNMAY`。

链接使用 `SysLink` 的短显示文本与真实 URI 分离。邮箱优先于项目链接，微信链接只显示微信号并打开 `ShowWechatDialog`；二维码窗口同样使用 DPI 感知的等比图片绘制。`WM_CLOSE`、`IDCANCEL` 和“关闭”按钮统一结束模态窗。版本文字来自 CMake 生成的 `markdownmay/build_version.hpp`，源文件不得出现另一份版本字符串。

## 3. 应用启动

### 3.1 CMP-APP-01：入口

执行顺序：

1. 记录进程起始时间，不分配日志线程；
2. `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`；
3. `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`；
4. `CoInitializeEx(nullptr, COINIT_APARTMENTTHREADED)`；
5. 安装顶层异常过滤器；
6. 解析命令行；
7. 形成多实例启动计划；多路径中的后续路径派生独立进程；
8. 若为次实例，发送路径并退出；
9. 构造 `Application`；
10. 创建主窗口并进入消息循环；
11. 有序停止后台任务、写设置、撤销 COM。

任何窗口创建前失败均使用系统消息框显示最小中文错误。窗口过程最外层捕获所有异常，转换为 `APP-9001`，不能让异常穿过 Win32。

### 3.2 CMP-APP-03：命令行

支持：

```text
MarkdownMay.exe
MarkdownMay.exe <一个或多个路径>
MarkdownMay.exe --register
MarkdownMay.exe --unregister
MarkdownMay.exe --safe-mode
```

1.0 UI 只有单活动文档。收到多个路径时打开第一个，其余路径进入“待打开队列”；关闭/保存当前文件后继续，或者在 UI 中让用户选择。禁止静默丢弃。

路径来自 `CommandLineToArgvW`，不自行按空格拆分。

## 4. 文档会话

### 4.1 CMP-DOC-01：状态

```text
Closed
  → Loading
  → OpenValid | OpenInvalid
  → Saving
  → OpenValid | OpenInvalid
  → Closing
  → Closed
```

`DocumentSession` 只在 UI 线程修改。后台解析结果通过窗口私有消息或 UI 调度队列提交。

版本递增规则：

- 任何改变源码字节的操作使 `SourceRevision += 1`；
- 成功解析当前源码后 `ParsedRevision = SourceRevision`；
- 成功写盘后 `SavedRevision = 被保存快照的 Revision`；
- 若保存期间用户继续编辑，保存成功仍保持 dirty，因为 `SavedRevision < SourceRevision`；
- 版本从 1 开始，0 表示不存在。

### 4.2 解析结果接收

`accept_parse_result(result)`：

1. 检查 `DocumentId`；
2. 检查 `result.source_revision == current SourceRevision`；
3. 检查语义树内部 revision；
4. 运行快速 validator；
5. 通过后原子替换 `SemanticDocument` 和 `ParsedRevision`；
6. 发布一次 `DocumentParsed` 事件；
7. 任何检查失败均拒绝结果；过期结果不作为用户错误。

### 4.3 脏状态

```text
Clean      : SourceRevision == SavedRevision
Modified   : SourceRevision != SavedRevision
RecoveryOnly: 未命名文档或保存失败但已有恢复快照
```

窗口标题使用 `*` 加文字“未保存”，不能只用颜色。

## 5. 三模式实现

### 5.1 CMP-EDIT-01：模式控制器

控制器持有三个表面，但一次只显示：

- Render：一个可编辑 RichEdit；
- Source：一个可编辑 Scintilla；
- Split：左侧复用同一 Scintilla，右侧为单独只读 RichEdit。

源码控件在 Source 和 Split 之间复用，避免两份源码缓冲。Render 和 Split 右栏是两个投影表面，但都只从同一语义快照更新。

`switch_to(target)` 算法：

1. 若相同模式，返回成功；
2. 提交当前 IME 组合输入；
3. 完成活动编辑事务；
4. 捕获当前 `ViewLocation`；
5. 若目标需要渲染，要求 `ParsedRevision == SourceRevision`；
6. 版本不等且正在解析，等待结果的 UI 状态不超过 300 ms；不得阻塞消息循环；
7. 解析失败则保持当前模式并返回 `EDITOR-2004`；
8. 确保目标控件内容版本正确；
9. 切换可见控件；
10. 映射并恢复位置；
11. 更新菜单、工具栏、状态栏。

### 5.2 CMP-EDIT-03：源码表面

Scintilla 配置：

- UTF-8 code page；
- CRLF/LF 显示遵循会话，不自动转换；
- Markdown lexer 只负责着色，不改变文本；
- 解析错误使用 indicator 和 margin marker；
- 修改通知合并为 `SourceChange`；
- 大批量投影时关闭通知，完成后一次同步版本；
- 源码控件自身 undo 栈不作为最终跨模式撤销依据。

### 5.3 CMP-EDIT-05：防抖解析

```text
收到源码变更
→ SourceRevision++
→ 取消旧计时器和旧解析任务
→ 150 ms 后复制不可变 UTF-8 快照
→ BG 解析
→ UI 按 DocumentId/Revision 接收
```

连续输入时最大延迟为 500 ms：即使一直输入，也要周期性产生解析结果。10 MB 文档将防抖提高到 350 ms，仍遵守最大延迟。

解析失败：

- 保留完整源码；
- `ParseState = Invalid`；
- 保存可用；
- Render 和导出禁用；
- Split 右栏清除旧内容，显示错误摘要；
- 错误范围在源码中标记；
- 不修改最近成功语义树，但它不可用于显示或导出。

### 5.4 CMP-EDIT-06：RichEdit 投影

全量投影：

1. `WM_SETREDRAW(FALSE)`；
2. 清空目标；
3. 深度优先遍历块节点；
4. 插入文字和对象；
5. 通过 TOM 设置段落和字符格式；
6. 建立 `ProjectionMap`；
7. 设置投影修订号；
8. 恢复选区和滚动；
9. `WM_SETREDRAW(TRUE)` 并失效窗口。

`ProjectionMap` 记录：

```text
NodeId → RichEdit [cpMin, cpMax)
RichEdit cp → NodeId + nodeOffset
NodeId → SourceRange
```

图片使用稳定对象占位符 U+FFFC 对应 OLE 对象。表格优先使用 TOM 表格；功能验证不满足时使用自定义块对象，但不得改变上层接口。

### 5.5 CMP-EDIT-07：渲染编辑同步

RichEdit 修改通知先转换为候选操作：

- 文本插入/删除；
- 段落拆分/合并；
- 格式范围改变；
- 对象插入/删除；
- 表格单元格操作。

不直接从整个 RichEdit 反推 Markdown。每个用户动作通过命令或通知映射成 `DocumentEdit`，应用到不可变树的 copy-on-write 路径，validator 通过后序列化为源码。

若收到无法映射的 RichEdit 变更：

1. 立即阻止提交；
2. 从最近有效语义快照重建受影响投影；
3. 恢复选区；
4. 返回 `EDITOR-2011` 并记录诊断；
5. 不改变 SourceRevision。

## 6. 编辑事务与撤销

### 6.1 CMP-EDIT-08：事务

事务字段：

- 唯一 ID；
- 来源模式；
- 前后源码修订；
- 前后源码差异或模型操作；
- 前后选择；
- 文件副作用，如图片重命名；
- 用户可读描述。

提交顺序：

```text
验证前置版本
→ 执行可回滚文件准备操作
→ 应用模型/源码变化
→ validator
→ 序列化
→ 提交会话版本
→ 完成文件副作用
→ 写入 undo
→ 通知视图
```

失败按相反顺序回滚。无法回滚文件名时保留两者并报错，不允许删除文件。

### 6.2 跨模式撤销

应用级 undo 是权威。每个视图的原生 undo 关闭或截获：

- 源码输入按时间和光标连续性合并；
- IME 一次上屏为一个事务；
- 一次格式命令为一个事务；
- 图片删除加重命名为一个复合事务；
- 模式切换不是 undo 项；
- 保存不是 undo 项。

撤销后同步当前可见表面；其他表面在下次显示前按版本刷新。

## 7. 语义模型

### 7.1 CMP-DOC-02：节点

正式实现不得沿用接口草案中“所有属性放通用字段”的简化方式。节点使用 `std::variant` 或多态不可变值：

```text
Block = Paragraph | Heading | Quote | List | CodeBlock | Table
      | ThematicBreak | UnknownBlock
Inline = Text | Emphasis | Strong | Strike | InlineCode | Link | Image
```

节点 ID：

- 新打开文档从 1 单调分配；
- 局部编辑保留未改变节点 ID；
- 删除后 ID 不复用；
- 全量重新解析时用源范围、节点种类和内容指纹匹配旧 ID；
- 无法匹配则分配新 ID。

### 7.2 CMP-DOC-05：不变量

至少检查：

- 根只有块节点；
- 行内节点不能直接包含块；
- 标题级别 1～6；
- 表格每行列数一致；
- SourceRange 合法且子范围不越父范围；
- NodeId 唯一；
- 受支持节点没有环；
- 图片目标非空或有明确 missing 状态；
- 文档 revision 与会话 parsed revision 一致。

Release 中保存和导出前运行快速检查；Debug 和测试运行完整检查。

## 8. Markdown

### 8.1 CMP-MD-01/02：解析

MD4C 回调不得抛异常进入 C 代码。适配器用 `noexcept` 回调捕获状态：

- 回调只追加事件或设置错误；
- 输入指针在 parse 调用结束后失效，不存裸指针；
- 所有范围转换检查溢出；
- 最大嵌套深度 128；
- 单节点最大字节数受总文件限制保护；
- 原始 HTML 作为 UnknownBlock，不执行。

### 8.2 CMP-MD-03：写入

稳定规范：

- ATX 标题 `#`；
- 无序列表默认 `-`；
- 有序列表保留起始号，后续规范编号；
- 粗体使用 `**`，斜体使用 `*`；
- fenced code 使用至少三个反引号，长度避开内容冲突；
- 表格使用 GFM 管道格式；
- 本地图片路径使用 `/` 作为 Markdown 分隔符；
- 必要字符按 CommonMark 转义；
- 文档末尾恰好一个换行。

序列化首先产生 LF UTF-8，文件层再转换目标换行和编码。

### 8.3 CMP-MD-04：未知块

UnknownBlock 保存：

- 原始 UTF-8 字节；
- 原始 SourceRange；
- 内容指纹；
- 前后空行信息。

只要用户没有删除或在其内部进行渲染编辑，writer 原样输出。源码模式可直接修改它，下一次解析重新识别。

## 9. 文件和编码

### 9.1 CMP-FILE-01：读取

- 使用 `CreateFileW`，共享读、写、删除，允许外部编辑器；
- 普通路径初始读取上限 64 MB，超过时询问而非直接分配；
- 获取最终规范路径和文件 ID；
- 分块读取，检查短读；
- 不使用内存映射作为首版默认，避免外部替换复杂性。

### 9.2 CMP-FILE-02：编码

检测顺序：

1. UTF-8 BOM；
2. UTF-16 LE/BE BOM；
3. 严格 UTF-8 验证；
4. 否则返回不支持编码，不猜测 ANSI 代码页。

新文档：UTF-8 无 BOM、CRLF。已有文档保留编码；Mixed 换行保存时弹出选择，默认统一为占比最高者。

### 9.3 CMP-FILE-03：原子保存

临时文件名：

```text
.<原文件名>.markdownmay.<进程ID>.<随机数>.tmp
```

必须与目标同目录。流程：

- `CREATE_NEW` 防碰撞；
- 写入全部字节；
- `FlushFileBuffers`；
- 目标存在则 `ReplaceFileW`，不存在则 `MoveFileExW(MOVEFILE_WRITE_THROUGH)`；
- 失败删除临时文件；删除失败登记下次清理；
- 更新文件身份；
- 不自行改变 ACL。

### 9.4 CMP-FILE-04：外部变更

目录通知只是触发器。收到通知后比较：

- volume serial + file ID；
- 最后写入时间；
- 文件大小；
- 必要时内容快速哈希。

自身保存期间用预期文件身份抑制回声通知。

## 10. 图片

### 10.1 CMP-FILE-05：资源目录

`<文档名>.assets` 中的文件视为受管资源，但程序只操作自己明确引用的文件，不扫描并删除孤儿。

导入命名：

- 首选原文件名；
- 冲突且内容相同则复用；
- 冲突且内容不同则 `name_2.ext`；
- 剪贴板图片为 `image_YYYYMMDD_HHMMSS_N.png`；
- 路径写成相对 Markdown 路径。

### 10.2 `del_` 标记

前置检查：

1. 解析规范路径；
2. 确认直属或位于当前 `.assets` 下且未逃逸；
3. 确认当前语义文档无其他引用；
4. 确认不是远程或外部图片；
5. 选择不冲突的目标名。

使用 `MoveFileExW` 重命名，不覆盖。撤销时如果原名被占用：

- 不覆盖；
- 生成安全恢复名；
- 更新恢复后的 Markdown 引用；
- 提示用户。

## 11. 导出

### 11.1 CMP-EXP-01：快照

创建导出请求时检查：

```text
ParsedRevision == SourceRevision
SemanticDocument.revision == SourceRevision
validator == OK
```

否则返回 `EXPORT-6001`。`ExportDocument` 把 NodeId 保留为诊断来源，但不持有 UI 对象。

### 11.2 CMP-EXP-02：PDF

进入具体格式 writer 前，`BuildExportDocument` 接收独立 `ExportContext`。该上下文只用于在创建固定修订快照时解析本地图片引用并复制有界字节；远程、缺失和超限资源以枚举状态冻结。writer 不得在稍后重新读取正文语义或以网络补齐资源。公式使用 `formula_inline`/`formula_block` 语义节点保存源码和类型，当前不包含可执行或排版 AST。

布局单位统一为 1/1000 pt。分页算法：

1. 测量块所需高度；
2. 段落按行断页；

## 22. DC-2026-004：V04 详细设计冻结

### 22.1 导出类型与快照门禁

新增 `export` 模块正式实现，核心值类型如下：

- `ExportScope { outline, full }`；
- `ExportFormat { pdf, docx, txt, html }`；
- `ExportRequest { scope, format, target, revision, options, profile }`；
- `ExportDocument { revision, source_path, blocks, resources }`；
- `ExportBlock`/`ExportInline` 使用拥有型值保存 writer 所需语义、NodeId 和源范围，不保存 `document::Node*`。

`ExportDocumentBuilder::build` 接收一次 `DocumentSnapshot`。它依次验证语义存在、`parsed_revision == source_revision`、请求修订一致、快速不变量通过、scope/format 组合合法；任一失败返回稳定错误且不创建目标临时文件。`outline` 只复制 Heading 并保留实际级别；`full` 深拷贝全部支持语义。HTML 与 outline 组合在 V04 中返回选项无效。

### 22.2 公共任务和原子提交

`ExportTask` 拥有固定 `ExportDocument`、`ResolvedExportOptions`、取消令牌和进度 sink。writer 输出到目标目录内不可预测的唯一临时文件。writer 完成后执行格式校验，再刷新文件缓冲并用既有原子文件设施提交。取消、异常诊断、无权限、磁盘满和校验失败统一清理临时文件，不删除或截断既有目标。

进度是单调的阶段/完成量，不允许后台线程直接操作 HWND。UI 通过发布消息读取状态；关闭窗口时先请求取消，不无限等待。

### 22.3 Writer 边界

- `TxtWriter`：UTF-8 无 BOM、CRLF；按 V04 TXT-003～008 做确定性语义降级。
- `PdfWriter`：复用页面选项，文字保持可复制搜索；字体由 DirectWrite 枚举 Windows 已安装字体并记录回退诊断。
- `DocxWriter`：生成 Open XML 部件、关系和媒体 ZIP；不启动 Word/WPS。
- `SafeHtmlWriter`：先转义普通文本和原始 HTML，再生成语义标签、严格 CSP、内嵌 CSS/固定数据资源和本地图片 `data:`。远程资源永不取回。

Mermaid/公式在 `ExportDocument` 中保存类型和源码。PDF/DOCX/TXT 生成可见占位及源码；HTML 生成无事件属性的受控容器。公式浏览器排版只有在单文件、零网络、无自带字体样机通过后启用，否则固定使用源码占位。

### 22.4 文档组合组件

`DocumentCombineService` 负责解码、最少边界换行、链接重写计划和受管图片复制计划；计划全部可执行后才提交一次正文事务。资源复制使用补偿记录，正文提交失败时回滚新资源。`DocumentSplitService` 验证 UTF-8/CRLF 边界，预解析前后候选，并通过 `DualTargetCommit` 协调两个临时文件；默认不改变当前会话。

### 22.5 多窗口启动和共享服务

`StartupCoordinator` 默认直接创建当前进程窗口。多个输入路径按顺序启动同一 EXE 的独立子进程并传递单一路径；路径使用既有安全命令行引用。旧 `SingleInstance` 不再是普通启动门禁，可在迁移完成后删除。`SettingsService`、`RecentFilesService` 和恢复索引采用跨进程锁内的“重新读取—合并—原子写入”，锁等待有上限并返回可诊断错误。

### 22.6 MDM ProfileService

解析器只接受受限 YAML 数据模型，并在构造完整对象前限制字节数、深度、节点数、序列长度和标量长度。schema 校验把值转换为 `ResolvedProfile`；应用层永远不读取未验证 YAML 节点。监视到变化后在后台解析，成功则原子替换当前配置快照并通知 UI，失败只发布诊断。旁车路径由当前正文路径替换扩展名得到；字体值必须通过系统已安装字体枚举。

## 23. DC-2026-006：V05 第八阶段详细设计冻结

> 状态：2026-08-12 用户批准；接口名可在 8.1 头文件正式化时微调，但不变量不得弱化。

### 23.1 CMP-COMB-01：SourcePositionMapper

输入 `DocumentId`、活动表面种类、表面修订、会话修订和原生选择位置；输出 `SourceOffset { uint64_t utf8_byte; Revision revision; }`。偏移不得超过源码长度，必须位于 UTF-8 码点边界且不在 CRLF 中间。渲染模式通过既有 `ProjectionMap`，源码/对照左栏通过 UTF-8 code page 位置映射。版本不一致返回位置过期错误，不猜测最近位置。

### 23.2 CMP-COMB-02/03：切分计划与双新目标提交

`SplitPlan` 拥有固定源码字节、文档类型、编码、换行、偏移、两个规范目标和候选诊断。目标必须不同、不等于源路径且在提交开始时不存在；两者扩展名必须继承当前 `.md/.markdown` 或 `.txt` 类型。

提交顺序：独占创建两个同目录临时文件 → 编码写入并刷新 → 重读校验 → 再确认最终目标不存在 → 移动前段临时文件 → 移动后段临时文件。后一步失败时删除本次创建的目标一和全部临时文件；补偿失败返回严重诊断并列出需用户处理的路径。服务从不调用 `DocumentSession::commit`，成功也不写 undo。

### 23.3 CMP-COMB-04～06：插入计划与事务

`InsertPlan` 包含来源固定字节、解码结果、最少边界换行、链接重写表、资源复制表和最终 UTF-8 插入片段。Markdown 来源进入受限语义扫描；TXT 来源只解码，不识别 Markdown 引用。来源 UTF-8/UTF-16 编码仅用于读取，插入后成为会话内部 UTF-8；最终保存统一调用 `EncodeText` 转为当前文档编码。

执行顺序：验证会话修订 → 独占准备资源目标 → 复制并校验资源 → 提交单次正文事务 → 登记 undo 文件副作用。失败反向删除仅由本事务新建的资源；不得覆盖或清理已有文件。来源路径只读打开且永不写回。

### 23.3.1 CMP-COMB-07：DOCX/PDF 条件 reader

8.3B 先验证 DOCX Open XML 只读提取与 PDF 文字层/阅读顺序检测。reader 输出有界的中间段落、标题、列表、表格或纯文本块，再转换为目标文档可插入文本；不复用导出 writer，也不启动 Office。PDF 页面没有可用文字层、文档加密禁止提取或阅读顺序质量不足时返回“不支持提取”，不执行 OCR。任何新增解析依赖须先通过许可证、安全、静态链接、单 EXE 体积和中文样本门禁。

最终决定（2026-08-13）：本组件不实现。风险样机已完成取证，但用户选择放弃 DOCX/PDF 插入，以维持轻量单 EXE 和零新增解析依赖；`CMP-COMB-04～06` 的 `.md/.markdown/.txt` 路线即为正式完整范围。

### 23.4 CMP-COMB-07：应用菜单与命令编排（8.8A）

“编辑”菜单在“全选”和“查找”之间增加独立分组：`edit_insert_document` 显示“在光标处插入文档…”，`edit_split_document` 显示“从光标处切分文档…”。两项均先调用活动 `ViewModeController` 同步表面并返回源码选区，再由 `SourcePositionMapper` 拒绝非折叠选区、过期修订、UTF-8 或 CRLF 非法边界。

插入使用单个打开对话框并调用既有 `DocumentCombineService`，提交后刷新活动表面和文档状态；切分仅在当前文档已命名时启用，连续使用两个保存目标对话框，目标必须尚不存在并保持源扩展名，再调用既有 `DocumentSplitService`。对话框取消均返回无副作用成功；领域失败由操作专用消息说明，不叠加通用错误框。

### 23.5 RichEdit 大文档投影复杂度门禁

`ProjectionSpan::begin/end` 到 RichEdit UTF-16 位置的换算必须在每次投影/主题重放开始时用一次线性扫描生成位置表，随后按 O(1) 索引；禁止每个 span 对正文前缀重复执行换行规范化和 UTF-8→UTF-16 转换。首次投影只对图片 span 执行对象插入，普通 span 的字符/段落格式统一由主题重放执行一次，不得对全部 span 连续格式化两遍。可见 RichEdit 在整次文本、字符格式和段落格式批处理中须通过 TOM `ITextDocument::Freeze/Unfreeze` 合并布局，RAII 保证所有返回路径解冻。性能回归使用约 50 KB 的标题、行内格式、列表、表格和代码块混合文档，在可见完整 `MainWindow` 中执行，Debug/Release 门限均为 10 秒。

“最近文件”命令由自绘弹出菜单分派时，`OpenRecentFile` 会更新最近文件顺序。该菜单内容不得在 `TrackPopupMenuEx` 的命令调用栈内同步重建：`MainWindow::set_recent_files` 只保存最新快照并投递专用 `WM_APP` 消息，消息循环恢复后再修改原生菜单。重建循环必须检查 `DeleteMenu` 返回值；Windows 暂时拒绝修改活动菜单时立即退出，禁止仅依赖未变化的菜单项数量继续循环。

### 23.4 CMP-DOC-07 / CMP-FILE-08：TXT 文档

`DocumentKind` 属于会话元数据。`plain_text` 的 `parsed_revision` 不伪装成 Markdown 解析成功；需要语义文档的命令统一通过 capability 查询拒绝。纯文本编辑仍调用会话源码事务，因此权威 undo、恢复和外部修改检测逻辑不分叉。

打开按扩展名路由类型，编码顺序继续为 UTF-8 BOM、UTF-16 BOM、严格 UTF-8。保存按会话编码/换行策略编码。另存扩展名变化在目标成功提交后才切换类型和 UI 能力，失败保持原类型。

### 23.5 CMP-PLAT-01～03：关联、默认应用与图标

`AssociationPlan` 为每个类型声明 ProgID、扩展集合、描述、命令和图标资源索引。`apply/remove/inspect` 都在 HKCU；remove 逐值比较当前 EXE 规范路径和已知数据，只删除自有叶值并保留未知子项。测试通过可注入的隔离 HKCU 子树，不触碰用户真实关联。

默认应用动作优先使用 Windows 文档化设置入口，失败回退默认应用主页。返回值只表示设置界面成功打开，不表示默认程序已改变。

资源编译为三类图标分配稳定正资源 ID；构建测试解析 PE 资源并核对 ICO 图层，关联测试核对 `DefaultIcon` 索引。调用 `SHChangeNotify` 后由人工矩阵验证资源管理器缓存刷新。

### 23.6 CMP-PLAT-04 / CMP-UI-07：程序安置

`ApplicationPlacementService` 公开 `inspect(source, folder)`、`place(plan)` 两阶段接口。`inspect` 拒绝空路径和非目录父路径，规范目标固定为 `folder / MarkdownMay.exe`，比较源/目标文件身份与字节内容并返回 `same_path`、`target_exists`、`same_content`。UI 只根据计划决定是否请求覆盖确认。

`place` 创建目标目录后，以 `CREATE_NEW` 打开同目录不可预测临时文件；循环复制源字节并检查大小溢出，调用 `FlushFileBuffers`，关闭后重新只读打开源与临时文件做分块逐字节校验。验证成功后使用 `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 提交；失败只删除本事务临时文件。服务不删除旧 EXE，也不改注册表。

`PlacementDialog` 是 DPI 感知的原生模态窗口，包含说明、文件夹编辑框、“浏览…”、“安置”和“取消”。默认路径由 `FOLDERID_LocalAppData / Programs / MarkdownMay` 得到；浏览使用 `IFileDialog + FOS_PICKFOLDERS`，手工路径与浏览路径进入同一检查。

对话框客户区按“标题与目的—安置位置—目标文件夹—目标程序预览—操作按钮”分层。安置位置使用同一 `WS_GROUP` 内水平排列的两个 `BS_AUTORADIOBUTTON`：“楼上322”和“自定义位置”。初始选择前者，路径框显示 `DefaultPlacementFolder()` 但与浏览按钮一同禁用；切换后者才启用路径编辑与文件夹浏览，并保留用户已输入的自定义值。两种模式最终仍把同一路径值交给 `ApplicationPlacementService::inspect`，不建立第二套验证流程。

标题使用加粗消息字体，正文和辅助文字使用系统消息字体；颜色取当前应用 `ThemePalette`，高对比度继续使用系统颜色。`WM_DPICHANGED` 重建字体并按 96 DPI 逻辑尺寸重排，`WM_SETTINGCHANGE/WM_THEMECHANGED` 刷新画刷和标题栏。默认/取消按钮分别保持 Enter/Esc 语义，Tab 顺序覆盖单选项、路径、浏览、安置和取消。

命令 `tools_place_application` 先调用现有 `ConfirmDocumentReplacement`。若文档已命名且保存成功，则把该路径作为新进程唯一打开参数；未命名空文档不传递路径。新进程命令行为 `--wait-for-process <pid> --repair-file-types [document]`，参数只由本程序生成；解析器只接受严格十进制、非零 DWORD PID，等待最多 30 秒。

启动顺序调整为：解析参数 → 若存在受控等待 PID，则打开 `SYNCHRONIZE` 句柄并等待退出 → 普通单实例仲裁 → 若指定修复则调用既有 `FileAssociationRegistry::register_application` → 创建窗口并打开文档。旧进程仅在 `CreateProcessW` 成功后请求正常关闭；若启动失败，旧进程继续运行并显示错误。
