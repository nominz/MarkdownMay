# 第九阶段块悬停与段落手柄需求变更影响分析

> 变更编号：CR-2026-029
>
> 日期：2026-08-22
>
> 结论：新增独立第九阶段；原系统测试/发布阶段顺延为第十/十一阶段

## 1. 影响结论

| 维度 | 影响 |
| --- | --- |
| 需求 | 新增 V07、BLOCKUI-001～020；明确首版不含拖拽排序 |
| UI | 渲染表面左侧悬停层、H1～H6 类型标志、手柄、原生上下文菜单、键盘与无障碍 |
| 文档模型 | 不新增正文模型；以有效语义修订、NodeId、SourceRange 建立短生命周期可见块索引 |
| Markdown | 不改变解析和序列化；块操作复用结构命令并经解析/范围门禁提交 |
| 三模式同步 | 渲染完整支持；对照右侧操作同一会话并同步左侧；源码模式不仿制悬停层 |
| 撤销/剪贴板 | 修改命令各为单事务；复制无事务；剪切同时满足剪贴板成功与正文提交边界 |
| 文件/图片/导出 | 文件格式、编码、换行、图片资源和导出内容无直接变化；复杂块操作不得破坏引用或资源 |
| 平台 | 原生 Win32/RichEdit/Scintilla；不新增第三方运行时或网络能力 |
| 非功能 | 增加可见区命中性能、主题、高对比度、100%～300% DPI、键盘/UIA 要求 |
| 测试 | 新增块索引/事务单元测试、RichEdit/对照集成测试、应用菜单测试、性能与人工视觉矩阵 |
| 文档 | 更新需求、阶段路线、总体/详细设计、功能矩阵和接续交接；实现封闭后再更新 README/用户说明 |

## 2. 主要风险与控制

1. RichEdit 可见行与 Markdown 块并非一一对应：命中必须从投影映射回稳定块，不按屏幕行直接修改源码。
2. 标题左侧已有折叠三角：三类控件预留固定槽位，并用互斥矩形命中。
3. 菜单打开期间正文可能被重投影或修改：菜单上下文固定 DocumentId/Revision/NodeId/range，执行前全部复核。
4. 列表、表格、引用和代码块结构边界复杂：能力查询只开放已有安全命令，未支持项禁用。
5. 频繁 `WM_MOUSEMOVE` 易引入性能回退：只查询可见块索引和缓存布局，不解析全文、不重投影。

## 3. 路线决定

该功能的交互、事务和兼容风险高于普通视觉修饰，且会改变后续完整系统测试的输入基线，因此独立设为第九阶段是合理的。第十阶段冻结功能后执行完整系统测试与缺陷修复；第十一阶段执行发布准备与最终验收。
