## 1. 基线关系与变更范围

V05 及其引用的 V04、V03、V02 未被本文替换的条款继续有效。本次只增加 Markdown 标题折叠能力，不改变 Markdown 文件格式、解析语义、保存结果、导出结果或 `DocumentSession` 唯一正文状态。

永久边界保持不变：Windows 原生 C++20/Win32、轻量、离线、无账号、无云、无遥测、无 Electron、无 WebEngine、无运行时下载、单 EXE 发布；TXT 仍是纯文本语义，不提供标题折叠。

## 2. CR-2026-023：Markdown 标题折叠

用户要求：打开 Markdown 文档，或者在新建文档中输入标题后，在各级标题前提供折叠功能，可把该标题所属层级的内容折叠起来。

### 2.1 范围与层级语义

| 编号 | 需求 |
| --- | --- |
| FOLD-001 | Markdown 文档的 H1～H6 标题均显示折叠控件；已打开文档和新建后实时输入形成的标题行为一致 |
| FOLD-002 | 折叠某标题时保留该标题可见，隐藏从标题结束后到下一个“同级或更高层级标题”开始前的全部内容；更低级标题及其正文属于该范围 |
| FOLD-003 | 展开恢复该范围；嵌套标题原有的独立折叠状态必须保留，例如先折叠 H2、再折叠其父 H1，展开 H1 后 H2 仍保持折叠 |
| FOLD-004 | 空章节仍显示标题折叠控件；切换不会隐藏其他章节，也不得越过文档末尾或合法源范围 |
| FOLD-005 | 折叠只影响当前窗口的编辑视图，不改写 Markdown 源码、不改变 `DocumentSession` 修订/脏状态、不进入撤销栈，也不影响保存、恢复、打印或导出内容 |

### 2.2 三种编辑模式

| 编号 | 需求 |
| --- | --- |
| FOLD-006 | 渲染模式在每个可见标题左侧显示可点击的展开/折叠三角；控件不成为正文字符，复制和保存均不包含该符号 |
| FOLD-007 | 源码模式在标题所在行的折叠边栏显示同等状态；折叠隐藏完整后续源码行，但标题源码行保持可见 |
| FOLD-008 | 对照模式左侧源码和右侧只读渲染使用同一折叠状态；从任一侧切换后，两侧在同一 UI 更新周期内同步 |
| FOLD-009 | 三模式切换不得丢失当前会话折叠状态；TXT 文档不显示折叠控件，也不保留伪 Markdown 折叠状态 |
| FOLD-010 | 标题控件点击只切换折叠，不移动正文插入点；点击标题文字仍按原行为定位和编辑 |

### 2.3 编辑、导航与状态生命周期

| 编号 | 需求 |
| --- | --- |
| FOLD-011 | 标题新增、删除、改级或普通正文编辑后，折叠范围按最新成功解析修订重算；通过稳定 `NodeId` 能对应的标题保留状态，新标题默认展开，已删除标题的状态丢弃 |
| FOLD-012 | 当前解析修订落后于源码修订或语义不可用时，撤销隐藏效果并暂时禁用折叠控件；不得用旧范围继续隐藏新正文 |
| FOLD-013 | 查找结果、大纲导航、错误定位或程序化选区落入折叠范围时，自动展开覆盖该位置的祖先章节，再完成定位 |
| FOLD-014 | 用户在折叠标题行输入或编辑标题时保持该标题可编辑；任何可能修改隐藏正文的命令必须先展开相应范围或明确作用于完整源码，不得静默丢失隐藏内容 |
| FOLD-015 | 新建、打开另一文档或重新打开文件时全部标题默认展开；首版不把折叠状态写入 Markdown、恢复文件或本地设置 |

### 2.4 可用性、无障碍与非功能要求

| 编号 | 需求 |
| --- | --- |
| FOLD-016 | 展开/折叠状态不能只靠颜色区分；使用方向不同的三角形，并适配浅色、深色、高对比度及 100%～300% DPI |
| FOLD-017 | 折叠控件提供可访问名称“折叠/展开：{标题文本}”、按钮角色和展开状态；键盘用户可在标题处使用 `Ctrl+Shift+[` 切换当前标题折叠状态 |
| FOLD-018 | 标题折叠命中区不得遮挡标题文字或现有大纲窗格；触摸板/鼠标滚动、选区和右键菜单保持原行为 |
| FOLD-019 | 折叠范围计算对标题数为 O(h)，应用可见性对受影响范围为 O(n)；约 50 KB 混合文档折叠/展开单次目标小于 100 ms，10,000 标题不得出现无限循环或越界 |
| FOLD-020 | 折叠实现不得建立第二套正文、不得删除控件文本、不得通过重新序列化折叠后的投影改变原文；异常或范围校验失败时恢复为全部可见并返回稳定诊断 |

## 3. 验收摘要

1. 构造 H1/H2/H3 混合文档，逐级折叠并验证边界、嵌套状态和文档末尾。
2. 在渲染、源码、对照三种模式分别切换折叠并验证同步、模式切换和编辑后重算。
3. 验证折叠前后源码字节、修订、dirty、撤销历史和保存文件完全不因折叠改变。
4. 验证查找/大纲导航进入隐藏章节时自动展开；解析暂时失效时不保留旧隐藏范围。
5. 完成 Debug/Release 构建、自动回归，以及浅色/深色、高 DPI、键盘和屏幕阅读器人工验收。

## 3A. CR-2026-026：表格与大纲缺陷修订

| 编号 | 需求 |
| --- | --- |
| TABLEVIS-001 | 渲染表格的行线必须位于相邻行的实际边界，不得穿过文字；表头和斑马底色必须覆盖完整单元格区域而非仅覆盖字符墨迹 |
| OUTLINE-026 | 左侧大纲使用可展开/折叠的层级树，父标题折叠时隐藏其子标题节点；折叠大纲树不改变正文、标题折叠状态或文档脏状态 |
| OUTLINE-027 | 点击任一大纲节点必须按该标题源码位置稳定定位当前编辑表面；目标标题在空间允许时对齐到视口顶部 |

## 4. 已冻结决定

- D1：首版折叠状态按“仅当前打开会话、重新打开全部展开”实现，不持久化到本地设置。
- D2：对照模式两侧共用状态，任一侧操作都会同步另一侧。
- D3：导航到隐藏内容时自动展开，而不是只把光标停在不可见位置。
- D4：空章节也显示控件，以满足“各级标题前均有折叠功能”的一致性。

以上 D1～D4 于 2026-08-18 经用户明确批准。
