# 马冬梅多窗口需求变更影响分析

> 变更编号：CR-2026-003
>
> 日期：2026-08-08
>
> 状态：评审草案，未批准实现

## 1. 变更结论

用户要求从 V02“默认单实例、第二次请求转交已有窗口”调整为“允许多窗口，每个窗口打开一个文档”。这不是既有实现偏差，而是与 SHELL-009 直接冲突的需求变更。建议采用多进程多窗口：每次启动形成独立进程、主窗口和 `DocumentSession`，保持当前单窗口单活动文档架构，不在一个进程内引入文档集合。

## 2. 影响范围

| 维度 | 影响 |
| --- | --- |
| 需求 | V03 以 SHELL-009-V03～014-V03 替换/细化 V02 SHELL-009～010 |
| 启动 | `app/startup.*` 不再把普通启动强制路由到既有进程；一次多路径启动需派生多个独立窗口/进程 |
| 平台 | `platform/single_instance.*` 从默认启动必经路径移除；可保留代码直至迁移验收完成，不立即删除 |
| 文件关联 | 每次关联启动创建新窗口；中文、空格、Emoji 路径规则不变 |
| 文档状态 | 每个窗口仍只有一个 `DocumentSession`；不同窗口完全隔离，不建立全局正文模型 |
| 保存冲突 | 同一文件被多个窗口打开时，依赖既有外部修改检测；必须补“双窗口先后保存”回归 |
| 设置/最近文件 | 设置文件和最近文件成为多进程共享资源，需要检查原子写入、合并和竞争，不得互相截断 |
| 恢复 | 恢复文件键必须能区分多个窗口/进程；一个窗口退出不得清理其他窗口的恢复状态 |
| 生命周期 | 关闭一个窗口只结束对应进程；其他窗口继续响应和保存 |
| 性能 | 多进程会按窗口增加工作集，但隔离性和实现风险优于单进程多文档窗口管理器 |
| 测试 | 替换单实例转发测试；增加双窗口、同文件冲突、多路径、多进程设置/最近文件竞争和独立退出测试 |

## 3. 设计变更方案

1. 保持 `Application → MainWindow → DocumentWindow → DocumentSession` 一对一所有权不变。
2. 默认启动路径跳过 `SingleInstanceCoordinator` 的互斥体取得和 IPC 转发。
3. 单路径启动由当前进程直接创建一个窗口；无路径启动创建一个空白窗口。
4. 多路径启动优先由启动进程按原参数派生其余独立进程，每个进程只接收一个规范化路径；必须设置递归派生保护参数，避免子进程再次拆分。
5. 文件关联、拖放和窗口内“打开”仍在当前窗口替换当前文档，并沿用未保存确认；“新建窗口”明确启动新进程。
6. 对共享 INI/最近文件/恢复数据增加跨进程写入设计和测试后才能实现，不能仅删除互斥体就宣称完成。

## 4. 风险与评审点

- 一次传入多个文件，是创建多个独立窗口（本草案建议）还是只打开第一个文件。
- “文件—新建”继续替换当前文档，还是改为新窗口；本草案建议保留当前行为，另设“新建窗口”。
- 同一文件多窗口打开是否允许；本草案建议允许，但保存必须经过外部修改冲突确认。
- 多进程同时更新最近文件和设置时必须避免最后写入者覆盖其他进程的新条目。

用户批准上述口径后，才能修改启动和单实例代码并形成新的 Release。
