## 1. 文档目的

本文定义马冬梅 1.0 的完整产品需求、约束和验收标准，是总体设计、详细设计、编码和最终验收的上位依据。

## 2. 产品定义

### 2.1 一句话定义

马冬梅是一个面向普通 Windows 办公用户的、原生轻量、所见即所得、支持图片和文档导出的 Markdown 记事本。

### 2.2 目标用户

- 财务、行政、人事、运营等非开发岗位；
- 需要直接阅读和修改 `.md` 文件的 Windows 用户；
- 不愿安装 VS Code、语言包、插件或大型运行时的用户；
- 需要免费、开源、离线工具的个人和组织。

### 2.3 核心目标

| 编号 | 目标 |
| --- | --- |
| OBJ-001 | 用户双击 Markdown 文件后几乎感觉不到等待 |
| OBJ-002 | 用户不学习 Markdown 标记也能完成日常排版 |
| OBJ-003 | 阅读和编辑在同一个所见即所得文档表面完成 |
| OBJ-004 | 程序以单个 EXE 发布，不要求安装运行时或插件 |
| OBJ-005 | 文档仍是通用 Markdown 文件，不建立私有数据库 |
| OBJ-006 | 支持图片以及 PDF、DOCX 导出 |
| OBJ-007 | 默认中文，操作习惯接近 Windows 记事本和 Office |

### 2.4 永久产品边界

以下能力永久不属于本产品：

- 账号、登录、会员和付费功能；
- 云同步、在线文档、团队协作和远程存储；
- 广告、遥测和用户行为上报；
- 应用内检查更新和自动更新；
- 插件系统和插件市场；
- 笔记库、双向链接、知识图谱和项目管理；
- 内嵌浏览器、网页调试和脚本执行；
- Mermaid、LaTeX 及其他需要外部运行时的动态内容；
- Office 文档导入；
- macOS、Linux、Android、iOS 和 Web 版本；
- 以 Markdown 源码或左右预览作为主要编辑方式。

## 3. 运行环境与发布约束

| 编号 | 需求 |
| --- | --- |
| ENV-001 | 支持 64 位 Windows 10 和 Windows 11 |
| ENV-002 | 产品发布物为单个 `MarkdownMay.exe` |
| ENV-003 | EXE 不依赖随程序分发的 DLL、资源目录或配置文件 |
| ENV-004 | EXE 可从任意具有读取和执行权限的目录启动 |
| ENV-005 | 程序正常工作不得要求管理员权限 |
| ENV-006 | 程序不得要求安装 Visual C++、.NET、WebView2、Java 或 Node.js 运行时 |
| ENV-007 | 用户设置、恢复数据和日志保存到当前用户本地应用数据目录 |
| ENV-008 | 程序不得在正常功能中发起网络请求 |
| ENV-009 | 软件许可证为 MIT，源代码和构建说明公开 |

验收：

- 在干净的 Windows 10/11 虚拟机中只复制 EXE，能够启动、编辑、保存和导出；
- 使用网络监测确认正常操作没有外连；
- 普通用户账户能够使用除系统最终默认应用确认外的全部功能。

## 13. 性能与容量需求

性能在普通 SATA/SSD 办公电脑、Release 构建、杀毒软件正常开启条件下测量。测试机器配置和测量方法必须随报告记录。

| 编号 | 需求 |
| --- | --- |
| PERF-001 | 10 KB 普通文档冷启动到主窗口可见目标不超过 300 ms |
| PERF-002 | 10 KB 普通文档冷启动到可操作目标不超过 500 ms |
| PERF-003 | 热启动到可操作目标不超过 200 ms |
| PERF-004 | 空白文档稳定后工作集目标不超过 40 MB |
| PERF-005 | Release EXE 目标不超过 10 MB；若超出必须提交依赖和尺寸分析 |
| PERF-006 | 1 MB 混合格式文档能够在 2 秒内可操作 |
| PERF-007 | 10 MB 文本型 Markdown 能打开、编辑和保存，不崩溃 |
| PERF-008 | 连续中文输入时不得出现可感知的周期性冻结 |
| PERF-009 | 不可见的大图片不得在启动关键路径全部解码 |
| PERF-010 | PDF/DOCX 导出期间界面保持响应并显示可取消的进度 |

PERF-001～005 是强目标而非脱离硬件的绝对保证；若未达到，不得直接删除指标，必须提交测量、瓶颈和取舍供用户决定。

## 17. 需求追溯与验收规则

1. 每个需求编号至少对应一个自动测试、人工测试或检查记录。
2. 自动化可稳定验证的内容不得只写“人工看一下”。
3. UI 视觉、输入法、Word/WPS 兼容等必须保留人工验收记录。
4. 最终验收不接受“主流程可用但边界以后再补”。
5. 所有阻断级和严重级缺陷关闭后才允许发布 1.0。
6. 未达到性能目标时必须由用户书面接受偏差。

## 18. 本次评审重点

请重点确认以下默认规则是否符合预期：

1. 新文档默认 UTF-8 无 BOM、CRLF。
