> 版本：0.1（评审草案）

> 上一冻结基线：`需求规格说明书_V02.md` 1.0

## 1. 升版说明

V03 在 V02 基础上新增当前轻量版的大纲能力，并提出把默认单实例改为多进程多窗口的需求变更。V02 原文只读保留；本草案评审通过后，V03 将整理为包含全部既有条款的完整冻结基线。在本草案冻结前：

- 第一至第六阶段既有能力继续以 V02 为验收依据；
- 大纲仅进行需求、影响和设计评审，不进入代码实现；
- `DocumentSession` 仍是三种模式及大纲唯一的文档状态来源；
- 不引入 WebEngine、Electron、云服务、运行时下载或第二套正文模型。
- 多窗口仅完成需求与设计评审，不修改 V02 已封闭的单实例启动实现。

## 2. 变更请求

| 字段 | 内容 |
| --- | --- |
| 编号 | CR-2026-002 |
| 原始要求 | 当前轻量版增加大纲功能，并在第七阶段 PDF/DOCX 导出前完成 |
| 原因 | 长 Markdown 文档需要快速理解标题结构和定位 |
| 产品边界 | 文档内标题导航，不扩展为知识库、文件树、双向链接或项目管理 |

### 2.1 多窗口变更请求

| 字段 | 内容 |
| --- | --- |
| 编号 | CR-2026-003 |
| 原始要求 | 允许同时打开多个马冬梅窗口，每个窗口打开一个文档，以便并列比较 |
| 原因 | 轻量工具的真实使用场景需要多个独立窗口并列，V02 默认单实例会阻止该工作流 |
| 产品边界 | 多进程多窗口、每窗口单活动文档；不等同于窗口内多标签或同窗分屏 |

### 2.2 多窗口需求草案

| 编号 | 需求 |
| --- | --- |
| SHELL-009-V03 | 默认允许同时运行多个马冬梅进程和顶层窗口，不再把第二次启动请求强制转发给已有窗口 |
| SHELL-010-V03 | 每个窗口保持一个独立 `DocumentSession`、保存状态、撤销历史、视图模式和文件路径；不同窗口不得共享或覆盖正文状态 |
| SHELL-011-V03 | 从资源管理器双击、命令行或文件关联打开一个文件时，新启动进程创建一个窗口并打开该文件 |
| SHELL-012-V03 | 一次命令行传入多个文件时，每个有效路径创建一个独立窗口；路径顺序保持不变，任一文件失败不得阻止其他窗口打开 |
| SHELL-013-V03 | 同一文件允许在多个窗口打开；保存时继续使用既有外部修改检测，禁止静默覆盖其他窗口已保存的新版本 |
| SHELL-014-V03 | “新建窗口”创建新的独立进程/窗口；关闭一个窗口不得退出或影响其他窗口 |

上述条款拟替换 V02 SHELL-009，并细化原 SHELL-010。评审通过前不进入启动代码实现。

## 3. 大纲功能需求

### 3.1 基本呈现

| 编号 | 需求 |
| --- | --- |
| OUTLINE-001 | 大纲从当前 `DocumentSession` 最新有效语义文档的一至六级标题生成，不重新维护第二份正文或独立标题数据库 |
| OUTLINE-002 | 大纲显示在文档区左侧的可折叠侧栏；不遮盖正文，不使用弹出窗口作为常态载体 |
| OUTLINE-003 | 默认显示大纲；用户可通过“视图—大纲”、工具栏按钮和快捷键显示或隐藏 |
| OUTLINE-004 | 无标题文档显示非错误空状态“当前文档没有标题” |
| OUTLINE-005 | 每项显示标题可见纯文本；隐藏 Markdown 标记，不执行原始 HTML，不加载图片 |
| OUTLINE-006 | H1～H6 全部显示，按标题级别缩进；缺级标题保持实际级别关系，不虚构中间标题 |
| OUTLINE-007 | 侧栏宽度可拖动，DPI 缩放后默认宽度为 260 个 96-DPI 像素等价值，最小 180、最大不超过窗口客户区的 45% |
| OUTLINE-008 | 窗口文档区可用宽度低于 640 个 96-DPI 像素等价值时，大纲自动临时隐藏；窗口恢复后还原用户原显示意图 |

### 3.2 导航与状态

| 编号 | 需求 |
| --- | --- |
| OUTLINE-009 | 单击大纲项把当前编辑表面定位到对应标题，并把标题滚动到视口上部附近，不修改文档和撤销历史 |
| OUTLINE-010 | 渲染、源码、对照三种模式均可使用大纲；定位目标分别为渲染标题、源码标题行、对照模式左侧源码标题行 |
| OUTLINE-011 | 大纲高亮当前光标所在标题章节；光标在首个标题之前时不高亮任何标题 |
| OUTLINE-012 | 键盘支持 Tab 获得焦点、上下键移动、左右键折叠/展开层级、Enter 定位、Esc 返回编辑区 |
| OUTLINE-013 | 标题层级可在大纲内折叠；折叠只影响大纲显示，不折叠或隐藏正文 |
| OUTLINE-014 | 当前项、展开/折叠状态和层级向 Windows UI Automation 暴露可访问名称、角色和状态，不能只靠颜色表达当前项 |

### 3.3 实时更新与错误状态

| 编号 | 需求 |
| --- | --- |
| OUTLINE-015 | 渲染模式标题编辑成功提交后立即更新大纲；不得要求切换模式或保存 |
| OUTLINE-016 | 源码/对照左栏编辑后，大纲随既有解析防抖结果更新；普通文档目标为停止输入后 200 ms 内可见更新，连续输入最迟 500 ms 更新一次 |
| OUTLINE-017 | 当前源码解析失败时，大纲不得把旧标题冒充当前内容；显示“源码存在错误，大纲暂不可用”，保留完整源码和错误定位能力 |
| OUTLINE-018 | 源码恢复有效后大纲自动恢复，无需切换模式 |
| OUTLINE-019 | 同名标题作为不同节点分别显示和定位，身份以稳定 `NodeId` 为准，不以标题文字作为唯一键 |
| OUTLINE-020 | 标题插入、删除、改名、升级、降级、撤销、重做、打开新文件和外部重新载入后，大纲必须与当前会话修订一致 |

### 3.4 设置、性能与边界

| 编号 | 需求 |
| --- | --- |
| OUTLINE-021 | 本地设置保存用户的大纲显示意图和侧栏宽度；损坏或越界值使用安全默认值，未知设置键继续保留 |
| OUTLINE-022 | 大纲设置只存放于当前用户 LocalAppData，不写入 Markdown 文件，不随文档共享 |
| OUTLINE-023 | 10 MB 文本型 Markdown 或 10,000 个标题时，大纲不得导致崩溃；生成和刷新不得无上限阻塞 UI 线程 |
| OUTLINE-024 | 大纲只读取标题节点，不改变 Markdown 解析、序列化、保存、打印、PDF 或 DOCX 内容 |
| OUTLINE-025 | 大纲不提供拖动标题重排、批量升降级、正文折叠、全文搜索、文件树或跨文档导航；这些属于未来受控变更 |

## 4. 验收场景

1. 打开包含 H1～H6、缺级和同名标题的文档，大纲文本、层级、顺序与语义文档一致。
2. 在三种模式分别点击项目，定位到同一标题语义位置，文档不变脏且撤销栈不增加。
3. 在渲染模式修改标题以及在源码模式修改 `#` 级别，大纲按 OUTLINE-015/016 更新。
4. 制造解析失败，大纲清除旧标题并显示错误态；修复源码后自动恢复。
5. 折叠父项只隐藏其大纲后代，正文保持不变；键盘和屏幕阅读器可操作。
6. 100%～300% DPI、浅色、深色和高对比度下布局无截断；窄窗口自动隐藏并可恢复。
7. 设置重启往返保留显示意图和合法宽度，不修改 Markdown 文件。
8. 10,000 标题压力样例下界面保持响应，记录刷新耗时和工作集。

## 5. 评审决策点

本草案提出的唯一方案是“默认显示、左侧可折叠侧栏、H1～H6、支持层级折叠、保存显示意图与宽度”。请用户评审以下决策：

1. 是否接受默认显示；
2. 是否接受 260 px 默认宽度及窄于 640 px 自动隐藏；
3. 是否接受折叠只作用于大纲而不折叠正文；
4. 是否接受三种模式中的定位目标以当前可编辑表面为准；
5. 是否接受解析失败时清除旧大纲并显示错误态。

评审结论未记录前，本文件保持 0.1 草案状态。
