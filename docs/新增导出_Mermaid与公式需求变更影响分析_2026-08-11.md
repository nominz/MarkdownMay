# 新增导出、Mermaid 与公式需求变更影响分析

> 文档编号：MM-CR-2026-007-009
>
> 版本：0.3（全文 HTML 正式纳入第七阶段）
>
> 日期：2026-08-11
>
> 状态：已由 `需求规格说明书_V04.md` 1.0 于 2026-08-12 正式冻结；本文保留影响分析和方案论证

> 2026-08-11 新增不可协商约束：发布物必须始终为单个 EXE；Mermaid/公式只能原生实现或静态链接进 EXE；不得附带或嵌入自有字体，只能使用 Windows 当前已安装字体。

## 1. 变更背景

用户明确要求在继续第七阶段前补入三组能力：

1. 导出不再只有“PDF/DOCX 全文”，而是由“内容范围 × 文件格式”组成；内容范围至少包含仅大纲和全文，文件格式至少包含 PDF、DOCX、TXT。
2. Markdown 中允许粘贴 Mermaid 代码；当前应用内不解析，只显示安全占位符，保留源码。
3. Markdown 中允许粘贴公式代码；当前应用内不解析，只显示安全占位符，保留源码。
4. 候选方案是在“全文 HTML 导出”中保留这些代码并嵌入受控渲染资源，由用户使用系统浏览器打开后渲染整篇文档。

这些要求均属于正式产品范围变更。Mermaid 和公式与 V02 第 2 节及原产品技术方案中“明确排除 Mermaid、LaTeX 和需要 JavaScript 的内容”的旧条款直接冲突，因此不能作为普通缺陷或第七阶段顺带开发，必须升版需求基线。

## 2. 需求分解

### 2.1 CR-2026-007：二维导出模型

导出应先选择内容范围，再选择目标格式，两者是正交维度：

| 内容范围 | PDF | DOCX | TXT |
| --- | --- | --- | --- |
| 仅大纲 | 必须支持 | 必须支持 | 必须支持 |
| 全文 | 必须支持 | 必须支持 | 必须支持 |

定义：

- “仅大纲”只读取当前有效语义文档中的 H1～H6，按源顺序和标题层级输出，不包含标题下正文。
- “全文”包含标题和正文；标题本身自然构成文档结构，不额外插入一份重复大纲。
- 屏幕左侧 `OutlineView` 不是导出数据源；它和导出大纲都读取同一 `DocumentSession` 固定修订快照中的 Heading 节点。
- 六种组合使用同一导出入口和一致的成功、失败、取消、原子替换规则。

建议的产品交互是一个“导出”对话框：

```text
内容：○ 全文  ○ 仅大纲
格式：○ PDF   ○ Word（DOCX）   ○ 纯文本（TXT）
```

文件扩展名由格式决定。菜单不展开成六个独立命令，避免让普通用户面对过多入口。

### 2.2 TXT 的产品价值与建议语义

TXT 不是无用功能。它适合：

- 把标题结构交给不使用 Markdown 的人或旧系统；
- 生成可被记事本、邮件、工单和办公系统直接接收的纯文字；
- 消除 Markdown 标记后进行全文检索、归档、审阅或无格式复制；
- 在不能打开 PDF/DOCX 的环境中提供最低兼容输出。

建议把 TXT 定义为“语义纯文本导出”，而不是把 `.md` 原样另存为 `.txt`；后者只是改扩展名，产品价值很低。

以下建议规则已由 V04 冻结：

- 编码固定 UTF-8 无 BOM，换行使用 CRLF；
- 仅大纲：去掉 `#` 标记，H1 不缩进，H2～H6 每级增加两个半角空格；同名标题和缺级标题照原顺序输出；
- 全文：去掉粗体、斜体、删除线等排版标记，保留可见文字和段落；
- 列表保留 `-` 或数字序号，任务项保留 `[ ]`/`[x]`；
- 链接输出为 `显示文字（URL）`，图片输出为 `图片：替代文字（路径或地址）`；
- 表格建议输出为制表符分隔文本；代码块保留代码正文，不保留围栏；
- Mermaid 和公式在纯文本中保留源代码并带类型标识，避免信息丢失。

TXT 导出与“另存为 Markdown”必须保持概念分离：TXT 是派生输出，不改变当前文档路径、格式或已保存状态。

### 2.3 CR-2026-008：Mermaid 保留与占位

调整后的最小产品目标：

- 使用标准围栏代码块，例如 `````mermaid``；
- 源码/对照左栏继续编辑原始 Mermaid 文本；
- 渲染模式和对照右栏显示明确的 Mermaid 占位符，不在应用内解析或绘图；
- 无独立可视化编辑器，无拖拽节点，无属性面板；
- 因应用内不解析，不承诺 Mermaid 语法正确性；占位符可显示语言类型和源码摘要，不修改或丢弃源码；
- 离线运行，不调用云端 Mermaid 服务，不启动外部命令，不下载运行时。

应用内原生 Mermaid 解析和绘制延期，不进入当前阶段。支持的实际图类型由 HTML 中固定版本的 Mermaid 脚本决定，马冬梅只负责安全识别围栏、保留源码和生成 HTML 容器。

### 2.4 CR-2026-009：公式保留与占位

调整后的最小产品目标：

- 支持行内公式 `$...$` 和块公式 `$$...$$`；
- 源码模式编辑原始公式文本；渲染模式显示公式占位符，不在应用内排版；
- 无可视化公式编辑器；
- 应用内不判断公式是否有效，始终保留源码；浏览器渲染失败由导出的 HTML 显示错误；
- 支持复制原始公式源码；不执行宏中的外部命令或文件访问。

应用内原生公式排版延期。HTML 导出中的公式兼容范围由固定版本的浏览器端公式库决定，必须禁用危险宏、外部文件和网络加载。

### 2.5 CR-2026-013：全文 HTML 导出与浏览器间接渲染（正式范围）

新增正式导出组合：`全文 × HTML`。它导出整篇 Markdown 的标题、正文、列表、表格、链接、图片、代码块、Mermaid 和公式，不是只导出 Mermaid/公式片段。当前不要求 `仅大纲 × HTML`。

推荐产物为单个离线 `.html` 文件：

- 普通 Markdown 语义由马冬梅转换为安全 HTML；
- Mermaid 源码写入受控容器，由 HTML 内固定版本 Mermaid 脚本渲染；
- 公式源码写入受控容器，由 HTML 内固定版本公式脚本渲染；
- CSS、JavaScript 和必要的非字体资源全部内嵌在 HTML 中；
- 图片优先转为 `data:` 资源以保证单文件移动后仍可显示；超大图片的体积策略待冻结；
- HTML 默认设置严格 CSP，禁止联网、外部脚本、插件、表单提交和任意原始 HTML 执行；
- 用户在系统浏览器中打开文件后才执行内嵌渲染脚本，马冬梅自身不嵌入浏览器、不执行 JavaScript。

明确排除 CDN 方案：引用在线 Mermaid、KaTeX 或 MathJax 虽能显著减小 HTML，却违反离线、隐私和长期可重现要求。也不采用“HTML + js/css/fonts 文件夹”，因为这会降低导出物便携性。

公式仍有一个需要样机验证的问题：常见浏览器端公式库通常需要自己的数学字体资源。由于用户明确禁止携带或嵌入自有字体，样机必须验证以下路线之一：

1. 使用浏览器原生 MathML，并只依赖 Windows 已安装字体；但从 LaTeX 源码转为 MathML 仍需要安全转换器；
2. 使用能够仅依赖系统字体工作的浏览器端公式渲染方案；
3. 若两者均不能达到可接受效果，则 HTML 首版保留公式源码和占位，不承诺公式排版。

因此 Mermaid 的 HTML 间接渲染可行性较高；公式在“不携带字体”约束下仍需小型样机，不能提前写成已解决。

## 3. 技术可行性与难度

### 3.1 导出大纲

难度：低到中。

当前语义文档已有 Heading、层级、源顺序和稳定 NodeId，大纲 UI 也证明了读取路径。主要工作是把标题筛选和层级样式放入不可变 `ExportDocument`，并分别映射到 PDF、DOCX、TXT。不能直接截取 `OutlineView` 文本，因为 UI 状态不是导出模型。

### 3.2 TXT

难度：中。

文件写入本身简单，真正需要设计的是“丢弃格式但不丢失语义”的规则，尤其是链接、图片、表格、任务项、Mermaid 和公式。上述规则冻结后，实现和测试风险明显低于 PDF/DOCX。

### 3.3 Mermaid

难度：高，属于新技术风险。

官方 Mermaid 是 JavaScript 工具，其公开用法面向网页 DOM；常用官方 CLI 通过浏览器自动化渲染。将官方方案直接嵌入会带来 JavaScript/DOM/浏览器依赖，明显冲击“Windows 原生、轻量、无 WebEngine、单 EXE”的长期边界；调用在线服务又违反离线和隐私要求。

可选路线：

| 路线 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| WebView2/Chromium + 官方 Mermaid | 兼容性最高 | 违反无 WebEngine，体积和运行时依赖不可接受 | 排除 |
| 云端或外部 CLI | 实现快 | 违反离线、隐私、单 EXE和无运行时下载 | 排除 |
| 嵌入 JS 引擎并补 DOM/SVG | 可复用部分官方代码 | 集成复杂，仍引入较重脚本执行面和安全面 | 不推荐 |
| 原生解析、布局和 GDI/Direct2D 绘制 | 符合产品边界，可控且离线 | 只能分批实现语法子集，工作量大 | 推荐做风险样机 |
| 引入新兴原生第三方实现 | 可能减少工作量 | 成熟度、许可证、C++ 接入、兼容性和长期维护尚未验证 | 样机阶段评估，不直接承诺 |

粗略工程量（单名熟悉 C++/Win32 的开发者，包含自动测试，不含长期兼容维护）：

- 自研流程图单一最小闭环：约 6～10 周；
- 自研流程图、时序图、类图、状态图、ER 图五类可用子集：约 4～7 人月；
- 追求 Mermaid 官方二十余种图及大量语法兼容：至少 12～24 人月，且后续必须持续追随官方语法变化，不建议承诺；
- 若找到经过样机验证的静态原生库：五类子集的产品集成仍约需 6～12 周，用于 C++ ABI/构建、字体、主题、DPI、缓存、安全、三模式、打印、PDF/DOCX 和黄金测试；库只能减少解析/布局工作，不能消除产品集成工作。

上述是量级估算，不是排期承诺。样机必须以 Release EXE 增量体积、复杂图耗时、内存峰值和兼容样例实测后重新估算。

### 3.4 公式

难度：中高，但可控性优于 Mermaid。

当前固定版本 MD4C 已具备识别 `$...$`/`$$...$$` 数学 span 的开关，因此语法识别入口可复用；它不负责公式排版。KaTeX/MathJax 的主流集成仍面向 JavaScript、HTML/CSS、浏览器或 Node，直接引入不符合现有渲染架构。完整 MiKTeX/TeX 发行版体积大并可能下载包，也不适合本产品。

推荐先验证“小型原生公式 AST + DirectWrite/Direct2D 布局绘制”，并同时调研可静态链接、许可证兼容的原生数学排版库。首个样机必须验证中文系统字体环境、基线对齐、缩放、复制、打印和 PDF/DOCX 映射。

粗略工程量：

- 使用成熟、可静态链接的原生 C/C++ 数学排版库实现常用子集：约 6～12 周，主要工作是适配 AST/绘制接口、系统字体、RichEdit 投影、三模式、打印和导出；
- 自研常用 LaTeX 数学子集解析、盒模型布局和绘制：约 3～5 人月；
- 追求广泛 LaTeX 宏、AMS 扩展和复杂排版兼容：至少 9～18 人月，不符合轻量首版目标。

Microsoft 的 OpenType MATH 表能提供分数、根号、伸缩符号等字体度量，但它不是完整公式布局算法；即使使用 DirectWrite，仍需要解析器和数学布局引擎。运行时必须枚举 Windows 已安装字体并选择具备所需字形/数学度量的字体；找不到时显示明确占位或降级结果，不下载、不释放、不嵌入随程序携带的字体文件。

### 3.5 单 EXE 与字体硬门槛

以下条件高于 Mermaid/公式兼容数量和视觉效果，任何样机只要违反其中一项即判定路线失败：

1. 最终发布物始终只有 `MarkdownMay.exe`，不得附带 DLL、JS、WASM、字体、资源包、浏览器或命令行工具；
2. 所有第三方代码和必需资源必须经许可证审查后静态编入 EXE；不得首次运行解压辅助运行时到磁盘规避单 EXE；
3. 正常显示、打印和导出不得联网、调用云服务或启动外部程序；
4. 不嵌入或分发自有字体，只使用 Windows 当前已安装字体；
5. 字体缺失必须可诊断并安全降级，不能触发下载；
6. Release 样机必须记录 EXE 体积增量、冷启动、普通文档内存和复杂内容渲染耗时。

## 4. 对现有基线的影响

| 层面 | 影响 |

| 需求 | 新建完整《需求规格说明书_V04》；V02 中排除 Mermaid/LaTeX 的条款必须被明确替换，不能只追加备注 |
| 文档模型 | `NodeKind` 需增加 Mermaid/公式语义，或为代码块增加受控类型属性；必须保持未知语法原文往返 |

| 测试 | 增加解析、往返、渲染黄金、三模式、DPI/主题、安全、性能、打印和六种导出组合测试 |

## 5. 对阶段路线的影响

应用内 Mermaid/公式原生渲染已经延期，因此不再阻塞 PDF/DOCX/TXT 主线。通用导出模型仍应预留 `html` 格式和原始扩展块，以免后续返工。

建议把原第七阶段重排为：

1. **7.0 既有能力收口**：解决当前自动测试和 Windows 默认应用闭环；
2. **7.1 V04 需求与设计冻结**：冻结二维导出、TXT、Mermaid/公式占位和全文 HTML 候选行为；
3. **7.2 HTML 风险样机**：验证单文件、离线、CSP、Mermaid 浏览器渲染、公式系统字体路线和导出体积；
4. **7.3 通用导出模型**：内容范围先选择仅大纲/全文，格式选择 PDF/DOCX/TXT，并预留全文 HTML；
6. **7.5 TXT 六组合中的两项**：先封闭规则最清楚的仅大纲 TXT 和全文 TXT；
7. **7.6 PDF**：封闭仅大纲和全文 PDF，全文包含 Mermaid/公式；
8. **7.7 DOCX**：封闭仅大纲和全文 DOCX；Mermaid/公式按 V04 冻结的占位/源码规则处理；
9. **7.8 全文 HTML 与阶段封闭**：样机通过后实现完整 HTML；若公式字体路线未通过，只保留公式源码/占位并如实缩小范围。

这样安排把高风险的应用内图形/公式引擎从当前阶段移除，同时保留源码并利用浏览器处理 HTML 展示；马冬梅仍负责全文结构、安全转换和可移植导出。

## 6. V04 已冻结事项

以下事项已按 V04 的正式口径处理；原建议保留用于说明取舍：

1. TXT 是否采用本文建议的“语义纯文本”，而不是 Markdown 原文改扩展名；
2. 仅大纲 TXT 是否用两空格缩进，是否需要自动章节编号；
3. “全文包含大纲和正文”是否仅指标题天然存在于正文，还是要求在文件开头额外生成一份目录；本文建议不重复生成目录；
4. Mermaid 首版是否接受常用图类型子集，而非承诺官方全部图类型；
5. Mermaid/公式在 DOCX 中优先作为高质量矢量/图片嵌入，还是要求转换为 Word 可编辑原生图形/公式；本文建议首版不承诺 Word 原生可编辑对象；
6. 公式语法是否冻结为 `$...$` 与 `$$...$$`，以及首版 LaTeX 命令子集。

## 7. 当前结论

- 导出大纲、全文 TXT、仅大纲 TXT：产品价值成立，建议纳入当前版本。
- 导出结构：正式采用“内容范围 × 文件格式”的二维模型，不设计六套独立实现。
- 应用内 Mermaid 和公式解析：明确延期，当前只保留代码和显示占位符。
- 全文 HTML：正式进入第七阶段和 V04 范围；优先采用离线单文件方案。
- Mermaid HTML 渲染可行性较高；公式受“不嵌入字体”约束，仍需 MathML/系统字体样机。
- 单 EXE 与仅使用 Windows 已安装字体是硬门槛；如果某条技术路线不能满足，即使兼容性更好也直接排除。
- 在 V04 和风险样机结论批准前，不进入正式 PDF/DOCX writer，实现阶段不得绕过长期轻量与离线边界。
