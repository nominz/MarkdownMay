> 文档编号：MM-CR-2026-010-012
>
> 版本：0.1（需求分析草案）
>
> 日期：2026-08-11
>
> 状态：已由 `需求规格说明书_V04.md` 1.0 于 2026-08-12 正式冻结；本文保留影响分析和方案论证

> 永久边界：单 EXE 发布优先级最高且不可突破；配置只能引用 Windows 已安装字体，不允许 `.mdm` 指向、携带或触发下载字体文件。

## 1. 产品主线

本轮新增能力不是把马冬梅扩张成知识库或开发工具，而是强化它作为“个人文档工作台”的差异化：

- 能把长文档在当前位置安全拆开；
- 能把其他 Markdown 文件插入或追加到当前文档；
- 能同时打开多个独立文档窗口；
- 能把个人排版和导出偏好保存为可携带的 `.mdm` 配置方案并挂接使用。

这四项与大纲、查找替换、二维导出、Mermaid 和公式共同形成产品特点：结构化浏览、文档重组、个性化呈现和面向办公场景的输出。

## 2. CR-2026-010：文件切分、插入与追加

### 2.1 功能定义

| 功能 | 建议定义 |
| --- | --- |
| 在插入点切分 | 把当前文档的唯一源码在当前插入点映射到的 UTF-8 源偏移处分成前、后两个新 Markdown 文件 |
| 插入 Markdown 文件 | 读取用户选择的 `.md/.markdown`，转换为当前会话的 UTF-8 语义输入，并在当前插入点插入 |
| 追加 Markdown 文件 | 与插入使用同一服务，但目标位置固定为当前文档末尾 |

插入和追加不是“打开另一个文档”，而是一次对当前 `DocumentSession` 的事务性正文修改；必须进入撤销历史并把当前文档标记为未保存。

### 2.2 切分建议语义

1. 三种模式都以当前可编辑表面的插入点为准，由既有投影映射得到唯一源码偏移。
2. 不按字符编码字节中间切分；CRLF 也不得拆成孤立的 `CR`/`LF`。
3. 如果插入点位于 Markdown 标记、链接、代码围栏、表格行或其他结构内部，精确切分可能使一个或两个结果语法不完整。首版建议先预解析两个候选结果并明确警告，但仍允许用户坚持按当前位置切分，不擅自移动插入点。
4. 用户选择两个不同目标路径；目标不能相同，也不能与受保护的临时文件冲突。
5. 两个目标均写入临时文件并校验成功后才分别原子落盘；任一写入失败不得只留下半次成功而冒充完成。
6. 默认不删除或覆盖当前原文件。成功后保留当前文档，并提供“打开前半部分”“打开后半部分”或“两者都打开”的结果动作；多窗口实现后复用独立窗口。
7. 两个结果的编码和换行默认继承当前文档；切分本身不改变原文字符。

### 2.3 插入/追加的关键规则

- 识别被插入文件的 UTF-8 BOM、UTF-16 LE/BE 和换行，转换为当前会话的内部 UTF-8 表示。
- 在两段内容边界只补足防止语法粘连所需的最少换行，不静默改写正文其他部分。
- 插入前建立单次事务；解析失败时保留用户可恢复的原始输入并给出明确结果。
- 不能简单拼接原始字节：来源文件中的相对链接和图片路径以来源目录为基准，插入后基准会变。
- 对相对链接应计算并改写为相对于当前目标文档的新路径；无法安全改写时提示用户。
- 对受管图片建议复制到当前文档的 `<文档名>.assets`，使用不冲突文件名并重写引用；当前文档尚未保存时沿用既有规则，先要求保存。
- 远程图片仍只保留地址，不下载。
- 追加复用同一套编码、链接、图片和事务规则，不建立第二套实现。

### 2.4 失败和安全边界

- 源文件过大、不可读、编码损坏、路径无权限、磁盘满、图片复制失败均要有稳定错误码。
- 文件内容视为不可信输入；插入 Mermaid、公式或 HTML 时只进入既有安全解析路径，不执行脚本、命令或外部内容。
- 插入文件不得隐式修改来源文件；切分不得默认删除原文件。

## 3. CR-2026-003 升级确认：多窗口多文档

用户再次明确否定当前默认单实例体验。这里需要区分：

- “单实例”是无论启动多少次，系统中通常只有一个马冬梅进程，后续文件被转交到已有窗口。
- 用户需要的是同时并列打开多个文档，而不是把第二次打开请求排队交给一个窗口。

建议正式冻结为“多进程、多窗口、每窗口一个文档”：

1. 每次从资源管理器、命令行或“新建窗口”打开一个文档，创建独立窗口和独立 `DocumentSession`。
2. 一个窗口关闭、保存、撤销或切换模式不影响其他窗口。
3. 同一文件允许在多个窗口打开，但保存必须经过外部修改冲突检测。
4. 一次传入多个路径时按路径顺序创建多个窗口。
5. “文件—打开”默认在当前窗口打开；另提供“在新窗口打开”。
6. 本阶段不引入窗口内标签页；多标签是另一项产品决策，不能与取消单实例混为一谈。

实现上仍建议多进程而非一个进程持有多个文档窗口，因为它最大限度保持当前 `Application → MainWindow → DocumentSession` 一对一架构。需要补充设置、最近文件和恢复数据的跨进程合并与锁定。

## 4. CR-2026-011：MDM 可移植配置方案

### 4.1 文件定位

`.mdm` 是马冬梅配置方案文件，内容使用受限 YAML 子集。它不是 Markdown 正文，也不是插件或可执行脚本。

建议职责：

- 导出当前允许共享的配置为 `.mdm`；
- 导入 `.mdm`：把其值一次性复制为当前本地设置；
- 挂接 `.mdm`：保留对外部文件的引用，文件更新后重新加载；
- 解除挂接：回到本地设置和内置默认值，不删除 `.mdm` 文件。

### 4.2 配置分层

按从低到高的优先级合并：

```text
内置安全默认值
  < LocalAppData/settings.ini 本地设置
  < 当前挂接的全局 .mdm
  < 当前文档同名 .mdm 旁车方案
  < 高对比度等系统强制可访问性覆盖
```

建议首版允许配置：

- H1～H6、正文、引用、代码、表格的字体族、字号、字重、颜色、段前/段后和行距；
- 编辑区正文宽度、左右内边距、大纲默认宽度和显示偏好；
- 浅色/深色配色，但不得覆盖 Windows 高对比度强制规则；
- PDF/DOCX/TXT 的默认内容范围、格式、纸张、方向、边距、字体和标题层级样式；
- Mermaid 和公式的主题、字号、最大宽度等安全范围内选项。

不允许配置：可执行命令、脚本、DLL、网络地址自动加载、任意文件包含、注册表写入或无限资源参数。

字体字段只接受 Windows 当前已安装的字体族名称。找不到指定字体时按 V04 冻结的系统字体回退链处理并提示；不得从 `.mdm` 相对/绝对路径读取字体，不得把字体写入 EXE，也不得联网下载。

### 4.3 挂接路径放在哪里

不建议把普通 `.mdm` 挂接路径写入注册表。理由：

- 项目已有 LocalAppData `settings.ini`，它就是用户设置的正式存储位置；再引入注册表会形成两套设置真相。
- 注册表中的绝对路径不便备份、迁移和便携使用，文件移动后容易失效。
- 多窗口并发时注册表并不比经过原子写入和锁定的本地设置文件更自然。
- 注册表应继续只承担 Windows 文件关联/Capabilities 等平台职责。

建议方案：

| 挂接范围 | 路径发现/存储 |
| --- | --- |
| 全局配置 | `settings.ini` 保存 `active_profile_path`；相对路径按设置目录解析或保存规范化绝对路径 |
| 单文档配置 | 与正文同目录、同基本名的旁车文件，例如 `报告.md` 自动挂接 `报告.mdm` |
| 临时预览 | 只在当前窗口内存中应用，关闭窗口后失效 |

同名旁车的优势是 `报告.md` 与 `报告.mdm` 一起移动后仍能自动挂接，不需要维护以文档绝对路径为键的注册表映射。如果用户不希望自动挂接，可在本地设置中关闭该行为。

### 4.4 YAML 子集与兼容性

- 顶层必须包含 `schema_version`、`profile_name` 和 `settings`。
- 使用 UTF-8 无 BOM；字段名固定英文，显示名称可为 Unicode。
- 只接受映射、序列、字符串、布尔和有界数字；禁用自定义类型、对象构造、执行标签和递归别名炸弹。
- 未识别字段保留或忽略并给出诊断，旧版本按明确迁移规则升级。
- 导入/挂接前完成 schema 校验；错误配置不覆盖最后一次有效配置。

示例仅表达结构，字段尚未冻结：

```yaml
schema_version: 1
profile_name: "我的紧凑办公样式"
settings:
  typography:
    body:
      font_family: "Microsoft YaHei UI"
      size_pt: 10.5
    heading_1:
      size_pt: 18
      weight: 600
  outline:
    width_dip: 240
  export:
    default_scope: full
    default_format: docx
```

## 5. 工程影响

| 层面 | 影响 |
| --- | --- |
| 需求 | V04 增加文档切分、插入、追加、多窗口和配置方案需求；替换 V02 单实例条款 |
| 文档状态 | 全部正文变更仍经当前窗口唯一 `DocumentSession`；切分输出只读取固定快照 |
| 文件 I/O | 新增双目标事务、插入文件解码、相对路径重写和受管图片复制事务 |
| 三模式 | 统一提供可靠的插入点到源偏移映射；命令可用性保持一致 |
| 应用外壳 | 增加切分、插入、追加、新建窗口、在新窗口打开、配置导入/导出/挂接/解除命令 |
| 启动 | 普通启动移除单实例 IPC 必经路径；多路径拆为多个进程/窗口 |
| 设置服务 | INI schema 升版；增加 MDM schema、合并、监视、回退和多进程并发控制 |
| UI/样式 | 当前硬编码的标题和正文样式改为经校验的主题/排版配置，不允许越过 DPI 和高对比度边界 |
| 导出 | PDF/DOCX/TXT 使用同一有效配置快照；导出任务开始后配置变化不改变正在生成的文件 |
| 安全 | YAML、插入文件和路径均视为不可信输入；限制大小、深度、别名和资源值 |
| 测试 | 增加编码、边界切分、双目标失败、相对链接、图片事务、多进程、YAML 安全、配置层叠和六种导出组合测试 |

## 6. 难度与实施顺序

| 能力 | 难度 | 主要风险 |
| --- | --- | --- |
| 插入/追加纯文本 Markdown | 中 | 编码、换行、撤销和语法边界 |
| 插入含相对链接/图片的 Markdown | 中高 | 路径重写、图片复制和事务回滚 |
| 在插入点切分 | 中高 | 投影映射、结构中间切分、双目标原子结果 |
| 多进程多窗口 | 中高 | 设置/最近文件/恢复的跨进程竞争 |
| MDM 基础导入导出 | 中 | YAML 安全子集、schema 和迁移 |
| MDM 挂接与实时重载 | 中高 | 路径移动、坏配置回退、多窗口一致性 |
| 大量排版自定义 | 高 | 渲染、打印、三种导出、主题/DPI/无障碍的组合测试量 |

建议依赖顺序：

1. V04 冻结术语、交互、配置字段和失败行为；
2. 收口多窗口底层及共享设置并发；
3. 抽取统一的文档导入/路径重写服务；
4. 实现插入和追加；
5. 实现双目标安全切分；
6. 实现 MDM schema、导入导出和分层合并；
7. 实现全局/旁车挂接与安全重载；
8. 把排版配置接入屏幕、打印、Mermaid/公式和导出。

## 7. V04 已冻结决定

1. 切分成功后默认保留原文件；
2. 结构内部切分允许警告后按精确位置执行；
3. 插入本地图片默认复制到当前 `.assets`；
4. 首版只提供多窗口，不含窗口内标签页；
5. 自动发现 `报告.md` 同目录的 `报告.mdm` 旁车方案；
6. MDM 首批字段按 V04 MDM-010 的有界范围开放；
7. 挂接文件校验成功后自动应用，失败保留最后有效配置并提示。

## 8. 当前结论

- 四组功能均有清晰产品价值，适合纳入马冬梅差异化路线。
- 多窗口已由 V04 正式替换单实例需求；首版不增加标签页。
- 文件插入/追加必须处理相对链接和图片，不能用字符串拼接冒充完成。
- `.mdm` 采用受限 YAML、分层配置和同名旁车挂接；普通挂接路径不写注册表。
- 大规模样式自定义会显著扩大测试矩阵，必须按字段分批开放，不能一次放出任意配置。
