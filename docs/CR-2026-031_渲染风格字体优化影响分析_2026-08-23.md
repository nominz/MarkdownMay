# CR-2026-031 渲染风格字体优化影响分析

## 1. 用户决定

保留宋盈、元朗、明正、清晰四种风格的既有字号、标题粗体、稳定 ID、默认元朗及入口行为，只调整字体族，并建立可供后续指定修改的 `渲染风格字体字号基线.md`。

## 2. 影响范围

| 维度 | 结论 |
| --- | --- |
| 需求 | V07 升级为 1.1，CR-2026-031 替换 CR-2026-028 的字体族定义 |
| UI | 菜单、工具栏、显示名和默认选择不变；四种风格的渲染字体变化 |
| 文档模型 | 无影响；`DocumentSession` 仍是唯一正文状态 |
| Markdown / 文件 / 编码 | 无影响；不修改、解析或序列化正文 |
| 三模式同步 | 渲染模式及对照右栏使用新字体；源码模式不变 |
| 图片 / 导出 | 无影响；本次只调整屏幕 RichEdit 投影，不改变导出 profile |
| 平台 | 继续引用 Windows 已安装的宋体、黑体、等线和微软雅黑；不附带字体 |
| 非功能 | 无网络、无运行时下载、无新增依赖、单 EXE 边界不变 |
| 测试 | `render_style_unit` 增加四套正文字体和标题字体的精确断言；执行 Debug/Release 构建和相关回归 |
| 文档 | 同步 V07、总体设计、详细设计、功能影响矩阵、新参数基线及阶段/交接记录 |

## 3. 实现边界

本次不增加运行时解析 Markdown 配置文件的能力。人工维护基线用于后续需求沟通和代码同步，避免形成伴随文件或第二套运行时配置来源。
