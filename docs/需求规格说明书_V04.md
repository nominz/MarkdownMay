## 1. 基线组成与优先级

V04 是当前最高正式需求基线。它采用受控增量整合方式：

1. V02 中未被本文件明确替换的完整产品、功能和非功能条款继续有效；
2. V03 的 OUTLINE-001～025、FIND-001～009、UI-015-V03 继续有效；
3. V03 的多窗口草案由本文件 SHELL-009-V04～016-V04 正式替换；
4. V02 中“排除 Mermaid、LaTeX”的产品边界由本文件 EXT-001～010 替换；
5. V02 PDF-001、DOCX-001 由二维导出范围条款扩展，其余 PDF-002～012、DOCX-002～011 在不冲突处继续有效；
6. 发生冲突时按“用户当前明确指令 → V04 → V03 已冻结条款 → V02 → 设计文档”的顺序解释。

V04 不改变以下永久边界：Windows 原生 C++20/Win32、轻量、离线、无账号、无云服务、无遥测、无 Electron、无 WebEngine、无运行时下载；正式发布物保持单个 EXE；`DocumentSession` 是每个窗口三种编辑模式唯一的正文状态。

## 3. 导出需求

### 3.1 通用模型

| 编号 | 需求 |
| --- | --- |
| EXPORT-001 | 导出先选择内容范围，再选择格式；菜单使用一个统一入口，不展开为六个独立命令 |
| EXPORT-002 | PDF、DOCX、TXT 必须支持“仅大纲”和“全文”；HTML 当前只支持“全文” |
| EXPORT-003 | 仅大纲只读取固定修订语义文档中的 H1～H6，保持源顺序和实际层级，不包含标题下正文，不自动生成章节编号 |
| EXPORT-004 | 全文包含标题和正文，不在文件开头重复插入一份目录或大纲 |
| EXPORT-005 | 左侧 `OutlineView` 不是导出数据源；大纲和全文都从同一 `DocumentSession` 最新有效固定修订建立不可变导出快照 |
| EXPORT-006 | 创建快照时必须满足 `ParsedRevision == SourceRevision` 且语义不变量有效；否则禁用全部导出，不得使用旧语义内容 |
| EXPORT-007 | 导出开始后的编辑和配置变化不得改变正在生成的文件 |
| EXPORT-008 | 成功前写同目录唯一临时文件并完成结构校验，再原子替换目标；失败或取消不得覆盖有效目标或留下伪成功文件 |
| EXPORT-009 | 导出期间 UI 保持响应，显示可取消进度，并明确报告成功、失败或取消 |
| EXPORT-010 | 输出不得包含编辑器界面、大纲窗格、查找栏、光标、选区、用户名、计算机名或未要求的本地路径元数据 |
| EXPORT-011 | 不使用 Office 自动化、云转换、外部 CLI、运行时下载或首次运行释放辅助组件 |
| EXPORT-012 | 导出对话框记忆经验证的默认选项，但不改变当前 Markdown 文档路径、保存状态或编码 |

### 3.2 PDF 与 DOCX

- PDF-002～012、DOCX-002～011 继续有效。
- PDF-001-V04：支持仅大纲或全文导出为 PDF。
- DOCX-001-V04：支持仅大纲或全文导出为 DOCX。
- 仅大纲 PDF/DOCX 用标题样式和层级缩进表达结构。
- 全文 PDF/DOCX 中 Mermaid/公式首版保留类型、源码和明确占位，不承诺应用内或 Office 原生可编辑图形/公式对象。

### 3.3 TXT

| 编号 | 需求 |
| --- | --- |
| TXT-001 | TXT 是语义纯文本派生输出，不是把 Markdown 原文改扩展名 |
| TXT-002 | 固定使用 UTF-8 无 BOM 和 CRLF |
| TXT-003 | 仅大纲去掉 `#`；H1 不缩进，H2～H6 每级增加两个半角空格；同名和缺级标题照原顺序输出 |
| TXT-004 | 全文去掉行内排版标记，保留可见文字、段落和标题 |
| TXT-005 | 列表保留 `-` 或数字序号，任务项保留 `[ ]`/`[x]`，代码块保留代码正文而不保留围栏 |
| TXT-006 | 链接输出为“显示文字（URL）”；图片输出为“图片：替代文字（引用）”；不得下载远程图片 |
| TXT-007 | 表格输出为制表符分隔的行；单元格内换行转换为空格 |
| TXT-008 | Mermaid 和公式保留源码并带类型标识，确保信息不丢失 |
| TXT-009 | TXT 与 PDF/DOCX 共用 EXPORT-006～012 的修订、原子性、取消和隐私规则 |

### 3.4 全文 HTML

| 编号 | 需求 |
| --- | --- |
| HTML-001 | 导出完整当前文档为单个离线 `.html`；当前不提供仅大纲 HTML |
| HTML-002 | 普通 Markdown 转换为安全语义 HTML；CSS、固定版本脚本和允许内嵌的图片资源包含在同一文件内，不依赖 CDN 或伴随目录 |
| HTML-003 | 马冬梅只生成文件，不嵌入浏览器、不在进程内执行 JavaScript；用户使用系统浏览器打开结果 |
| HTML-004 | Mermaid 源码写入受控容器，由内嵌固定版本资源在浏览器中尝试渲染；失败时保留源码和可见错误 |
| HTML-005 | 公式优先经样机验证的 MathML/系统字体路线；不得携带或嵌入公式字体。路线不满足约束时首版保留源码和占位，不得虚报排版支持 |
| HTML-006 | 设置严格 CSP，禁止外部网络、外部脚本、插件、表单提交、原始 HTML 事件处理器和非预期活动内容 |
| HTML-007 | 原始 HTML、Mermaid 和公式均视为不可信输入；必须转义/清理并限制输入大小、嵌套、执行时间和内存 |
| HTML-008 | 本地受支持图片可转为 `data:`；远程图片继续显示阻止加载占位，不发起网络请求 |
| HTML-009 | 单文件资源超过冻结上限时明确失败或按规则降级，仍遵守原子目标文件要求 |
| HTML-010 | 至少验证 Windows 当前受支持主流浏览器的离线打开、零网络、打印预览和失败回退 |

## 4. Mermaid 与公式源码保留

| 编号 | 需求 |
| --- | --- |
| EXT-001 | 识别 `mermaid` 围栏代码块并完整保留源码、语言标识、源范围和往返结果 |
| EXT-002 | 识别 `$...$` 行内公式和 `$$...$$` 块公式并完整保留源码和源范围 |
| EXT-003 | 渲染模式及对照右栏只显示安全、只读、可访问的类型占位和源码摘要，不执行、解析或绘制 Mermaid/公式 |
| EXT-004 | 源码模式及对照左栏继续编辑原始代码；切换模式不得修改源码 |
| EXT-005 | 应用内不承诺语法有效性，不提供可视化编辑器、属性面板或拖拽编辑 |
| EXT-006 | 占位内容不得进入文档大纲，不得加载外链、文件、脚本、宏或命令 |
| EXT-007 | 复制和保存必须能恢复原始源码；未知或错误输入不得静默丢弃 |
| EXT-008 | PDF/DOCX/TXT 按各格式条款保留类型与源码；HTML 按 HTML-004～007 处理 |
| EXT-009 | 不为 Mermaid/公式引入 WebEngine、外部进程、网络服务、运行时下载或辅助文件释放 |
| EXT-010 | 未来应用内原生渲染属于新的受控变更，不是 V04 验收范围 |

## 5. 文档组合需求

| 编号 | 需求 |
| --- | --- |
| COMBINE-001 | 三种模式均按当前可编辑表面插入点映射到唯一 UTF-8 源偏移执行切分或插入 |
| COMBINE-002 | 不得在 UTF-8 码点或 CRLF 中间切分；位于结构内部时预解析两个候选、明确警告，并允许用户确认后按精确位置切分 |
| COMBINE-003 | 切分要求两个不同目标；两个临时文件均写入并校验后再提交，任一失败不得冒充完整成功 |
| COMBINE-004 | 切分默认保留当前原文件和当前会话，不自动删除或覆盖原文件 |
| COMBINE-005 | 插入和追加读取 `.md/.markdown` 的既有受支持编码，转换为当前会话内部 UTF-8；追加复用插入服务且位置固定为文末 |
| COMBINE-006 | 插入/追加是当前 `DocumentSession` 的单次可撤销事务，并只补防止语法粘连所需的最少换行 |
| COMBINE-007 | 相对链接按来源目录解析并改写为相对当前目标文档的引用；无法安全改写时先提示，不静默改变目标 |
| COMBINE-008 | 本地图片默认复制到当前 `.assets` 并重写引用；当前文档未保存时先要求保存；远程图片只保留地址 |
| COMBINE-009 | 图片复制、引用重写和正文提交构成可回滚事务；失败不得留下正文引用与资源状态不一致 |
| COMBINE-010 | 插入内容视为不可信，不执行其中的 HTML、Mermaid、公式、脚本或外部命令 |

## 6. 多窗口需求

| 编号 | 需求 |
| --- | --- |
| SHELL-009-V04 | 默认允许多个马冬梅进程和顶层窗口，不再强制把第二次启动转发给已有窗口 |
| SHELL-010-V04 | 每个窗口持有独立 `DocumentSession`、路径、脏状态、撤销历史和视图模式 |
| SHELL-011-V04 | 资源管理器、文件关联、命令行或“在新窗口打开”启动独立窗口并打开目标文件 |
| SHELL-012-V04 | 一次命令行传入多个有效路径时按顺序创建独立进程/窗口；单个失败不阻止其他路径 |
| SHELL-013-V04 | 同一文件可在多个窗口打开；保存仍执行外部修改冲突检测，禁止静默覆盖 |
| SHELL-014-V04 | “新建窗口”创建独立进程/窗口；关闭一个窗口不影响其他窗口 |
| SHELL-015-V04 | “文件—打开”和“最近文件”仅在当前窗口干净、未命名且正文为空时复用；当前窗口已有路径、已有正文或未保存修改时，默认启动独立进程/窗口打开目标文件，当前窗口不得弹出替换确认或改变正文 |
| SHELL-016-V04 | 首版不提供窗口内标签页；多标签必须另立需求变更 |

多进程更新设置、最近文件和恢复数据时必须锁定并合并，不得以最后写入者覆盖其他进程新增数据。

## 7. MDM 配置方案

| 编号 | 需求 |
| --- | --- |
| MDM-001 | `.mdm` 是 UTF-8 无 BOM 的受限 YAML 配置文件，不是正文、插件或脚本 |
| MDM-002 | 支持导出当前可共享配置、一次性导入、全局挂接、解除挂接和临时预览 |
| MDM-003 | 优先级为：内置默认 < LocalAppData INI < 全局挂接 MDM < 同名文档旁车 MDM < 系统高对比度强制覆盖 |
| MDM-004 | `报告.md` 自动发现同目录 `报告.mdm`；用户可在本地设置关闭旁车自动发现 |
| MDM-005 | 全局挂接路径写入 LocalAppData 设置，不写注册表；注册表继续只用于 Windows 平台关联 |
| MDM-006 | 顶层必须含 `schema_version`、`profile_name`、`settings`；只允许映射、序列、字符串、布尔和有界数字 |
| MDM-007 | 禁止自定义执行标签、对象构造、脚本、DLL、网络加载、任意文件包含和无界别名 |
| MDM-008 | 配置变化经完整校验后自动应用；失败保留最后有效配置并提示，不用坏配置覆盖有效状态 |
| MDM-009 | 字体字段只接受 Windows 已安装字体族名称；缺失时使用冻结回退链并提示，禁止字体文件路径、嵌入、分发或下载 |
| MDM-010 | 首批字段限于正文/H1～H6/引用/代码/表格排版、编辑区与大纲尺寸、合规配色及导出默认值；字段必须有范围上限 |
| MDM-011 | 高对比度、DPI、安全和资源上限高于 MDM 自定义值，配置不得关闭这些保护 |
| MDM-012 | 未识别字段保留或忽略并诊断；schema 升级必须有明确迁移测试 |

## 8. 非功能与发布硬门槛

| 编号 | 需求 |
| --- | --- |
| NFR-V04-001 | 正式发布物始终为单个 `MarkdownMay.exe`；不得附带或首次运行释放 DLL、JS、WASM、字体、资源包或辅助程序 |
| NFR-V04-002 | 固定脚本/资源若用于 HTML，必须作为数据静态编入 EXE并仅写入用户明确导出的 HTML；应用进程不执行脚本 |
| NFR-V04-003 | 新依赖必须固定版本，完成许可证、安全、静态链接、体积和离线边界审查 |
| NFR-V04-004 | 只使用 Windows 已安装字体；字体缺失可诊断并安全降级，不触发下载 |
| NFR-V04-005 | 10 MB 文档导出和组合操作不得无上限阻塞 UI；压力上限、耗时和内存必须留证 |
| NFR-V04-006 | 多进程、YAML、HTML、路径、图片和扩展源码均按不可信输入处理 |

## 9. 阶段边界与验收

### 9.1 第七阶段

第七阶段实现 EXPORT-001～012、PDF-001-V04、DOCX-001-V04、TXT-001～009、HTML-001～010 及其必需的 EXT 源码保留/占位能力。先完成 HTML 安全与公式系统字体风险样机，再按不可变导出模型、通用任务管线、TXT、PDF、DOCX、HTML 的依赖顺序实施。

COMBINE、SHELL 多窗口和 MDM 已在 V04 冻结，但除非其底层能力是第七阶段导出硬依赖，否则不得插入 PDF/DOCX/TXT/HTML 的依赖链；应各自建立后续受控增量和验收矩阵。

### 9.2 验收证据

- 每条需求必须映射到设计、实现、自动测试、人工兼容性和验收证据；
- Debug/Release 构建和与风险相称的全量测试必须如实记录；
- PDF 验证结构、文本提取、中文复制搜索、链接、分页、图片和表格；
- DOCX 验证 ZIP/XML/关系闭包及 Word/WPS 打开编辑；
- TXT 验证精确编码、换行和语义降级；
- HTML 验证单文件离线、严格 CSP、零网络、浏览器兼容和失败回退；
- 未实际执行的真实软件、DPI、高对比度、性能或安全测试不得写成“通过”。
