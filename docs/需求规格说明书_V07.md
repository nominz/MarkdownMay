## 1. 基线关系与变更范围

V06 及其引用的 V05～V02 未被本文替换的条款继续有效。本次新增“块悬停标志、段落手柄与块上下文菜单”，并把它设为新的第九阶段；原完整系统测试、发布准备与最终验收分别顺延为第十、第十一阶段。

本功能是当前 `DocumentSession` 正文之上的原生交互层，不建立块数据库或第二套正文模型，不改变 Markdown 文件格式，也不引入 WebEngine、Electron、云服务或运行时下载。用户提供的语雀截图只作为交互意图参考，不要求复制其品牌、布局或全部菜单。

2026-08-28 的 CR-2026-038 为三种文档编辑表面增加鼠标右键菜单。参考图只约束宽松、大气的视觉尺度与常用编辑动作，不复制 Bing 搜索、拼写或系统品牌功能；菜单不得联网，也不得增加拼写服务。

## 1.1 CR-2026-038：文档区鼠标右键菜单

| 编号 | 需求 |
| --- | --- |
| CTXMENU-001 | 渲染、源码和对照两侧文档表面均响应鼠标右键；菜单提供撤销、重做、剪切、复制、粘贴、删除和全选，不提供 Bing/网络搜索、拼写或插入表格 |
| CTXMENU-002 | 菜单采用舒展原生弹层：基准宽度不小于 300 DIP，普通项高度不小于 42 DIP，具有清晰图标区、文字区、快捷键区和分组，不得退化为紧凑小菜单 |
| CTXMENU-003 | 命令状态按当前选区、只读状态、撤销历史和剪贴板实时查询；对照右侧只读渲染仅允许复制、全选及适用的历史命令 |
| CTXMENU-004 | 所有正文修改继续通过当前编辑表面同步到唯一 `DocumentSession`；菜单本身不保存正文副本，不改变文件格式、编码、换行或导出 |
| CTXMENU-005 | 菜单跟随应用文本色、背景色、系统高亮色和窗口 DPI；保留原生方向键、Enter、Esc、外部点击关闭及屏幕阅读器菜单语义 |
| CTXMENU-006 | 鼠标右键落在既有非空选区内部时，弹出菜单前不得折叠该选区；剪切、复制和删除必须按原选区启用。右键落在选区外时允许按编辑器正常规则移动插入点 |

2026-08-24 的 CR-2026-035 / DEF-041 复发修正列表渲染缩进语义：无序、有序和任务列表的标记位于正文起始列左侧；同一列表项自动换行后的续行必须向右缩进并与首行正文起始列对齐，不得比首行标记更靠左。该修正只影响 RichEdit 投影段落格式，不改变 Markdown 源码、列表编辑事务或 `DocumentSession`。

2026-08-26 的 DEF-043 修正渲染表格中文字、背景与网格线几何不一致：RichEdit 继续作为文字排版唯一权威；显示层必须从当前投影、修订和 RichEdit 已完成的实际布局派生短生命周期表格几何，统一提供表、行、列及单元格矩形。GDI 网格不得再用控件 DC 字体高度猜测行底；水平留白必须同时进入 RichEdit 文字起点和网格边界规则。该修正不改变 Markdown、表格编辑事务、导出、撤销或 `DocumentSession`，不增加表格选择、移动、拖拽及交互控件。

2026-08-26 的 CR-2026-036 替换 DEF-043 仍保留的 paragraph + tabs 表格正文路线：Windows 11 渲染表面必须把 Markdown table/row/cell 投影为 `msftedit.dll` 原生 RichEdit table/row/cell，每个逻辑 cell 拥有独立文字排版区域并由 RichEdit 负责自动换行、行高、margin、border 和背景。表格内部采用 table/cell-aware 源码映射，系统 cell/row/table 标记不得写回 Markdown；单 Cell 输入、删除、粘贴、选择替换和应用级 undo/redo 必须继续提交唯一 `DocumentSession`。不保留 tabs 兼容渲染，不支持 Windows 10 fallback，不增加 WebEngine 或大型依赖。

## 2. CR-2026-029：块悬停标志与段落手柄

### 2.1 悬停与块识别

| 编号 | 需求 |
| --- | --- |
| BLOCKUI-001 | Markdown 渲染编辑表面中，鼠标悬停在可操作块所在行时，在正文左侧空白区显示块控件；鼠标离开该块及控件后隐藏，正文不得因控件出现而水平跳动 |
| BLOCKUI-002 | H1～H6 显示可辨认的标题类型标志（如 `H1`～`H6`）和独立段落手柄；普通段落及其他首版支持块至少显示段落手柄 |
| BLOCKUI-003 | 块身份、类型和源码范围必须来自当前有效语义修订及稳定 `NodeId`；解析过期、范围非法、TXT 文档或不支持块不显示可执行控件 |
| BLOCKUI-004 | 控件不是正文字符，不参与复制、保存、撤销、打印或导出，不改变修订、dirty 和标题折叠状态 |
| BLOCKUI-005 | 控件不得遮挡标题折叠三角、表格、选区或正文；同一区域同时存在折叠控件时，按“折叠三角—类型标志—段落手柄—正文”的稳定顺序布局 |

### 2.2 段落手柄与上下文菜单

| 编号 | 需求 |
| --- | --- |
| BLOCKUI-006 | 单击段落手柄打开原生上下文菜单；再次单击、Esc、点击外部或窗口失焦可关闭，打开菜单本身不移动正文插入点 |
| BLOCKUI-007 | 首版菜单提供：转换为、删除、复制、剪切、增加缩进/减少缩进、在下方添加；仅对当前块类型合法的命令启用，不可用项应禁用而非猜测执行 |
| BLOCKUI-008 | “转换为”首版至少覆盖普通段落与 H1～H6；转换必须通过既有格式命令和一次 `DocumentSession` 事务完成，保留块内文本与可表达的行内格式 |
| BLOCKUI-009 | 删除、剪切、缩进及在下方添加的作用域必须是菜单打开时锁定的完整块源码范围；若菜单打开后会话修订变化，命令应取消并提示状态已变化 |
| BLOCKUI-010 | 复制只写剪贴板且不改变正文；删除、剪切、转换、缩进和添加分别形成一次可撤销正文事务，不得拆成多个撤销步骤 |
| BLOCKUI-011 | “在下方添加”在当前块完整结束位置插入一个普通空段落，并把插入点移入新段落；列表、表格、代码块等结构边界必须使用结构感知规则，不能破坏 Markdown |
| BLOCKUI-012 | 首版不把拖拽排序视为段落手柄的承诺；若以后增加拖拽，必须另立需求处理跨结构移动、图片资源、撤销和无障碍 |

### 2.3 三模式、键盘与无障碍

| 编号 | 需求 |
| --- | --- |
| BLOCKUI-013 | 渲染模式提供完整悬停控件；对照模式右侧只读渲染可显示类型和手柄，但会修改正文的菜单命令须作用于同一 `DocumentSession` 并同步左侧源码；源码模式沿用 Scintilla 行/折叠边栏，不叠加仿渲染悬停控件 |
| BLOCKUI-014 | 模式切换、滚动、缩放、主题变化、DPI 变化和编辑后重投影必须清除过期命中并按最新可见块重新定位，不能留下漂浮控件或点到相邻块 |
| BLOCKUI-015 | 键盘用户可在当前块调用等价的“块操作”上下文菜单；菜单采用标准方向键、Enter 和 Esc 行为，焦点返回原编辑表面及原逻辑位置 |
| BLOCKUI-016 | 类型标志与手柄提供块类型、标题文本摘要和“块操作”可访问名称；状态不能只靠颜色区分，适配浅色、深色、高对比度及 100%～300% DPI |

### 2.4 性能与失败边界

| 编号 | 需求 |
| --- | --- |
| BLOCKUI-017 | 鼠标移动命中不得触发全文解析、全文投影或正文事务；基于当前可见布局和预建块索引，单次命中目标小于 16 ms |
| BLOCKUI-018 | 约 50 KB 混合文档连续滚动和悬停不得产生明显卡顿；10,000 块索引不得出现无限循环、越界或随块数平方增长 |
| BLOCKUI-019 | 菜单命令提交前必须复核 DocumentId、Revision、NodeId 和源码范围；任何不一致均安全取消，不对邻接块执行操作 |
| BLOCKUI-020 | 异常、解析失效或原生菜单创建失败时，正文保持不变并返回稳定诊断；不得因控件失败影响正常输入、保存和关闭 |

## 3. 阶段与验收摘要

新的第九阶段只实现并验收 BLOCKUI-001～020；先冻结影响分析和设计，再按“块索引与命中—原生控件—菜单查询—事务命令—三模式同步—无障碍与性能”依赖顺序实施。原第九阶段完整系统测试改为第十阶段，原第十阶段发布准备与最终验收改为第十一阶段。

验收至少覆盖：H1～H6 与普通段落悬停、标题折叠控件并存、菜单全命令与单步撤销、过期修订拒绝、三模式同步、TXT 禁用、主题/DPI/键盘/屏幕阅读器、50 KB 与 10,000 块性能，以及 Debug/Release 全量回归。

## 8. CR-2026-037：原生表格尺寸稳定性与只读文件语义

| 编号 | 需求 |
| --- | --- |
| TABLECELL-RESIZE-001 | 窗口最大化、还原和连续 resize 不得清空或重建正文；现有 RichEdit 原生表格应原位更新 Cell 宽度并保持内容、选择和 Markdown source 不变 |
| FILE-READONLY-001 | 带 Windows `FILE_ATTRIBUTE_READONLY` 的 Markdown/TXT 必须按原路径打开，标题栏和状态栏显示“只读”，编辑表面不可修改，普通保存不得覆盖原文件，另存为成功后转为可编辑命名文档 |
| FILE-OPEN-ATOMIC-001 | 文件载入或视图投影失败时不得留下“目标内容 + 无标题身份”的半提交状态；窗口文件身份、只读状态和原文档应恢复到打开前状态 |
| TABLECELL-WIDTH-001 | RichEdit 自带的 RTF 表格列线拖拽不得修改 Markdown 投影视图或导致表格消失；Markdown 分隔行中的连字符数量不承载列宽语义。未来列宽交互必须由应用操作区控制并作为非正文视图状态处理 |
