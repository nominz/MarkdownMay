# 标题折叠功能变更影响分析与设计变更方案

> 变更：CR-2026-023
>
> 需求基线：`需求规格说明书_V06.md` 1.0
>
> 日期：2026-08-18
>
> 状态：用户已批准，进入实现

## 1. 影响分析结论

标题折叠是 `DocumentSession` 最新有效语义标题树上的会话级视图状态。它不拥有正文、不修改 Markdown，也不改变保存、恢复、打印或导出。本变更主要影响标题范围派生、RichEdit/Scintilla 可见性、三模式同步、导航自动展开、无障碍和性能回归。

| 维度 | 影响与处理 |
| --- | --- |
| 需求 | 新增 FOLD-001～020；V05 既有条款继续有效 |
| UI | 渲染标题左侧增加原生绘制三角及命中区；源码使用 Scintilla 折叠边栏 |
| 文档模型 | 不新增正文节点；复用 Heading、NodeId、SourceRange；新增可丢弃的 `FoldState` 视图快照 |
| Markdown | 不改解析器语义和 writer；从最新语义树计算同级/高层级边界 |
| 三模式同步 | `ViewModeController` 统一持有折叠控制器，向两个 RichEdit 投影和一个 SourceView 发布同一状态 |
| 编辑/撤销 | 折叠不提交事务；正文编辑后按稳定 NodeId 协调状态，语义过期时全部显示 |
| 查找/大纲 | 目标位于隐藏范围时先展开祖先，再执行现有源位置导航 |
| 文件/图片 | 无格式和资源生命周期影响；隐藏图片对象仍由原投影拥有 |
| 导出/打印 | 无内容影响，固定读取完整 `DocumentSession` 快照，不读取折叠状态 |
| 设置/恢复 | 首版不持久化；新开/重开文档默认全部展开 |
| 平台/无障碍 | Win32 自绘、Scintilla margin、UIA 展开状态、DPI/主题/高对比度 |
| 性能 | 标题范围线性构建；切换只更新受影响区；增加 50 KB 和 10,000 标题门禁 |
| 安全/隐私 | 不联网、不记录标题文字，不执行隐藏内容 |

未发现与轻量单 EXE、Windows 原生或 `DocumentSession` 唯一正文状态的硬冲突。

## 2. 关键设计

```text
DocumentSession（唯一正文）
  └─ SemanticDocument / Heading NodeId + SourceRange
       └─ HeadingFoldController（仅视图状态）
            ├─ FoldSnapshot(revision, heading ranges, collapsed NodeId set)
            ├─ RichEditHost（渲染模式标题三角 + CFE_HIDDEN）
            ├─ SourceView（Scintilla fold margin/line visibility）
            └─ SplitView（左右共享同一快照）
```

建议新增 `editor/heading_fold_controller.*`，由 `ViewModeController` 独占。核心类型：

```text
HeadingFoldItem {
  NodeId node_id;
  uint8 level;
  SourceRange heading_range;
  SourceRange body_range;
  bool collapsed;
}

FoldSnapshot {
  Revision parsed_revision;
  vector<HeadingFoldItem> headings;
}
```

范围算法按标题源顺序使用层级栈：每个标题的 `body_range.begin` 为标题块结束，`body_range.end` 为首个后续 `level <= current.level` 标题开始，否则为源码末尾。范围必须经过 UTF-8 边界、包含关系和当前修订校验。

## 3. 表面实现策略

- `RichEditHost`：折叠时对正文对应 UTF-16 范围应用 `CFE_HIDDEN`，标题自身不隐藏；标题左侧三角只在绘制层出现，通过现有投影位置表完成命中测试。展开时只重放相应范围可见性，随后恢复既有字符/段落格式和表格线绘制。
- `SourceView`：启用专用折叠 margin/marker，按 `FoldSnapshot` 设置标题行 fold header 和层级；使用 Scintilla 显示/隐藏行能力，不删除编辑缓冲文字。
- `SplitView`：左右不各存状态，只订阅同一控制器；右侧只读渲染也显示并接受折叠点击。
- 导航：`navigate_to_source`、查找和错误定位先调用 `expand_to_reveal(offset)`，再执行原选区映射。
- 编辑同步：表面提交正文前保持完整底层文本；解析修订失配时清除隐藏格式/显示全部行，待最新语义快照成功后重建。

## 4. 主要风险与门禁

1. RichEdit 隐藏格式参与选区、复制和 TOM 操作：必须验证复制全文、撤销、IME、图片对象和表格均不丢内容；不满足时改为受控投影映射方案并先登记设计变更。
2. Scintilla 行折叠与 UTF-8 源范围边界不同：只按完整源码行隐藏，ATX/Setext 标题及末行无换行均需专测。
3. 双层嵌套状态：可见性应为“任一祖先折叠即隐藏”，展开父节点不得清除子节点状态。
4. 编辑后 NodeId 协调失败：宁可丢弃对应折叠状态并显示内容，不得沿用过期范围。
5. 隐藏图片/表格重绘：滚动、DPI、主题、打印客户区和窗口重建须回归。
