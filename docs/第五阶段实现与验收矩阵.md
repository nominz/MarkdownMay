# 马冬梅第五阶段实现与验收矩阵

> 文档编号：MM-DEV-005
> 状态：已完成（2026-08-01）

## 阶段边界

本阶段只实现覆盖完整需求范围的编辑器组件。主窗口、菜单、工具栏、文件关联和单实例属于第六阶段，不在本阶段提前实现。

## 每个节点增量的封闭门槛

每增加一种节点，必须依次通过模型测试、投影测试、输入测试和 Markdown 往返测试，才能进入下一个增量。

增量 1 已建立应用级撤销栈并关闭 RichEdit 原生撤销；控件变更先计算单一最小差异，再作为带前置修订号的事务提交。无法映射为纯段落的变化会恢复最近合法投影，不修改会话版本。

增量 2 已实现粗体、斜体、删除线、行内代码和链接命令。RichEdit 投影隐藏 Markdown 标记及链接地址，以字符格式呈现语义，并维护可见 UTF-8 字节到源码字节的映射；粗体和链接内部连续输入、光标保持、撤销及往返测试均已覆盖。

增量 3 已实现一至六级标题、普通段落、引用、围栏代码块和分隔线命令。投影隐藏块标记，以字号、缩进、等宽背景和分隔线占位呈现语义；块内输入、撤销和往返均已覆盖。本增量同时修复 MD4C 生成软换行的源范围计算，并统一使用 RichEdit 原生字符位置换算跨段选区，避免 CRLF 累积偏移。

增量 4 已实现有序列表、无序列表、任务列表、勾选切换、四空格嵌套缩进和反缩进。投影使用项目符号、连续序号及勾选框呈现语义；支持项目正文输入、回车续建同类项目、任务续项自动清空勾选、空项目回车退出列表，并保持嵌套层级往返一致。

增量 5 已实现图片引用和本地文件插入、图片对象选中、10%～300% 显示比例、替换与引用删除。WIC 在解码前读取尺寸并限制一亿像素；本地可用图片、缺失/损坏图片及远程图片使用不同对象状态，远程地址只保留且绝不请求网络。文件插入复用 `<文档名>.assets` 安全复制规则；删除仅改变文档引用，受管文件的 `del_` 复合事务留待增量 6。

增量 6 已将受管图片引用删除与 `del_` 重命名纳入复合撤销/重做链路。同一文件仍有其他引用时不改名；外部、绝对路径、远程及缺失图片不执行文件操作；撤销时恢复原文件名，若原名已被占用则恢复为不冲突的 `_restored_N` 名称并同步更新 Markdown 引用，保留占用者文件。

增量 7 已实现 GFM 表格插入、单元格修改、Tab/Shift+Tab 导航、末格 Tab 自动增行、行列增删、TSV 多单元格粘贴和整表删除。渲染投影隐藏管道符及分隔行，以制表位和表头/正文底色呈现单元格；所有结构操作统一规范化为列数一致的 GFM 管道表格并支持撤销及语义往返。

增量 8 已实现向前/向后查找、循环查找、区分大小写、当前替换和单事务全部替换；实现纯文本、受支持 HTML 语义、系统剪贴板文本和位图粘贴，以及图片/文档文件拖放分流。HTML 粘贴移除脚本与样式并转换标题、段落、列表、粗斜体、删除线、代码和链接；剪贴板位图以不冲突的时间戳 PNG 保存到受管资源目录。RichEdit 统一提供剪切、复制、粘贴、全选及常用格式命令分发。

增量 9 已使用完整 Markdown 固定样例封闭标题、段落、全部行内格式、自动链接、嵌套引用、嵌套列表、任务列表、代码块、分隔线、表格、图片和原始 HTML 块的混排打开及所见即所得投影。HTML 实体与数值实体在渲染区解码为可见字符；未识别原始块以原文样式显示，不执行其中内容且不静默消失，并允许与其共存的受支持内容正常编辑；远程图片继续只显示阻止加载占位。投影位置表覆盖实体、硬换行、CRLF 原始块和无文本回调的分隔线，保证全篇单调且不越出源码。打开和重复投影不修改源码、不产生未保存状态，编辑其他内容不改变原始块字节。

增量 10 已将 Scintilla 从风险样机依赖提升为正式编辑器静态依赖，建立可复用的源码宿主与同步层。源码表面使用 UTF-8、行号、自动换行、中文字体和基础 Markdown 着色；文本通知按 150 ms 防抖，并保证连续输入最迟 500 ms 提交到同一 `DocumentSession`。同步使用带前置修订号的源码事务，解析或编码问题以波浪线、行列号和首错跳转呈现；过期或无效输入不覆盖有效会话。源码保存直接读取当前 `SourceBuffer`，使用原子替换并保留指定编码和换行符，不经 Markdown Writer 规范化；保存成功才更新 `SavedRevision`。Markdown 解析失败时保留诊断且允许原样保存，非法 UTF-8 则拒绝保存。源码控件、同步层和文件保存已通过单元及真实 Win32 控件集成测试。

增量 11 已建立左右等宽的正式对照视图容器，左栏复用同一个 Scintilla 源码表面并保持可编辑，右栏使用独立 RichEdit 投影并设置系统只读标志。左栏防抖事务解析成功后立即按同一 `DocumentSession` 修订号重建右栏；解析或编码失败时右栏清除旧投影，只显示错误摘要和行列位置，不用旧内容冒充当前文档；源码恢复有效后自动恢复渲染。左侧垂直滚动按总行数比例同步右侧，窗口尺寸变化时保持双栏布局。真实控件集成测试覆盖初始投影、右栏键盘只读、内容防抖同步、错误占位、恢复渲染和滚动同步。

增量 12 已建立三模式状态控制器，默认显示可编辑渲染模式；源码模式与对照模式复用增量 11 容器中的同一个 Scintilla 缓冲，只改变右栏可见性和布局，不产生第二份源码。切换前提交当前表面变化，源码无有效语义版本时拒绝进入渲染模式但允许留在源码或进入带错误占位的对照模式。RichEdit 与 Scintilla 之间以 UTF-8 源码字节位置传递选区并滚动到光标附近。控制器订阅同一 `DocumentSession` 的事务事件，以前后源码快照建立应用级撤销/重做历史；模式切换和保存不进入历史，撤销/重做后只重建当前表面，其他表面在下次显示时刷新。状态矩阵测试覆盖渲染和源码连续编辑、两级跨模式撤销/重做、选区位置恢复、错误切换约束、恢复解析及 `ParsedRevision == SourceRevision`。

增量 13 已把三模式保存收口到模式控制器：保存前先提交当前可见表面，源码/对照模式允许已识别的 Markdown 解析错误按源码原样保存，非法 UTF-8 和渲染模式的不变量错误则拒绝写盘。保存固定取得一次不可变源码修订快照，经目标编码和换行转换后写入同目录临时文件，再经过可注入检查点才执行原子替换；检查点、编码、写入或替换失败均删除临时文件，不改变原文件，也不推进 `SavedRevision`。成功替换后立即按文件层重新打开，核对编码、换行和源码字节，核对通过才标记该快照修订为已保存。集成测试覆盖源码模式 UTF-8/LF 保存重开、故障注入保持原文件与脏状态、非法 UTF-8 拒绝覆盖，以及渲染模式 UTF-16 LE/CRLF 保存重开。

## 阶段出口

所有编辑操作矩阵通过；连续输入不发生模型/视图失步；崩溃和强制关闭后原文件不损坏。阶段结束前不发布中间版本。

验收结论：已通过。13 个依赖有序增量全部封闭；Debug、Release 各 31 项测试全部通过。连续输入、完整投影、三模式版本矩阵、保存重开和原子替换故障注入均有自动化证据。第五阶段只交付编辑器组件，不包含第六阶段应用外壳，因此本阶段未发布可供最终用户使用的版本。
