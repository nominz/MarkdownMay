## 3. 光标处切分

| 编号 | 需求 |
| --- | --- |
| SPLIT-001 | 渲染、源码、对照三种模式均把当前可编辑表面插入点映射为当前 `DocumentSession` 唯一 UTF-8 源偏移；对照模式以左侧可编辑表面为准 |
| SPLIT-002 | 不得在 UTF-8 码点或 CRLF 中间切分；无法得到可靠映射或修订已过期时禁用操作并提示 |
| SPLIT-003 | 在结构内部时分别预解析前后候选，展示风险警告；用户确认后仍按精确位置切分，不擅自移动插入点 |
| SPLIT-004 | 用户必须选择两个互不相同、且均不等于当前源文件规范路径的目标；当前文档为 `.md/.markdown` 时两个结果保持相同 Markdown 扩展名，当前文档为 `.txt` 时两个结果均为 `.txt`，不得在切分过程中转换文档类型 |
| SPLIT-005 | 两个结果逐字节保持切分前后内容，编码与换行继承当前文档；不得为语法完整性自动补正文 |
| SPLIT-006 | 两个同目录临时文件均完成写入、刷新与内容校验后才进入提交；提交前再次确认目标冲突与外部变化 |
| SPLIT-007 | 首版采用“两个目标均不得预先存在”的创建语义，以避免两个既有目标无法跨文件系统原子替换；任一创建/提交失败必须补偿删除本次新建结果并报告失败 |
| SPLIT-008 | 当前原文件、当前会话、脏状态、选区和撤销历史始终不变；切分不提供撤销命令 |
| SPLIT-009 | 成功后报告两个路径，并允许用户选择打开前段、后段或两者；打开动作遵守多窗口既有边界，不影响切分成功判定 |
| SPLIT-010 | 取消、磁盘满、权限、路径竞争或清理失败必须有稳定诊断；清理失败不得虚报完整成功 |

| INSERT-009 | 来源文件不得移动、覆盖、删除或改变时间戳；插入内容视为不可信，不执行 HTML、Mermaid、公式、脚本或命令 |

### 4.1 Word/PDF 文字插入扩展（8.3B，已撤销）

用户期望可把 Word 或带文字层的 PDF 内容插入当前光标位置。本能力定义为“提取可见文字并插入”，不是导入原排版、样式、页眉页脚、批注、修订、浮动对象或 PDF 页面布局。

| 编号 | 评审需求 |
| --- | --- |
| INSERTX-001 | Word 首版候选仅为 `.docx`，不支持旧二进制 `.doc`；提取正文段落、标题、列表和表格可见文字，并转换为安全的 Markdown/纯文本结构 |
| INSERTX-002 | PDF 仅接受存在可用文字层且文字提取质量达到门禁的文件；扫描件、仅图片页面、加密禁止提取或字体映射无法可靠还原时明确拒绝，不内置 OCR |
| INSERTX-003 | Word/PDF 插入不承诺复刻版式；对图片、脚注、复杂表格、多栏和阅读顺序必须按样机结果明确支持、降级或拒绝，不得静默产生明显乱序正文 |
| INSERTX-004 | 来源解析视为不可信输入，限制文件大小、ZIP 解压总量、XML 深度、PDF 对象数、页数、耗时和内存；不使用 Office 自动化、外部 CLI、云服务或运行时下载 |
| INSERTX-005 | 8.3B 必须先完成 DOCX/PDF 读取路线、许可证、单 EXE 体积、安全和中文提取质量样机；样机未通过则本阶段保留 `.md/.txt` 插入，不虚报 Word/PDF 支持 |

2026-08-13 用户依据风险样机正式撤销 INSERTX-001～005 的产品实现范围。第八阶段及当前产品只支持 `.md/.markdown/.txt` 插入；不得因此引入 `miniz`、PDFium、MuPDF、Office 自动化或外部转换程序。风险报告仅作为取舍证据保留，不构成待办功能；未来若重新提出，必须另立需求和架构变更，不从本基线自动恢复。

## 5. 直接打开和编辑 `.txt` 文件的语义（不是“导出为 TXT”）

本节场景是：用户在资源管理器双击 `.txt`，或在马冬梅中执行“打开”选择一个 `.txt`，然后把马冬梅当作记事本编辑并保存该文件。它不讨论把 Markdown 文档导出为 TXT；第七阶段的 TXT 导出规则保持不变。

| 编号 | 推荐需求 |
| --- | --- |
| TXTDOC-001 | `.txt` 是纯文本正文类型，不因内容包含 `#`、`*`、反引号或 URL 而解释为 Markdown |
| TXTDOC-002 | TXT 与 Markdown 共用 `DocumentSession` 的唯一 UTF-8 源文本、修订、脏状态、撤销和文件身份；不得建立第二套正文模型 |
| TXTDOC-003 | TXT 使用源码式纯文本编辑表面；渲染模式和对照模式不可用，模式菜单说明原因；大纲、Markdown 格式工具和图片语义操作禁用 |
| TXTDOC-004 | 查找替换、选择、复制粘贴、撤销重做、恢复、外部变更检测和多窗口打开继续可用 |
| TXTDOC-005 | 打开检测规则与既有文件层一致；已有 TXT 保存时保留原编码和主导换行策略，新建 TXT 默认 UTF-8 无 BOM、CRLF |
| TXTDOC-006 | 若严格 UTF-8/带 BOM UTF-16 均不匹配，明确提示不支持编码，不以系统 ANSI 猜测打开 |
| TXTDOC-007 | “另存为”在 TXT 与 Markdown 扩展名间转换时只改变文档类型，不自动插入或删除 Markdown 标记 |
| TXTDOC-008 | TXT 可使用现有“全文 TXT 导出”生成规范化副本；仅大纲、PDF、DOCX、HTML 等依赖 Markdown 语义的导出禁用 |
| TXTDOC-009 | 打开、最近文件、命令行和文件关联必须把 `.txt` 路由为 TXT 文档类型；无扩展名文件不自动视为 TXT |
| TXTDOC-010 | 状态栏明确显示“纯文本”、实际编码和换行；被禁用功能不得显示伪成功 |

例如打开一份内容为“`# 电话记录`”的普通 TXT 时，`#` 就是普通字符，不自动显示成一级标题；用户仍可编辑、查找、撤销和保存。未采用把 TXT 当 Markdown 渲染（会误解释普通文本）、建立独立 TXT 正文对象（违反唯一状态）和自动猜测 ANSI（存在静默乱码）三条路线。

## 6. Windows 候选程序与默认应用引导

| 编号 | 需求 |
| --- | --- |
| ASSOC-001 | 在当前用户范围注册 Markdown 与 TXT 两个稳定 ProgID；`.md/.markdown` 关联 Markdown ProgID，`.txt` 关联 TXT ProgID 的 OpenWith 能力 |
| ASSOC-002 | 注册使用当前规范 EXE 路径、安全引用的 `\"%1\"` 命令、独立 DefaultIcon 和 RegisteredApplications/Capabilities；不要求管理员权限 |
| ASSOC-003 | 应用设置界面分别显示 Markdown、TXT 的“候选已注册”状态、修复、撤销和“由用户在 Windows 中选择默认应用”动作；应用不得把候选注册称为抢占默认程序 |
| ASSOC-004 | 不写、不删除、不伪造 `UserChoice` 或其 Hash；注册成功不表述为“已设为默认” |
| ASSOC-005 | “由用户在 Windows 中选择默认应用”只打开受支持的 Windows 默认应用设置入口，并说明是否设为默认完全由用户在系统界面决定；不能直达时回退到默认应用主页 |
| ASSOC-006 | 撤销只删除当前 EXE 所拥有且值仍匹配的注册项，不破坏其他应用、用户当前默认选择或未知值 |
| ASSOC-007 | EXE 移动后按规范路径检测需要修复；用户拒绝后按当前路径记忆，不反复打扰 |
| ASSOC-008 | 注册、修复、撤销后调用文档化 Shell 变更通知；不得依赖重启资源管理器 |
| ASSOC-009 | 命令行打开路径仍按独立参数解析；恶意引号、空格、长路径和不存在路径不得造成命令注入 |

| PLACE-005 | 执行前复用既有未保存文档流程；用户取消保存或保存失败时，安置整体取消，当前进程、正文和文件关联均保持不变 |
| PLACE-006 | 先在目标目录创建独占临时文件，复制当前 EXE、刷新到磁盘并逐字节校验；验证成功后才以原子替换提交为 `MarkdownMay.exe` |

| PLACE-008 | 提交成功后启动新位置程序，并传递内部受控参数：等待旧进程退出、修复候选文件关联、打开当前已保存文档；随后关闭旧进程 |
| PLACE-009 | 新进程必须先等待指定旧进程退出，再参与普通单实例仲裁，避免启动请求被转发回即将关闭的旧进程；等待有上限且只接受严格十进制 PID |
| PLACE-010 | 新进程成功接管后按 ASSOC-001～009 把自有候选注册修复为新 EXE；不得写 `UserChoice`，不得把注册成功表述为已成为默认程序 |
| PLACE-011 | 复制、验证、替换或启动任一步失败时旧进程继续运行并显示可诊断错误；仅清理本事务创建的临时文件，不把不完整目标报告为成功 |

## 9. 非功能与阶段门禁

- 10 MB 切分/插入不得无限阻塞 UI；耗时操作提供取消和明确状态。
- 路径、编码、注册表值和插入内容均视为不可信输入；所有大小与偏移运算检查溢出。
- 日志不得记录正文、插入内容或完整用户路径；不增加第三方依赖，不突破单 EXE 和离线边界。
- 新增稳定错误码同步错误码表和 C++ 枚举，不复用既有编号。
- 8.0 只有在用户批准本 V05 及配套影响分析、设计和矩阵后才能封闭；批准前不得写功能代码。
- 阶段封闭前至少执行完整 Debug/Release、全量测试、隔离注册表、真实资源管理器/默认应用引导和 10 MB 风险验证。

## 10. 冻结结论

2026-08-12 用户明确批准本基线及以下场景：

1. 直接打开 `.txt` 时采用记事本式纯文本语义；`#`、`*` 等不解释为 Markdown。这与“导出为 TXT”无关。
2. `.txt` 只注册为候选程序，是否设为默认完全由用户在 Windows 中决定，应用不静默抢占。
3. `.md/.txt` 插入跨编码时静默解码到内部 UTF-8，保存时统一转为当前文档编码和换行。
4. 8.3B 样机完成后，用户于 2026-08-13 明确决定放弃 Word/PDF 插入；不引入新解析依赖，正式插入范围固定为 `.md/.markdown/.txt`。
5. 2026-08-15 用户批准“安置马冬梅…”：允许自选文件夹，默认安置到当前用户 LocalAppData；原 EXE 保留，新 EXE 接管启动与候选文件关联。
